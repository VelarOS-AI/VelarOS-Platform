# velaros 简约风格 —— 设计令牌使用规则

> **性质**：开发者照着做的规则书，每条给**判据**（为什么）与**反例**（写成什么样算跑偏）。
> 它不定义"好看"，它定义**一致**——让 77 个组件、两个产品壳看起来像一个人做的。
>
> 令牌定义在 `src/styles/tokens/`：`foundation.css`（主题无关地基）→ `theme-light.css`（默认主题）
> → `theme-dark.css`（主题覆盖，**当前为空占位**）→ `seed-presets.css`（种子覆盖）。
> 后者只准覆盖前者，禁反向依赖。

---

## 0. 一句话风格

**克制**：颜色少、层次浅、动效短。界面的信息层次靠**间距与边框**拉开，不靠阴影和色块堆叠。
品牌色是**点缀**不是底色——它出现在选中态、焦点环、进度和强调文字上，不铺满表面。

---

## 1. 颜色：引语义，不引具体色

> **规则**：组件只引**语义令牌**（`--foreground` / `--border` / `--card` / `--primary` / `--status-*`），
> **禁裸 hex/rgb/hsl**。裸色值的唯一合法住所是令牌层。
> **判据**：语义令牌能被主题、被双色种子、被 preset 整体重定义；具体色不能。写 `#666` 的那一刻，
> 这个像素就退出了设计系统。
> **反例**：`color: #666`；`background: rgba(0,0,0,.04)`（想要的是 `--background-muted`）。
> `门：check:ui-color-literal（棘轮，314 条存量冻结，新增即红）`

**颜色只有两个可配置种子**（§12.9）：`--velar-primary`（主题色）+ `--velar-accent`（副色）。
其余品牌色**全部从种子派生**（`color-mix` / `rgba(var(--…-rgb), α)`）。

> **规则**：**中性墨色与状态色刻意不随品牌种子走**。
> **判据**：换品牌色不应该给所有表面染色，也不应该让"危险红"变成品牌色相。表面与危险是
> **功能语义**，不是品牌表达。
> **反例**：把 `--background-panel` 改成品牌色的浅色调；把 `--status-red` 接到种子上。

**选色决策表**（照着挑，不要临时发明）：

| 你要表达 | 用 | 不要用 |
| --- | --- | --- |
| 正文 / 次要 / 更次要文字 | `--foreground` / `--foreground-secondary` / `--foreground-tertiary` | 自己调灰度 |
| 卡片、浮层表面 | `--card` / `--popover` | `#fff`、`--color-white`（那是**绝对**白，不随主题） |
| 弱化分区背景 | `--background-panel` / `--background-muted` | 半透明黑叠加 |
| 分隔线 / 描边 | `--border` / `--border-strong` | 自己写 rgba |
| 选中 / 激活 | `--chrome-rail-selected-bg`、`--accent` | 品牌色实心填充 |
| 成功/失败/警告/信息 | `--status-{green,red,amber,blue}` 及其 `-soft` | 自选绿红 |
| 焦点环 | `--ring` / `--ui-shadow-inset-focus` | outline 自定义颜色 |

**绝对中性色的边界**：`--color-white` / `--color-black` 语义就是"纯白/纯黑"，**永不随主题变**。
只有"叠在深色遮罩上的前景""控件底片"这类**确实与主题无关**的位置才用它们；需要随主题走的
表面一律用 `--card` / `--background`。用错的代价在暗色模式落地那天一次性爆发。

## 2. 层次：靠间距与边框，不靠阴影堆叠

> **规则**：**阴影只用于真正浮起来的东西**——浮层、弹窗、菜单。同层平铺的卡片、分区、列表行
> **一律不给阴影**，用 `--border` 描边 + `--background-panel` 表面区分。
> **判据**：阴影是"离开页面平面"的信号。给同层元素都加阴影，等于所有东西都在浮，层次反而消失，
> 还会让界面显脏（多层半透明黑叠加）。这是"简约"最容易失守的一条。
> **反例**：给每张列表卡加 `box-shadow`；用两层阴影模拟边框。

阴影只有三档，且**已经语义化**，按用途选而不是按深浅挑：

| 令牌 | 用途 |
| --- | --- |
| `--ui-shadow-popover`（= `--shadow-sm`） | 气泡、下拉、tooltip |
| `--ui-shadow-overlay`（= `--shadow-md`） | 模态、全屏层 |
| `--ui-shadow-inset-focus` | 焦点内环 |

> **现状差距**：组件当前多直接引 `--shadow-xs/sm/md`，三个 `--ui-shadow-*` 语义别名**零消费**。
> 新代码请用语义别名；存量迁移未做（见 Backlog）。

## 3. 密度：间距走 4px 梯子

> **规则**：间距用 `--ui-space-1..6`（4/8/12/16/20/24px）或它们的语义别名，**禁裸 px**。
> **判据**：梯子是"值单源"。语义别名（`--ui-space-page` / `-section` / `-card-x` …）**指向梯子**
> 而不是各自写字面量——否则调密度时会静默劈叉（改了页边距没改分区间距）。
> **反例**：`padding: 15px`；`gap: 0.9rem`。

**刻意不在梯子上的三个值**：`--ui-space-control-x`(14) / `--ui-space-control-y`(10) /
`--ui-space-card-y`(18)。它们是**控件内部的光学补偿**（图标与文字的视觉居中），强行对齐 4px 步进
会让控件变形。这是判决，不是漏改。

---

## 4. 圆角：四档，按构件体量选

| 档 | 值 | 用于 |
| --- | --- | --- |
| `--ui-radius-overlay` | 12px | 模态、大浮层 |
| `--ui-radius-panel` | 10px | 卡片、分区面板 |
| `--ui-radius-control` | 8px | 按钮、输入框、选择器（别名 `--ui-radius-pill`） |
| `--ui-radius-control-sm` | 6px | 小控件、标签（别名 `--ui-radius-chip`） |
| `--ui-radius-round` | 1000px | 头像、圆点、开关滑块 |

> **规则**：按**构件体量**选档，不按外观挑数值——大面积用大圆角、小控件用小圆角，嵌套时内层
> 圆角不得大于外层。
> **判据**：圆角是尺度语言。同一屏出现 6px/8px/10px 三种小控件圆角，用户读到的是"没对齐"而不是
> "有变化"。
> **反例**：给一个 28px 高的 chip 用 `--ui-radius-overlay`。

---

## 5. 字号：五档梯子 + 九个用途名

值单源在 `--ui-font-size-{xs,sm,md,lg,xl}`（10/12/14/22/24px）；九个语义名
（`--ui-font-title-xl/lg`、`--ui-font-heading`、`--ui-font-body-lg/md/sm`、`--ui-font-body`、
`--ui-font-caption`、`--ui-font-xs`）**按用途别名进梯子**。

> **规则**：**按用途选名，不按数值选名**。要调密度就改梯子，不改语义名的指向。
> **判据**：九个名此前各自写死字面量，落在同一档的（14px 三个、12px 两个、10px 两个）会在调档时
> 静默劈叉——改了"正文"没改"小正文"，界面出现两种 12px 各走各的。
> **反例**：因为想要 12px 就去用 `--ui-font-caption`（那是说明文字的名字）。

行高同理走 `--ui-line-*` 六档，不写裸数值。

---

## 6. 动效：短、一致、可退让

> **规则**：过渡只用 `--ui-transition-fast`(150ms) / `-default`(200ms) / `-slow`(300ms)，
> 不写裸时长。悬停/焦点用 fast，展开/收起用 default，入场/离场用 slow。
> **判据**：三档足够表达"轻/中/重"，再多就没人记得住，实际结果是每个组件自己发明一个数。
> **反例**：`transition: all .18s ease-in-out`（既是裸值又是 `all`）。

## 7. 暗色模式的对称规则

**现状必须说清**：`theme-dark.css` 是**空占位**，设 `data-theme="dark"` 目前**零视觉效果**。
以下是落地时的判决（写在这里，免得落地那天每条重新吵一遍）：

1. **只覆盖语义令牌**（`--background*` / `--foreground*` / `--border*` / `--card` / `--muted` /
   `--status-*-soft` / `--shadow-*`）。**禁止覆盖双色种子**——品牌色跨主题恒定，暗色靠调
   "表面与前景"拉对比度，不靠换品牌色。
2. **覆盖必须成对**：改了某个表面就要同时改它的前景与边框。对比度是三者的关系，不是单值属性；
   只改一半会让亮色下勉强够用的对比度在暗色下塌掉。
3. **密度与形状不随主题变**：`--ui-radius-*` / `--ui-space-*` / `--ui-font-*` / `--ui-border-*`
   一律不覆盖。它们是产品性格，不是主题变量。
4. **阴影不是"更黑的阴影"**：暗色表面靠边框与表面亮度分层，`--shadow-*` 应整体**减弱**。
   照搬亮色阴影会得到一团糊。
5. **绝对中性色永不覆盖**：`--color-white` / `--color-black` 的语义就是纯白纯黑。需要随主题走的
   位置本来就该引 `--card` / `--background`——落地暗色时，这两个令牌的**误用点**就是要修的清单。

## 8. 自查清单（改样式前后各过一遍）

- [ ] 没有裸 hex/rgb/hsl（`bun run check:ui-color-literal`）
- [ ] 没有裸 px 间距 / 圆角 / 字号 / 时长
- [ ] 同层元素没有阴影，浮层用了语义阴影令牌
- [ ] 新引的颜色能在第 1 节决策表里找到对应行
- [ ] 组件里没有 Tailwind 工具类（组件 CSS 是 pure CSS + tokens）
- [ ] 写的每个 `velar-*` 修饰类都真的有 CSS 规则
- [ ] 新令牌是**语义名**不是外观名（`--card-selected-bg` ✅ / `--light-gray-2` ❌）
