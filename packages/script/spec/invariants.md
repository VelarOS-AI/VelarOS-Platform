# Script 执行引擎不变量

编号保持稳定。源码版本、控制调用恢复与结果租约由 Velaros 验收覆盖；本表登记引擎的检查、编辑、隔离和结果契约。

## INV-40 原生 ES 模块链接与绑定

源码由 Node 的原生 ESM 系统链接；具名与命名空间 import 保留 live bindings，静态依赖在正文前执行，循环依赖按语言规则链接，顶层 await 会等待依赖完成。附属模块只按本次提供的源文装载一次；能力模块由授权表生成。不得把 import/export 降级成对象快照与顺序函数调用。

验证：`test/module-semantics.test.ts`，原生模块命名空间只读且不可扩展，数据对象仍递归冻结由 INV-27 验证。

## INV-41 标准输出的确定形状矛盾在工具执行前拒绝

执行 `check` 只对真实绑定标准 `velaros.output` 的调用增加窄预检：调用现场普通 options 的 `type` 确定为 text/code 或 list，且值由直接构造、不可变 const 引用或所有条件分支证明为不兼容形状时，返回原始源码位置的 2345 诊断，真实 session 不启动 runner、不调用能力。标准静态 import、别名、命名空间、字面量动态 import 的 const 解构与附属模块遵守同一合同。

可变属性、数组元素、函数返回、结构类型、泛型、any/unknown、混合分支、动态 options、getter/spread/动态键与局部自定义 output 保留既有运行时校验。普通 JavaScript 的其他类型推断不用于拒绝程序；不改输出值、类型选择或采集额度。验证：`test/output.test.ts` 的 INV-41 真实 session 零能力调用反例、合法动态值执行和原有运行时错误回执。

## INV-42 受信宿主完整编码与正文复用

宿主可按原 key/contentHash 提供完整等价文字编码；仅显式 text 展示、无摘要或选择视图时采用。原值、原指纹、原归档与采集上限不变，所有元数据及正文由同一 serializer 计量；放不下保持引用，不把片段标成 full。模型不能提供此宿主接口。移除已交付正文只匹配相同块身份，保留未匹配正文、引用、问题以及全局与块上限；不修改已冻结投影。

验证：`test/output.test.ts` 的 INV-35 宿主编码、身份与预算反例。

# INV-43 定向合同与内容身份

任意导出切片携带模块共同规则；多个导出共享传递类型闭包，每个类型、重载及规则按原顺序只交付一次，缺少任一名字时不交付不完整候选。值导出目录不混入类型，内容版本覆盖实际声明与模板字节，独立于 schema 和挂载实例。

验证：`test/script.test.ts` 的 INV-43 首末操作、旧格式、模块 JSDoc、循环/共享类型、重载、缺少导出及文档/模板内容变化反例。

## INV-44 显式完整视图先申请正文再分配

未配置整体上限时，无数字 `maxChars` 的显式 `view.mode: 'full'` 通过既有单一申请接口按完整选中表示的有界编码计量，不能先降成引用再以引用长度代表完整需求。宿主共享预算及展示总上限仍决定实际交付，预算不足保留引用和原身份；数字块上限（含零）、整体配置（含零）、reference、summary、部分选择与 required 自动视图保持各自语义，不修改原值、指纹或归档。

验证：`test/output.test.ts` 的 INV-44 字符串、对象与数组完整编码申请、预算不足、数字与配置优先级、manifest 覆盖、自动视图及部分选择反例；INV-35 的 64 块申请覆盖展示总上限。

## INV-45 按需操作文档与原生进程继承

能力目录的单操作文档来自正式声明切片，保留共同规则、用途和递归类型闭包；示例仅使用真实签名的参数名。Shell 启动的 Node 文件、普通子进程和 fork 继承当前预加载，真实磁盘文件按 Node 原生解析；PATH 使用宿主选择的 Node，NODE_OPTIONS 保留既有选项，父环境不改写。并发执行的目录与凭据隔离，未授权包拒绝，取消及超时回收同一进程树。

npm 目录由本次 Node 进程按程序入口查询，工作区版本覆盖后备身份；保留原包清单、文档、无版本状态与局部诊断。嵌套入口、别名、软链接、隐藏清单的 exports 和包自身引用沿用 Node 原生查找，不执行依赖代码。目录通过一次内部发布写入，不扩大观察进程的文件写权限。

同次发布的 execution 来自实际子进程，保留 Node 版本、执行文件、平台、架构、工作目录和有序命令路径；其他环境变量不进入目录。标准命令的可用性由实际解析决定，目录是启动快照。

验证：`test/operation-docs.test.ts`、`test/subprocess.test.ts`；Desktop 的 Electron 主进程与 ASAR 分发探针。

宿主可通过 acquireRuntime 为每次执行固定新的 npm 快照；目录发现、ESM/CJS 解析、PATH 与 Node 子进程使用同一快照。安装和升级在后续执行生效，当前进程继续使用原版本；完整回收后释放租约，回收不完整时保留。验证：`../velaros/act/system/spec/environment.test.mjs` 与 `test/subprocess.test.ts`。

## INV-46 显式宿主 npm 命名空间

`velaros:npm/<包名>` 只解析本次授权环境的安装根，版本固定在本次租约；裸包名仍遵循工作区 Node 解析。作用域包、别名、ESM/CJS 条件和公开子路径使用该安装的 exports，Node 子进程继承同一解析快照。未知包、路径越界与能力/组合包占用命名空间拒绝；工作区损坏不让裸导入偷换版本。执行目录同时保留入口实际身份和明确宿主导入对应的实际版本、清单与说明。后续租约更新只影响后续执行，回收后正常释放。

验证：`test/subprocess.test.ts` 的 INV-46 原生进程、旧版 CJS、作用域别名、子路径、子进程、拒绝与换版验收；Runtime `test/host-instructions.test.mjs` 的首帧与执行目录身份验收。
