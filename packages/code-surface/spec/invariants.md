# 代码面不变量登记

每一条都是本模块对外的承诺。改动或删除任何一条，都要在差量报告里点名并说明原来的承诺为什么不对；新增一条同样要点名。
检验方式与 `packages/agent/spec/invariants.md` 相同：测试 / 类型 / 门禁 / 运行时 / 文字，`check:module-ownership` 核对每一行的检验器是否存在。

编号只增不重排，所以会有空号：INV-19（批量能力说明的门禁）撤销了——那件事写进方法说明就够，为它单开一张登记表加一道门是多余的仪式。

2026-09-18 门换成脚本时间线（`program:run` 换成 `script:exec` / `history` / `show` / `diff`）：INV-11、INV-24、INV-25 按新形状改写——
原来的「在这个会话的上一份程序上改」只认最近一份、会话一结束就没了，现在任何一份记下来的代码都能当底稿；
新增 INV-29～INV-34 管一次调用多步、时间线、只存哈希的标记、重放、脚本库与保留上限；随后新增 INV-35（脚本库能删脚本）。
INV-36（系统空间经能力报路径记下改了哪些文件）撤销了：用户裁决系统空间不做那么复杂，时间线在系统空间里只记操作，不记文件改动。

| INV-7 | 超预算不静默：返回值与日志超过上限时按**结尾**保留（失败现场在尾部），并在 `notices` 里说清省略了多少 | 测试 | `spec/acceptance.test.ts` |
| INV-8 | 程序源码与 blobs 超过体量上限一律拒，不截断后照跑——半截程序跑出来的结果比不跑更坏 | 测试 | `spec/acceptance.test.ts` |
| INV-9 | 隔离必须**自证**才接活：子进程启动后先真去做一次该被拒绝的动作，证不出被关住就不把程序发进去（fail closed）。只相信命令行旗标不算数——`fork` 缺省用 `process.execPath`，宿主跑在 bun 下时那是 bun，它忽略 `--permission`，看着正常而隔离一点没生效 | 测试 | `spec/acceptance.test.ts` |
| INV-10 | 手滑写了 TypeScript 不废掉一整轮：整份诊断都落在「这个语法只能在 TypeScript 文件里用」那一族时，按 TypeScript 再查一遍（真类型错照样拦），剥掉类型照跑，并在 `notices` 里告诉模型下次直接写 JavaScript | 测试 | `spec/acceptance.test.ts` |
| INV-11 | 改已有的代码不必整份重写：`edits` 每处是 `oldText` 换 `newText`——`oldText` 一字不差、在底稿里唯一，一组全成或全不成、各处不许重叠。底稿是任何一份记下来的代码：脚本库里的一版，或者之前某一步的代码（检查没过的那一步也算），会话结束也还在。**不用行号，也不用字符位置**：模型看不见自己写过的代码的行号与偏移，不唯一就多带几行上下文。`program` 与 `from` 只给一个，`edits` 要和 `from` 一起给；`from` 指到没有的东西时明确拒绝，不猜一份出来 | 测试 | `spec/acceptance.test.ts` |
| INV-12 | 诊断必须带代码帧：出错那一行连同一个指向出错列的插字符一起给出。只回行列号等于让模型靠数行定位，而数行是它最不准的事之一 | 测试 | `spec/acceptance.test.ts` |
| INV-13 | 非常驻能力必须先导入才能用：`import` 了没授权的模块时**一行都不执行**，回要补的命名空间让模型拿到签名再重写；没 `import` 直接用那个名字是干净的 `Cannot find name`，不是「要补模块」。检查器只加载「常驻 + 本会话已导入」，**不加载全量**——加载全量就把这道闸拆了 | 测试 | `spec/acceptance.test.ts` |
| INV-14 | 租约写在 `import` 的属性上、随程序一起带回来，**续租退租不独占一轮**；认不出的租约值当没写（不为一个拼错的字废掉一轮） | 测试 | `spec/acceptance.test.ts` |
| INV-15 | **我们发明的东西要导入，语言自带的不动**：`blobs` 与 `template` 走恒常可用的 `velar:program` 模块，不做隐形全局——隐形全局是只有提示词告诉过模型才知道的暗知识；`console` 是 JavaScript 自带的，不动。`velar:program` 不占授权名额、不参与租约与回收 | 测试 | `spec/acceptance.test.ts` |
| INV-16 | 没跑完就交账：程序中止、超时或抛错时，**已经落定的能力调用逐条回给模型**（连着的同名同结果折成一条带 `times`），跑完了不给。这是**账**不是事务——不承诺回滚（跑过的命令回滚不了），承诺**知道**：工具面里中断落在两次调用之间、天然干净，程序里落在执行中途，副作用是真的，只回一个 `ABORTED` 等于让模型对着三个字瞎猜 | 测试 | `spec/acceptance.test.ts` |
| INV-17 | 内存也要封顶：隔离进程带 `--max-old-space-size` 起，堆爆时回 `TOO_LARGE` 并说清怎么改，不报成「意外退出」。超时管得住死循环，管不住一个循环里把整个仓库读进数组；子进程 stderr 必须有人收（没人收会把它堵死，而堆爆的现场只在那里） | 测试 | `spec/acceptance.test.ts` |
| INV-18 | **能力调用的时间不计进程序超时**：每次调用一开始就停表、落定后按剩下的预算接着走——命令跑多久由它自己的时限管，等用户点头也在调用里。必须在调用**开始**时停而不是结束后补时间：用户去倒杯水回来，程序早被我们自己杀了，而他刚点了同意。停表只扣调用那段，程序自己的计算照样按预算掐断 | 测试 | `spec/acceptance.test.ts` |
| INV-20 | 命名空间级的共同事实写在**操作接口头部**并带 `@AgentView`，生成进模块级注释：标记**之前**是给我们自己看的（实现类叫什么、进程里几份），标记**之后**才是模型面。方法上标记在第一行，于是整段都进模型面——同一条规则两处成立。没有这个位置时，「位置一律按字符算，没有行的概念」这类整族都成立的事只能在每个方法里抄一遍，抄漏是必然的 | 门禁 | `check:code-surface` |
| INV-21 | **回给模型的总量有上限，每条通道都算**：导出的值、日志、插手记录、失败说明、执行账、诊断各有自己的上限，整份回执再过一道 `resultChars` 硬闸。程序读了多大的文件、`throw` 了多长的错、被拒了多少次、写了多少个类型错，回到模型那里的都不超过它。失败说明留开头（要紧话在第一行），导出的值与日志留结尾（失败现场在尾部）。这些上限与「只有导出的值和日志会回来」写在门的说明里、模型看得见（`velar:program` 的声明也原样摆在那里，和检查器用的是同一份），数字跟着常量表走 | 测试 | `spec/acceptance.test.ts` |
| INV-22 | 导出照 ES 模块的样子交出，`export default` 与具名导出都行：只有 `export default` 就交它；有具名导出就交 `{ default?, ...具名 }`（跟 `import * as m` 同形），什么都没导出就是 undefined。`export default` **不中断执行**，它后面的代码照样跑。改写不挪模型写的任何一行，运行时报错的行号仍是模型写的那一行（能力报的错没接住时，是发起那次调用的那一行）——行号偏移在隔离进程启动时**量出来**，不写死（写死过一次，包装改了两行、行号一直差 3，从没被测出来） | 测试 | `spec/acceptance.test.ts` |
| INV-23 | 能力交给模型的图走**结果旁边**的通道，不进返回值：程序拿不到像素，文字结果里没有 base64，`resultChars` 只算文字。一次程序最多交 20 张、合计 20 MB——张数对齐 API「一个请求超过 20 张图，每张都不得超过 2000 px」那条线；超出的按顺序丢后面的，并在插手记录里说明 | 测试 | `spec/acceptance.test.ts` |
| INV-24 | 门按会话记导入过的模块，按空间开时间线：给模型的说明里有写脚本的规矩、四个工具怎么用、`velar:program` 的声明、常驻模块的完整声明、其余模块的方法名（代码模版不在里面，不常驻）；头一次 import 按需模块时那一步**不执行**，交回它的完整声明，之后这个会话里一直能用；租约 once、done 在那次之后退租，退租过的再用到时静默装回、不让模型白跑一轮；会话结束只忘掉导入，时间线属于空间，照样在 | 测试 | `spec/acceptance.test.ts` |
| INV-25 | 模型面上是四个工具：`script:exec` 改东西（跑、存、重放），`script:history`、`script:show`、`script:diff` 只读时间线；都常驻（不参与工具页裁剪）、回执不卸载成句柄，exec 同一会话不并发，说明只讲入参怎么填（规矩与声明在系统提示词里）。回执写成内容块：文字在前、图在后且每张前面一行说明，`result` 与内容块里的文字逐字一致（agent 据此原样转给模型，不转义不截断）；模型不收图时图不放进去、只说一声；只读的三个交回一块文字 | 测试 | `spec/acceptance.test.ts` |
| INV-26 | 程序停下时（跑完、失败、超时、被中止都算）还没落定的能力调用，会话触发这一轮的取消信号**叫停它们**，并按发出的顺序列进结果的 `unsettled`：发出去不等就交卷、或者死在一次调用中途，副作用都可能做了一半，模型得知道去核对哪几样 | 测试 | `spec/acceptance.test.ts` |
| INV-27 | 代码模版**不常驻**：不嵌进声明、不在门的说明里；随能力的模型面发布，跟着程序送进隔离进程，程序用 `velar:program` 的 `template('velar:x')` 读到、导出了才进上下文。写错模块名抛错并列出这个空间有哪些 | 测试 | `spec/acceptance.test.ts` |
| INV-28 | 回执写成可读的文字而不是整份 JSON：导出的字符串原样交回（多行照原样、不转义），别的值按 JSON；有具名导出时按名字分段；日志、系统插手过的地方、已经做完与停下时还没落定的调用各成一段；没跑完时第一行说失败码、行号与为什么。只导出一个值、别的什么都没有时就只交那个值 | 测试 | `spec/acceptance.test.ts` |
| INV-29 | 一次调用里写、存、跑：`script:exec` 的步骤按顺序做，某一步没成就停、后面的不做并说一声；write、edit、restore 先过类型检查、不跑，存进库的要是 JavaScript，和最新版一模一样时不存新版本；回执每一步一段，开头是步骤号（`C14.2`）；步骤写法不对（字段和 op 对不上、脚本路径不合规矩）时那一步不做、说清楚怎么写 | 测试 | `spec/acceptance.test.ts` |
| INV-30 | 每一次调用、每一步的代码、参数（input、blobs）、结果与调过的能力都记进这个空间的时间线（`journal.jsonl` 加按 sha256 寻址的对象），换一扇门（重启）也还在：history 列、show 看、diff 逐行比两版代码；restore 追加一个和旧版一样的新版本，历史只增不删；run 从之前的一步来时沿用它当时的参数（给了新的就用新的），库用最新版 | 测试 | `spec/acceptance.test.ts` |
| INV-31 | **时间线只存哈希，不存工作区文件的内容**：有工作区时每一步前后打标记（每个文件的 sha256 拼成只含哈希的目录树，根哈希就是标记，内容相同标记相同），记下这一步改了哪些文件与前后哈希；被 .gitignore 忽略的、按名字默认跳过的目录不算。上一次记下的标记之后外面改的文件，在下一次调用开头记成外部改动；工作区整份退回之前某一点时认得出是哪一点。diff 按文件比两个时间点 | 测试 | `spec/acceptance.test.ts` |
| INV-32 | 重放是按记录再跑一遍：同一份代码、同一组参数、当时用到的库版本（钉住，不用后来改的）。跑之前核对它当时改过的文件还是改前的样子，跑完核对改出来的和当时一样；对不上是 `REPLAY_MISMATCH`，逐个文件说应当是什么、现在是什么，这一次调用停下；改动现在已经在了时明说不用重放。只有跑成了的 run、replay 能重放。给一段调用号（from、to）时按先后重放那一段里跑成了、改过文件的每一步，每一步各有步骤号，改动已经在了的跳过、不算没成 | 测试 | `spec/acceptance.test.ts` |

| INV-34 | 时间线有保留上限（缺省 500 MB，宿主可以按空间设）：超了从最旧的调用清起，清掉结果正文、参数与标记，日志里记下清了什么；代码一直留着。清掉参数的步骤不能再重放，run 要沿用它的参数时要求重给 | 测试 | `spec/acceptance.test.ts` |
| INV-35 | 脚本库能删脚本：remove 之后这个路径的最新版取不到、库目录里不列（另起一行点名拿掉了的）、import 它的代码检查不过，删的时候把还在 import 它的脚本点名；各版本还在时间线上，带版本号照样取得到，restore 或者再 write 一版就回来了，版本号接着这个路径存过的最后一版往下排，同一个号永远只指一份正文 | 测试 | `spec/acceptance.test.ts` |
