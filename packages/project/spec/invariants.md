# 项目空间不变量登记

每一条都是本模块对外的承诺。改动或删除任何一条，都要在差量报告里点名并说明原来的承诺为什么不对；新增一条同样要点名。
检验方式与 `packages/system/spec/invariants.md` 相同：测试 / 类型 / 门禁 / 运行时 / 文字，`check:module-ownership` 核对每一行的检验器是否存在。

项目空间只是一张装配表加三件共用能力的项目端口。两件项目工具（`velar:project`、`velar:code`）与项目内核的承诺登记在
`packages/velar/project/spec/invariants.md`；本表的 INV-2、INV-4、INV-5 是从那边搬来的（原 INV-7、INV-16、INV-21），
INV-3 合并了原 INV-14、INV-17 里属于空间的那一半。

2026-09-18（ADR 0009）：INV-2 后半「会改项目的命令先过宿主的项目修改授权」、INV-4「沙箱落回过写治理」、INV-5「读取策略许看的图」作废，改成不问人、没有名单的承诺；
命令输出与镜像里命令的输出也不再脱敏。这些闸拦不住任何事（shell 本来就能读写），只打断模型。

| 编号 | 不变量 | 检验方式 | 检验器 |
| --- | --- | --- | --- |
| INV-1 | 项目空间挂五个命名空间（`project`、`code`、`shell`、`sandbox`、`images`）；交出的模块清单（`modules`）正好是这五件，每件的声明就是能力单元随包发布、与生成物相同的那一份，放出的方法就是能调的那些；常驻的是项目文件与命令 | 测试 | `spec/acceptance.test.ts` |
| INV-2 | 项目里的危险命令每次都由用户亲自确认（高风险、手动、不可记忆）；被拒时抛错、一个进程都不起；别的命令（会改项目的、长驻的也一样）不问，直接跑，输出原样交回 | 测试 | `spec/acceptance.test.ts` |
| INV-3 | 命令的工作目录与演练沙箱的源目录按解开符号链接后的真实路径钳在项目之内：出了项目在问用户之前就拒绝，一个进程都不起、什么都不镜像 | 测试 | `spec/acceptance.test.ts` |
| INV-4 | 演练沙箱落回不问人、不按名单拦：点名的路径核过（点名了没变化的就拒绝）就把同一份差量的指纹交给宿主落回；镜像里命令的输出原样交回 | 测试 | `spec/acceptance.test.ts` |
| INV-5 | 项目空间里看图（共用的 `velar:images`）只看项目里的图：出了项目（含经符号链接指到外面）的那一张看不了（PERMISSION），项目里的都照常交给模型 | 测试 | `spec/acceptance.test.ts` |
| INV-6 | 根入口只出产品面、注入面和它们用到的数据；`./contracts` 的整条引用链不碰 Node 内置模块，渲染进程可以直接加载 | 门禁 | `check:module-ownership` |
