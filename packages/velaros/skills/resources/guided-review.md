# 基于证据的代码审查

适用于用户要求审查当前改动、分支差异或一组具体文件。

1. 确认审查范围与仓库规则，读取当前 Git 状态和 diff。用 Execa 调用 Git，用 Node 或 ripgrep 读取相关源码。
2. 沿受影响的调用链检查输入校验、状态变化、错误传播、权限、并发与资源释放。对照实际代码和现有约定判断。
3. 优先验证会影响结果、数据或用户流程的具体问题；必要时运行已有的相关测试或最小复现。
4. 每条问题写出触发条件、用户影响、文件位置与依据，按影响排序。明确区分已验证的问题和仍需确认的推断。
5. 给出验证范围和剩余不确定性。没有发现具体问题时如实说明，不把测试通过当作绝对正确的证明。

依照用户要求决定是否修改代码；单独审查任务先交付发现。额外资源与 npm API 不确定时，从运行时目录查阅实际版本的原包文档。
