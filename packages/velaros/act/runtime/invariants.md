## INV-88 原生 exec 工具的完整接纳

主会话默认开放 execute、observe、blobs、done，两种传输按同一 allowed 许可裁剪。`protocol.transport` 可显式选择 tools 或 text；缺省使用公开默认值，不支持工具的驱动回落文本，显式 tools 不受支持时拒绝激活。原生 exec/observe 的 code/options、blobs 的 name/text、done 的 message/completion 由正式 TS 类型生成 JSON schema，文本声明与原生调用共用参数、原文、宿主输入、引用/编辑、快照、租约和异步校验。程序观察不可用时，正式控制 Schema 只允许空 code 配 history 或 clear；它们与程序登记、替换和刷新不同，不需要 Node 采集进程。原生 observe 与 exec 混批在任何执行前整批退回协议修复，clear 也属于观察；宿主和文本保持原子 observe+execute 提交，分别交付动态观察与普通执行结果。普通文本无需控制调用即可接纳；无后台工作时与 done 一样进入完成校验，但不会凭正文自动生成目标完成依据。两边都经过同一目标与领域验收。

稳定系统说明共享运行语义，调用语法由当前传输独立提供，并遵守许可与自定义名称。原生说明与工具描述使用 JSON 字段路径和原生调用示例；文本说明使用当前帧控制头与裸载荷规则。两种传输明确允许在已有执行或子任务运行且仅需等待时返回普通文本进度，由既有调度器挂起模型调用，执行进展、子任务结果或新输入唤醒。观察的完整源码表示登记或整体替换，编辑、刷新和退订均有对应语法；共享校验失败使用通用参数术语。实际模型请求中的稳定说明、动态帧协议和原生工具定义须与所选传输一致。

完整模型响应结束并验收全部声明后才执行动作；响应中断、重复身份或非法参数不产生前序效果。调用与持久回执按调用种类和 executionId 配对，观察、原文与完成声明不会占用执行结果位置；assistant 原文与配对记录保持来源绑定。原生观察往返整组只在 dynamic 交付，不拆开 call/result 或截断不透明状态，也不改造成虚构工具回执；真实审计继续保留，接受对应完整响应后才消费本次选择和往返。普通执行的完整响应仍在历史时，已展示结果正文通过 toolResult 绑定相应调用，不重复发送。进程正常结束且完成回收、能力回执落定的普通非零退出保留失败状态，两种传输的后续独立程序均继续且只执行一次；取消、超时、信号、未知效果、未落定调用或宿主故障中止派发。取消、重启和跨轮接续不重放已接受源码。

验证：`test/protocol-parity.test.mjs` 对同一含转义、Unicode、原文、宿主参数、引用编辑、快照、清除、异步、租约与完成声明进行双路增量解码，显式核对原生混批修复与文本/宿主原子提交的差异；真实 Node 会话保留跨轮观察、执行回执与协议切换。`test/text-decoder.test.mjs` 保留同响应观察与执行的原文绑定和增量边界；提示中的观察 JSON 示例经解码验证。`test/node-runtime.test.mjs` 的 Node/Execa、跨存储重开、完整响应拒绝与取消恢复；Model `test/native-tools.test.ts` 的 Responses/Chat 往返、调用回执拒绝、截断与工具指纹。

持久 npm 环境仅由宿主显式装配，Node 环境和状态目录不会自动授予包管理。`packageEnvironment` 固定宿主作用域，模型写入经过 Kernel 授权；当前已打开会话每次执行获取环境快照并复用原宿主进程端口，静态 Skill 依赖与动态 npm 包名冲突显式报错。模型说明给出发现、安装和验证路径。验证：`../system/spec/environment.test.mjs`。

## INV-91 前台等待由事件唤醒且不重启程序

模型的显式前台偏好可被新输入、其他已受理程序的收束和子任务交互或收束唤醒。子任务可在当前程序内创建；并行事件先给当前短程序既有的返回窗口，长等待及时响应；用户输入直接唤醒，没有新事件时不通过模型轮询。等待信号与运行信号分离，返回仍绑定原执行身份与真实状态，同批依赖顺序不变，宿主 execute 继续等待完整结果。退出等待回收本地监听和计时器，真实取消仍收束程序。

验证：`test/execution-observability.test.mjs` 的两种协议、真实 Node 进程、用户引导、后台失败、既有及新建子任务、依赖顺序、定向停止与宿主直接执行。

## INV-95 已有执行的有界完成等待

`executions.wait` 和两种协议的固定 wait 控制源码复用同一当前任务身份，等待原作业收束，最多 60000 毫秒；到期读取当前快照，终态或 unknown 立即返回。输出、分页及截断沿用 read。取消等待不取消目标，自身及跨任务身份拒绝。一次只接纳一个固定等待程序，它独立于普通执行槽与 read/stop 控制槽及其队列额度；新输入可中断前台返回，停止通道仍可控制原执行或等待程序。等待程序的宿主壁钟上限包含 5000 毫秒控制开销，普通 read/stop 保持原边界。

验证：`test/execution-observability.test.mjs` 的真实进程、超过五秒等待、满槽用户介入、等待取消、期限、任务隔离与两种协议。

任务展示把最新用户输入引用单列为 `task.latestInput`。有最新输入且当前认识为 `pending-review` 时，`active.items` 保留全部约束，模型问题完整移至 `historicalInterpretation.items`；待核对输入按最新引用与其他引用分组，保持全部引用而不截断。历史分组是待核对的认识，不是当前授权任务清单，也不表示目标完成、输入取消或约束失效。没有最新输入锚点或已核对时保持原认识。此分层仅用于展示，维护快照、持久状态、证据校验和用户输入原文不变，不触发强制反思。

### 组帧准备、候选与发布

一次组帧周期先准备稳定材料（能力 inventory、环境、当前段底座及已释放历史退役）；容量候选只试算正文和实际历史覆盖，不发布 `context:frame`、`context:request-proof` 或程序 `pendingFrame`。只有最终完整请求通过容量检查与证据验证，才发布选中帧及其正文 hash 证明，并登记程序帧。正式发布前重新核对授权、最新输入、段版本与 npm 环境；变化时丢弃周期并重新准备，不跨轮缓存。inventory 每周期一次，最终 npm 快照获取仅作版本复核并释放，须在计数中与 inventory 采集区分。

本地候选仍执行实际正文/历史载体 proof 核对，不把引用视为已读；失败、取消和预算试算不消费租约。租约仍在成功接受响应后由原 acknowledge/consume 路径扣减。`ActContextPort.beginFrame` 是唯一组帧入口，所有宿主显式提供候选、历史覆盖核对和最终发布；直接程序投影仍登记其帧。

段起点的最小交接由已有目标、计划、当前 question、带证据的历史变更和失败/写效果引用机械选出，不调用模型、不复制执行正文；最多 6000 字符，每类只选最近 4 条，超出保留省略计数和 `memory.list/read` 入口。计划和状态变更仍是模型解释，执行状态不等于领域验收；后续 `runtime-view` 优先，授权重置/任务切换后不携带旧交接。原文与旧段底座不变。

INV-78、INV-83 随无生产注入方的领域验收器和报告框架退役；目标与任务同次 CAS、取消及目标替换保护仍由 INV-48 的真实目标测试覆盖。

原 task-loop.test.mjs 专测已退役的领域验收器注入与自动核查修复循环，随该框架删除；脚本诊断、真实执行、请求内容和存储恢复仍由各自现役测试覆盖。
