使用项目自己的 package.json、tsconfig、格式化配置和已有验证命令。标准 npm 包直接 import；实际版本、README、类型入口在运行目录的 packages 中按需查阅。

修复问题先依据相关代码、失败日志或复现定位，修改后运行受影响范围的测试；涉及类型或接口变化时补充类型检查，打包行为变化时验证打包入口，并遵守项目明确要求。已有结果仍对应当前代码时不重复检查；必要检查通过即交付。失败保留命令、退出码和日志入口。

项目语言服务由宿主绑定的 velaros:code 统一查询入口提供。网页测试使用项目的 Playwright 配置和测试环境；浏览器二进制按任务需要准备。

## HTML 与浏览器交付

仅在任务实际创建或修改 HTML、浏览器脚本或网页交互时应用本节：

- 含 JavaScript、正则或反斜杠的大段 HTML 使用宿主提供的原文绑定机制，避免模板字符串和手工反转义再次改写源码。
- 修改内联 JavaScript 时检查其语法；修改 `input pattern` 时按浏览器 `v` 标志验证正反例；转义变化时检查受影响的嵌套脚本与正则。
- 修改影响网页交互时，在项目的浏览器测试入口实测受影响的关键路径；分别说明静态检查和交互验证结果。
