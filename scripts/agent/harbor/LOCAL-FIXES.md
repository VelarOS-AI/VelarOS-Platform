## 历史证据的结论边界

- **R18，两笔未知用量**：重新核对了网关请求和 Codex 原生日志。regex-log 的原生汇总等于已知请求之和，仍不能证明中断请求未产生供应商费用；Teleport 没有结束用量。两笔各 $20 预占继续保留，补齐需供应商请求级账单。
- **R26，QEMU 归因**：同类 Rosetta 症状下 Codex 曾完成 startup，说明不能把所有失败都归给环境；历史协议又不同，现有记录不能分离架构影响与排障策略。原超时、症状和成绩保留，结论停留在混合因素。
- **R27，Git 服务判分歧义**：任务说明与判分假设存在差异，同时原执行有 HTTP 404。原 reward=0 保留，二者分别记录；需要上游明确规范后才能作公平归因。评测专用信息不进入产品提示词。
- **R28，跨任务优势**：同题多次改版只能给出局部结果，当前数据不支持“整体超过 Codex”。本轮实现改善尚无新的模型行为数据。

## 差量与使用约定

模型操作的输入签名、读取权限和编辑事务保持兼容；展示范围和错误诊断增加信息。数值上限属于 ProjectTuning 并有边界断言。没有增加上下文窗口、结果预算或缓存策略。

运行中读取 `trace-progress.jsonl`，可用 `recoverTraceProgress` 合并诊断视图；其结果始终标记 provisional，不能代替最终成绩。完整非法记录报错，仅未完成的最后一行作为中断尾部处理。`traces.json` 和 `trajectory.json` 在结束时生成，格式保持兼容。

后续新产物的准备入口：`prepare-environment.py --libc musl`、`prepare-linux.py --bundle <新版本目录> --libc musl`、`prepare-codex.py --libc musl`。两侧采用匹配且冻结的 Node 版本和 libc。musl Node 来自 [Node.js unofficial-builds](https://github.com/nodejs/unofficial-builds)，必须核对对应发布目录的 SHA-256；UV 来自 [Astral 0.7.13 发布](https://github.com/astral-sh/uv/releases/tag/0.7.13)。

下一份执行清单必须纳入 `runtime_artifacts.py` 和全部改动的执行文件，新的 bundle 会纳入 `trace-export.mjs`。旧清单、bundle 和原始成绩对应原版本。

本地验收：90 项输出/编辑测试、129 项 Runtime 测试、30 项受控评测宿主测试、59 项 Python 回归，共 308 项通过；包构建、模块所有权、生成合同、Act 目录和错误构造检查通过。证据目录为 retrospective-49（`.velaros-workspace/bench/retrospective-49`），关键记录为 `abi-probe.json`、`trace-replay.json`、`unknown-usage-audit.json`、`review.json`、`final-checks.json`。
