# 长程原生执行评测

在冻结的真实项目上执行跨模块功能任务，先跑正式 ScriptAct Runtime，再跑应用内 Codex CLI。子任务、高级搜索和默认上下文整理均可用，任务结束后在独立副本运行功能验收与冻结的原项目测试。

评测脚本树连同 CommonJS 预加载器、数据夹具和其他普通文件一起冻结并记录哈希；排除依赖安装目录与缓存。符号链接等非普通文件在准备阶段报错，冻结目标不能覆盖已有证据。

## 用法

先准备任务 JSON 指定的源码提交和独占 Python 环境，并用 `scripts/agent/freeze-standard-runtime.mjs` 保存候选。`prepare.mjs <campaign-directory> <attempt-id> <candidate-name> [paired|scriptact] [task-file.json] [development] [on-demand|node|project] [request|goal] [adaptive|project]` 执行零模型基线检查、确认新功能验收拒绝原项目、预检终态导出，再冻结任务、候选和评测脚本。默认执行配对；`scriptact` 用于单独复测开发候选。重复使用已经看过结果的独立任务时，指定 `development`，冻结清单与汇总随之标为开发复测，原任务文件保持首次定义。

能力档 `project` 在标准 Node 环境上只装配 `velaros:project` 及其正式项目上下文来源，代码查询、搜索与子任务的开关与 `node` 相同。末尾的编辑策略默认 `adaptive`，保持任务正文不变；`project` 策略只在 ScriptAct 的执行任务中追加通过项目能力进行源码、测试、文档与配置编辑的要求，读取、计算、构建、测试和构建生成物仍用普通 Node。清单、实际任务和汇总记录这一独立实验条件，必须与自然按需使用分开报告。`node` 能力档不能选择 project 编辑策略；真实能力调用以完整 trace 为准，可用或要求使用都不等于实际使用。

编辑策略之后可传最后一个可选参数 `[command-path]`，按当前平台 PATH 分隔符写完整搜索路径；省略时冻结准备进程的 PATH。`commandEnvironment` 保存 Node 执行文件、版本、平台、架构和该路径，Node 二进制也进入冻结哈希。执行器核对 Node 身份并恢复冻结 PATH，后续启动控制器的临时工具目录不会自动进入参与者环境。准备阶段通过冻结 PATH 检查 Node 与 Git；Node 项目同时检查 npm 与 Bun，并记录工具版本，执行时再次核对。缺少打包器会在模型调用前失败。路径冻结只约束搜索来源；其他命令文件的实际内容与 OS 权限仍由宿主管理。

任务模式默认 `request`，按原有普通提交执行。显式 `goal` 将同一原始任务正文交给 Runtime 的目标模式，最终目标状态和读取故障写入 solve 记录；任务提示、期限、模型、依赖、验收和 Codex 配置保持同一冻结来源。该开关改变 ScriptAct 的完成控制，必须作为独立配置报告；不能将目标状态自行视为功能验收通过。清单和指标记录 `scriptactTaskMode`，旧清单缺省为普通请求。在首次独立任务需要后置参数而不设置开发标志时，`development` 的位置传空字符串。

任务文件位于本目录，`environment` 指定 campaign/sources 下的项目目录、campaign 下的 Python 环境、独立验收文件、原项目回归路径和评分前恢复的文件/目录。`regressionRunner` 选择项目原有的 pytest 或 unittest，unittest 可用 `regressionPattern` 指定项目原有的文件匹配模式；验收独立运行，统计同时保留 stderr 中的 unittest 结果。准备阶段分别复制评分环境和两个参与者的执行环境，重建 venv 激活脚本并重定位 Python 命令入口；执行中可以安装缺少的开发工具，双方从相同依赖起步，最终依赖单独记录，评分环境始终冻结。基线、评分与参与者的 PATH 均优先解析各自私有 bin，Runtime Node 子进程沿用同一绑定，CLI 实际导入当前源码副本。支持根包与 `src` 布局；`baselineFailure` 声明新功能在原项目上的预期失败，预检不符时不开始付费运行。原项目测试在独立基线副本执行。评分恢复支持分散在源码包中的测试目录，逐层检查父目录并拒绝经过代理创建的链接，保留相邻实现文件的真实改动。

上游存在可复现的基线故障时，`baselineIssues` 可在模型运行前声明精确测试身份、错误指纹、原因和公开来源。预检必须复现全部声明；完整测试照常执行，原始退出码和失败数保留。pytest 的 JUnit 记录用于核对原测试清单，新错误、同名不同错误、丢失用例和新增跳过都会判为回归。报告分别给出完整套件通过与相对基线无新增回归；双方任务附加相同基线说明。

使用准备结果中的 `controller` 路径执行 `node <controller> <attempt-directory>`。当前入口为冻结的 `launch.mjs`，它独占 campaign 执行锁，并通过 macOS `sandbox-exec` 启动冻结的 `worker`。全部后代继承信号边界：可停止自身和同一内核 sandbox 域的进程，向其他域的 PID 或进程组发送信号会被拒绝。worker 在读取模型凭据前，核对启动回执、父进程、冻结身份，并向自己的启动器发送无副作用的 SIGCONT 探针，必须实际得到 EPERM；直接启动 worker 或只伪造环境变量不能通过。后端不可用时在付费请求前失败，当前入口不支持由外部已运行 Desktop 进程承接执行。

同一 campaign 串行执行；锁残留或身份变化时保留现场，不凭锁的年龄或 PID 自动接管。参与者结束时分别回收其已登记工作目录中的进程，外层启动器再核验整个独占任务根；正常完成证明、退出和回收均通过后才归档。取消保留工作区与证据，回收范围无法确定时保留 campaign 锁。信号限制不构成文件系统或网络隔离，移出登记工作目录的脱离后代仍有回收覆盖限制；历史冻结控制器保留原行为，派发前须收束此前运行。控制器从尝试独立副本导入评测依赖，运行前后核对文件哈希和 Python 依赖。`analyze.mjs <attempt-directory>` 汇总已评分的最终验收、请求、上下文和费用覆盖率。

模型、凭据来源、上下文容量、输出上限、超时、请求数和参考价格从 campaign 的 `config.json` 读取，也可在 `command-path` 之后传配置路径。参数在派发前验证并写入冻结清单。`accounting.maxRequestsPerAttempt` 与 `accounting.perAttemptBudgetUsd` 分别限制参与者的上游请求与预占金额；配对共享总额度应能容纳双方的独立额度。用量缺失的请求仍保留预占，不按零费用计算。账本重开时核对独立额度，超额通过永久错误返回，避免把额度耗尽当作临时限流重试。

直接 Runtime 评测使用独立配置的模型服务凭据，无需 VelarOS 产品账号。配置可声明 `runtimeCompletion: {module, exportName, validation?: "node-isolated"}`，其中 module 是自包含 ESM 宿主产物适配器的绝对路径，exportName 是接受工作区根目录的正式适配器类；其依赖应已打入文件，仅保留 Node 内置导入。准备器复制适配器、登记哈希，并以真实工作区文件预检完整读取，运行前再次核对冻结字节，再通过 Runtime 的 `context.completion` 公共接口启用模型复核。桌面宿主可以构建并提供现有 WorkspaceCompletionArtifacts；该组合不访问账号存储。复核沿用参与者的同一模型和计费网关，请求和费用都计入该参与者。启用 node-isolated 时，冻结候选必须提供正式的 `createNodeCompletionValidationHost`，准备器在任何模型派发前执行真实隔离预检；运行时与只读取证共用产物授权及同一 Node 身份。未声明该配置的历史尝试保持原来的复核覆盖，不能追溯视为完整 Desktop 装配。

每个参与者评分前保存 `source-evidence/manifest.json`、从冻结基线到当前工作区的二进制补丁及全部未忽略的新文件。范围包含已提交、已暂存和未暂存改动，不按源文件扩展名筛选；符号链接记录链接原文，不跟随复制。清理执行副本前核验清单与内容哈希，评测失败同样保留证据。

能力使用由完整主线与支线 trace 汇总，按会话和调用身份去重，分别记录模块、操作和最终记录的状态。读取器兼容内联历史与带哈希的引用产物，引用身份或正文校验失败时拒绝汇总；缺失文件、缺失摘要与轨迹缺口保持未知或不完整。`capabilityUsage` 计数只表示真实模块调用，不与 Shell/Node 执行次数相加，也不把可用接口或替身模型测试算作自然使用收益。

汇总 v3 轨迹时逐 turn 读取，调用实体逐行校验并仅保留计数所需的身份、模块、操作和状态；保留完整原始产物。请求统计也逐文件处理，仅保留累计值与最后主请求的提示保留结果。内存随最大记录和摘要索引增长，旧内联格式仍需解析完整文件。统计次序、去重、费用缺口和终态判定与原汇总保持一致。

Node 项目声明 `runtime: "node"`、`regressionRunner: "mocha-json"`、`"jest-json"` 或 `"ava-tap"` 和项目自身的 `regressionEntry`，回归路径可包含项目测试器支持的 glob；独立验收使用本目录中的 `test_*.mjs` 与 Node 自带测试器。Mocha 与 AVA 指向项目自身 CLI 文件，AVA 保留普通参数并提供 npm 风格的本地工具路径；Jest 指向提供 runCLI 的包入口（如 `node_modules/jest/build/index.js`），冻结适配脚本调用 API 并保留普通 Node 进程 argv，避免测试器参数被应用解析。campaign/sources 中先安装完整依赖，准备、执行、评分分别复制 node_modules 实体目录，参与者可以在自己的副本安装工具。冻结身份包含 Node 二进制与版本、依赖文件内容和权限、相对链接；链接限于任务副本内部。评分恢复冻结依赖及原测试。Mocha/Jest JSON 与 AVA 官方 TAP 的逐例结果用于检查原测试清单与新增跳过。AVA 核对逐项编号、尾部计划和所有计数，缺失报告、矛盾统计、worker 崩溃或异常进程退出不能通过。收集和 hook 失败同样计入；Node TAP 的测试总数、失败和取消分别记录，空套件不能通过。原 Python 任务清单和运行语义兼容。

`environment.processEnvironment` 可显式冻结终端颜色和区域变量，值为字符串或 null（清除该变量），准备与执行控制器在启动参与者及评分进程前应用相同设置。可配置 NO_COLOR、FORCE_COLOR、CLICOLOR、CLICOLOR_FORCE、TERM、TZ、LANG 与 LC_ALL；省略时保留原环境。它用于记录项目基线所需条件，不能在付费之后调整以放行失败。

Node 任务还可冻结相对各自工作区的 `NODE_PATH`，用于原项目的模块夹具，路径不接受绝对位置或父目录跳转。Node 回归入口同时支持普通脚本和没有扩展名的 Node CLI。

旧版 node-tap 项目可使用 `regressionRunner: "tap-json"`。适配器调用冻结项目自己的 TAP parser，以 `--no-esm --no-coverage --jobs=1 --reporter=tap` 运行原测试，核验完整计划并记录所有层级的断言。用例身份只移除测试器附加在名称末尾的 `# time=...ms`，保留原始日志；兼容启动参数与覆盖率关闭必须作为环境适配披露，不能据此声称验证了旧版覆盖率工具链。构建进程使用同一冻结 PATH，并前置当前副本的 `node_modules/.bin` 以支持项目构建工具的子命令。

Vitest 项目使用 `regressionRunner: "vitest-json"`，`regressionEntry` 指向项目中提供 startVitest 的入口，例如 `node_modules/vitest/dist/node.js`。冻结适配器以单 worker 执行项目配置，通过官方 API 记录完整任务树、完成次数、取消状态及未处理异常。逐例计算通过、失败和跳过，套件收集/钩子错误独立保留；父套件错误导致未执行的测试也保留身份与错误。普通运行中状态、不完整报告、重复文件和矛盾结果均拒绝，测试器诊断与结构报告分开保存。

测试环境需要提前装配锁定依赖时，可声明 `environment.regressionPreloads`，每项是 node_modules 内的相对 JavaScript 文件。准备和评分的回归进程通过 NODE_OPTIONS 加载同一依赖，包含其派生 worker；双方任务附加相同的普通 Node 使用方法。源代码、构建与功能验收保持各自冻结配置，预加载只能在模型执行前登记。

Cheerio 文档变更订阅任务采用 Vitest、冻结的 Undici 回归预加载和项目自身 tshy 构建。原测试位于 `src` 中，`preserve` 逐文件恢复测试与配置，相邻实现继续使用参与者产物。独立验收覆盖 ESM/CommonJS 的普通与 slim 入口、browser 普通与 slim 入口、公共 TypeScript 声明，以及没有 Node 全局对象的浏览器 bundle。行为评分之外仍需复核维护源码的集成方式、局部变更捕获、文档与测试交付。

该任务的首个配对发现边界快照评分与操作过程中的文档归属存在歧义：原版 wrapAll/unwrap 会修改在调用前或调用后不在树中的父节点。原评分、候选和成本保留，cheerio-02 的有效对比资格排除；后续能力重放待独立契约核对。记录见工程报告的 Cheerio v39 审计；全树快照控制通过不单独证明时间归属语义正确。

Mocha/Jest 的 `baselineIssues` 与 pytest 使用同一套逐例合同：首次模型调用前复现精确用例身份和错误指纹，保留原失败计数与退出码。评分时允许相同已知失败或实际修复，新错误、指纹变化、缺失用例和新增跳过仍判为回归；原套件全过与相对基线无新增回归分别记录。

回归清单必须包含全部冻结原用例，允许额外通过的用例。逐文件恢复原测试时，模型新建的测试文件可能被项目测试器一并收集；这些通过项本身不构成原功能回归。新增失败、错误、跳过与重复身份仍拒绝，新增通过项也不能抵消原用例缺失或改名。原始计数与完整报告始终保留。

需要构建的 Node 项目可声明 `environment.build: {entry, args, optional?}`：entry 指向项目内冻结路径下的 Node 入口，可为 node_modules 中的构建工具或任务要求新增的项目脚本，也支持无扩展名的 Node CLI；args 按原样交给同一个 Node 可执行文件。迁移任务可声明 optional，以容纳尚无构建脚本的原项目：仅入口不存在时跳过并明确记录 skipped，任务验收仍须核对交付所需脚本与生成物。入口存在时的非零退出、断链与其他运行故障继续判为构建失败。基线、参与者初始副本和恢复原测试与依赖后的评分副本分别构建，日志单独保留。初始构建失败时停止该参与者的模型派发；评分构建失败时完整验收仍保留，但最终交付判为失败。省略 build 的任务保持原有步骤。

Python 参与者启动前，私有 venv 的 `.pth` 绑定其工作区的 `src` 与根目录，普通 Python、命令入口和 Node 派生的 Python 都优先使用当前源码。绑定只写入独占环境，拒绝系统 Python，路径记录在 `source-binding.json`。冻结评分环境继续由每次验收的 `PYTHONPATH` 指向对应评分副本。

Mocha 原始 stdout 可同时包含测试诊断和一个完整 JSON reporter 文档。解析器按 JSON 字符串与括号边界提取该文档，再核对计数和原测试清单；多个报告、截断报告、缺失报告和不一致统计保持失败。原始 stdout/stderr 始终保存，诊断文本不充当测试结果。

Mocha/Jest 的用例身份使用真实工作区与测试文件路径，目录别名指向相同文件时保持同一清单；尚未落盘的报告夹具按字面路径处理。路径解析的其他故障继续使评分失败。

模型从候选的正式供应商装配创建。预检在本地截获真实 SDK 出线，验证会话缓存键、显式断点、推理档与延续字段，再将结果写入冻结清单。`rich-01` 到 `rich-05` 直接接入 SDK，缺少供应商缓存翻译层；保留为历史开发诊断，费用与缓存不可用于完整产品接线下的收益结论。

本 campaign 的兼容端点在 `rich-06` 明确拒绝显式缓存断点，后续清单冻结该能力为 false，继续发送会话缓存键。该供应商能力选择和失败记录一同保留；不同端点应按实测能力单独配置。

新尝试在冻结清单中分配独立的 `scriptactSessionId`，Runtime、追踪、恢复和汇总使用同一身份；旧清单沿用其 `development` 身份。该身份决定产品的会话缓存路由键。历史运行共用了一个路由键，其观测仍保留；独立会话身份不代表供应商缓存一定是冷的。

新候选快照记录冻结时的源码提交与工作树是否有改动，准备阶段直接读取该身份；候选的完整文件指纹决定实际执行内容。缺少该元数据的旧快照在新尝试里标为 unknown，不使用当前检出的提交推断旧快照来源。已冻结的历史清单保留原值。

记录保存在运行目录：请求与事件、原始 trace、ATIF、带尝试签名的共享计费账本、独立验收、回归和变更清单。凭据只通过清单里的私有文件路径读取，业务进程拿到尝试凭据。任务工作区采用独占短路径，以避免上游测试的路径长度差异；根目录写入冻结清单。

## 约定

- 评测控制器每 5 秒检查自身的异步文件读取，单次超过 15 秒或读取失败即记录 `evaluator-host-failure.json`，取消参与者并关闭网关；10 秒收尾宽限后以基础设施退出码 70 结束。该检查覆盖模型执行、日志收尾、评分与归档，故障后不能继续派发下一参与者。检查依赖事件循环和同步证据写入仍可用，不能修复底层操作系统 I/O 故障或证明所有脱离进程均已回收。原生 Codex 的 stdout/stderr 直接写独占文件描述符，退出时同步保存 `codex-exit.json`，供后续评分故障时核对真实子进程终态；终态记录本身不代表任务成功。
- 开发任务用于诊断与回归。改进后的同题结果不能代替冻结未见任务的泛化验证。
- 长程资格要求观察到真实上下文整理，保存整理结果、原始需求覆盖、后续执行和支线证据；运行轮数本身不证明合格。
- 模型与生成策略按冻结清单对齐，分别报告 ScriptAct 硬输入上限与 Codex 软整理阈值的实际语义。默认实际 API 为 Responses，参考报价与真实账单分开，失败和用量缺失均保留。
- 验收使用独立测试文件并恢复原项目测试，代理修改测试不能让回归自动通过。测试结果之外还要检查任务要求的文档与覆盖范围。
- 评分器若有可由原项目和原始需求确认的错误，保留原评分和冻结文件，在独立修正目录记录前后哈希、原因与双方全部重评分；不重新执行模型，不改动产物，不把更正算成产品提升。
- `rich-01` 的原始控制器在 ScriptAct 完成后因缺少 ATIF 版本身份而导出失败。原控制器、请求、最终事件和 trace 已保留。`--resume-codex` 只接受有明确原哈希、新哈希和终态时间证据的恢复记录，重新导出并验收原有产物后继续 Codex；不调用模型重做 ScriptAct。

独占任务根在 POSIX 上使用执行用户的 uid/gid，避免临时目录继承组影响权限行为。验收副本和冻结测试恢复均保留符号链接原文，链接不会在复制时被重写为源工作区路径。原有冻结尝试继续使用自己的准备器与控制器。

每次新尝试把 TMPDIR、TMP、TEMP 固定到自身任务根下的 tmp，准备、模型执行、派生进程与评分共用该独占目录，避免上游测试用固定临时名称时相互干扰。清单保存这些路径，控制器核对后继承；临时根为符号链接时拒绝启动。旧冻结清单保持其原有环境。

基线、构建和评分命令通过独占临时文件的描述符采集 stdout/stderr，避免程序主动退出时截断尚未排空的管道。单流记录上限为 8,000,000 字节，执行上限为 180 秒；文件增长越界时通过同一守护器终止进程组，超限、超时、信号和非零退出保留为失败。记录读取及临时文件清理在进程组回收之后进行。采集器和守护器一起计入新尝试的冻结清单。

fs-extra 维护源码迁移任务要求将二十九个生产模块移到原生 ESM 的 src，同时维持 CommonJS 与 ESM 发布接口、函数身份和原测试。独立验收检查逐模块源码、入口行为、源码编辑传播、清空产物后重建、确定性与独立打包消费。打包沿用仓库受控工具；准备器将该工具与评分器一起复制并登记哈希。原实现的 API 清单作为合同夹具冻结，正向迁移控制及十种故障控制在任何付费执行前核验。完整交付仍须复核模型新增的测试、文档和示例，不能仅按有限功能得分认定。

2026-10-07 的 jsdiff 原子补丁任务评分审计保留在官网证据包和本机 followup 归档中。仓库评分器已修正为固定上游真实的 `lib/index.mjs` 入口，并使用原 `applyPatch` 可得到空字符串的标准删除夹具。原冻结文件和双方原分不改写；同一产物统一重判记录同时保留。YAML 后置 NUL 错误的补充检查属于运行后审查，与原冻结验收分开报告。


## 存储与恢复验证

新尝试登记独占任务根的真实路径、设备和 inode，并在任务根及证据目录各保存一份随机归属记录。准备、执行和回收使用同一资源锁。`config.json` 的可选 `storage` 接受 `minFreeBytes`（默认 2 GiB）与 `maxTaskBytes`（默认 16 GiB）。预算覆盖任务根、证据目录、计划写入的副本及未来任务根的归档余量（1.5 倍文件字节加 8 MiB 元数据空间）；两个位置所在卷均保留最低可用空间。准备、参与者复制、源码证据和评分复制前按实际来源大小预检，执行阶段每 15 秒检查并在超限时取消。收到宿主取消后保留 solve 和原工作区，写出 `grading-deferred.json`，停止后续评分复制和参与者派发。它是运行预算检查，外部程序写入与下次扫描之间仍有延迟。计量容许运行中的 socket 和已消失的临时文件；归档仍要求特殊资源已收束。

正常完成评分后，控制器关闭运行资源，将整个任务根流式压缩到尝试目录的 `execution-resources.jsonl.gz`。归档含相对路径、文件权限、链接原文、逐文件 SHA-256 和总清单校验；再次读取归档及原目录，确认内容一致并同步到磁盘后才删除任务根。原始评测记录、评分、源码证据和冻结控制器保存在任务根之外，`resources-archive.json` 和 `resources-cleanup.json` 分别记录验证与回收结果。准备失败也归档现场和 `preparation-error.json`。控制器异常退出、归属变化、锁仍占用、文件在归档期间变化或验证失败时保留现场，不自动接管未知资源锁。

以下命令可校验或还原完整现场；还原目标必须尚不存在：

```sh
node scripts/agent/long-tasks/resource-lifecycle.mjs --verify /absolute/attempt/execution-resources.jsonl.gz
node scripts/agent/long-tasks/resource-lifecycle.mjs --restore /absolute/attempt/execution-resources.jsonl.gz /absolute/new-restored-root
```

控制器失败后，确认相关进程均已退出并完成分析，可运行 `node scripts/agent/long-tasks/resource-lifecycle.mjs --archive /absolute/attempt/resources.json` 归档回收。残留资源锁仍会阻止操作；不能仅凭锁的时间或 PID 重用推断可删除。

归档格式是流式 JSONL + gzip，解压文本中的二进制文件分块使用 base64。还原会恢复链接原文，所有文件写入都拒绝穿过链接；归属记录保留原位置的审计身份，还原副本不自动获得删除原目录的权限。

`durability-soak.mjs <duration-ms> <output-directory>` 使用真实进程、SQLite 与 fsync 的外部写入，循环验证响应接收中断、操作提交后退出、操作已生效但回执丢失。每个故障点先验证活跃进程排斥竞争者，再 SIGKILL 并重开，独立核对外部效果数量与原始任务约束。传 0 跑一轮；传 3600000 持续至少一小时。每轮使用独占现场，成功回收，失败保留；输出目录应每次新建。此测试用确定性模型替身控制故障点，衡量恢复可靠性，不作为真实模型长任务成功率或范式优越性证据。

恢复后外部操作必须恰好完成一次：不完整响应的操作首次不执行，恢复后生成新的操作来完成原要求；已经提交的操作通过读回外部状态确认。每次最终完成都取得对应文件当前内容的独立核查证明。模型请求数分别为两次和一次，用于区分补做未执行事项与重放已接受事项。

`network-recovery.mjs <new-output-directory>` 通过本机 HTTP 服务、真实 TCP/SSE、正式模型驱动和 ScriptAct 测试三种断流点：响应头前、工具参数未完整接收、参数完整但响应尚未结束。每种分别运行同会话自动重试和关闭后重开 SQLite 的恢复。夹具直接切断 socket，断流响应不得产生副作用，原任务最终必须恰好完成一次，缺失 usage 的请求继续计为未知。独占现场和逐次网络请求、事件、追踪经校验归档后回收。确定性响应只控制故障注入，不作为真实模型能力或外部网络质量的测量。

RoomSync 持续故障任务从已曝光的真实交付快照派生，归为开发测试。要求修复既有行为、类型与打包缺陷，并累计 75 分钟真实服务负载，覆盖写入/压缩期间 SIGKILL、丢失确认回执和离线重连。可按执行上限分段恢复，完整回执、哈希与进度必须持久化；等待、实现时间和其他任务不能计入工作时长。证据解析器逐块核对原始字节哈希、逐条解析事件，保留唯一事务集合，核对非重叠时段和故障后恢复检查；21 项合成正反控制涵盖超过 32 MB 的单段日志、分块 UTF-8、尾部哈希篡改与跨块重复。单条记录仍有读取额度，日志总长没有额外的 32 MB 门槛。报告的有效时长必须达到门槛且不超过完整段总时长；启动、收尾可使两者不同，因此解析器明确保留 productiveTimeVerified=false。小时级资格仍须从源码和哈希日志核算实际有效区间，核对真实模型命令的宿主时间、实际进程与注入源码；文件中的累计计数不能自行证明真实运行。

汇总结果的 `passed` 沿用冻结评分器的自动检查意义；`completion` 单独核对运行终态、目标完成和自动检查。Runtime 的失败、等待或未完成目标不能由测试通过覆盖；Codex 需要明确的成功 turn 与正常进程退出；Desktop 空闲回执及完整追踪仍不等于成功终态。缺失证据用 null，完整交付继续要求人工核对任务承诺及保留的产物。`node scripts/agent/long-tasks/analyze.mjs /absolute/attempt metrics-completion-audit.json` 可把重分析保存到尝试目录中的单独 metrics 文件，并复用已归档的 Codex 原始记录；原始评分、solve 和默认 metrics 保留。

原生 Node 测试可选 `regressionRunner: "node-json"`，`regressionEntry` 可省略或声明 ESM 预加载入口。受控 TestsStream reporter 把诊断送到 stderr，逐项核对测试与套件清单和最终汇总，保留取消、钩子错误、跳过及 todo；零测试汇总或不完整清单不能通过。运行环境在冻结清单记录，当前控制在 Node 24.15.0 核验。

资源归档版本 2 保留已收束测试的 FIFO 节点与权限，仅作为元数据；不读取管道流，POSIX 恢复时重新创建节点。套接字等未收束特殊资源继续阻止清理。版本 1 的既有文件/目录/链接归档仍可校验与恢复。

注册为评测独占的 macOS 工作区额外核对 cwd 进程归属：启动前拒绝已有进程占用，Codex 结束或取消后，在独立进程组清理之外按 PID、启动时间和当前 cwd 回收脱组服务。每次发信号先写归属回执并重新核对身份，工作区外进程不进入此范围；清理失败阻止进入评分与下一题。该补充范围不证明已移出工作区的脱组后代已结束，回执明确保留 unknown。

`brittle-tap` 使用项目自身的 Brittle Node CLI 与原始参数。评分核对顶层测试计划、断言总数、失败/跳过和终态；测试名去掉计时且重复名保留序号，截断与矛盾不能记为通过。
