# 长程原生执行评测

在冻结的真实项目上执行跨模块功能任务，先跑正式 ScriptAct Runtime，再跑应用内 Codex CLI。子任务、高级搜索和默认上下文整理均可用，任务结束后在独立副本运行功能验收与冻结的原项目测试。

## 用法

先准备任务 JSON 指定的源码提交和独占 Python 环境，并用 `scripts/agent/freeze-standard-runtime.mjs` 保存候选。`prepare.mjs <campaign-directory> <attempt-id> <candidate-name> [paired|scriptact] [task-file.json] [development] [on-demand|shell-node] [request|goal]` 执行零模型基线检查、确认新功能验收拒绝原项目、预检终态导出，再冻结任务、候选和评测脚本。默认执行配对；`scriptact` 用于单独复测开发候选。重复使用已经看过结果的独立任务时，指定 `development`，冻结清单与汇总随之标为开发复测，原任务文件保持首次定义。

任务模式默认 `request`，按原有普通提交执行。显式 `goal` 将同一原始任务正文交给 Runtime 的目标模式，最终目标状态和读取故障写入 solve 记录；任务提示、期限、模型、依赖、验收和 Codex 配置保持同一冻结来源。该开关改变 ScriptAct 的完成控制，必须作为独立配置报告；不能将目标状态自行视为功能验收通过。清单和指标记录 `scriptactTaskMode`，旧清单缺省为普通请求。在首次独立任务需要后置参数而不设置开发标志时，`development` 的位置传空字符串。

任务文件位于本目录，`environment` 指定 campaign/sources 下的项目目录、campaign 下的 Python 环境、独立验收文件、原项目回归路径和评分前恢复的文件/目录。`regressionRunner` 选择项目原有的 pytest 或 unittest，unittest 可用 `regressionPattern` 指定项目原有的文件匹配模式；验收独立运行，统计同时保留 stderr 中的 unittest 结果。准备阶段分别复制评分环境和两个参与者的执行环境，重建 venv 激活脚本并重定位 Python 命令入口；执行中可以安装缺少的开发工具，双方从相同依赖起步，最终依赖单独记录，评分环境始终冻结。支持根包与 `src` 布局；`baselineFailure` 声明新功能在原项目上的预期失败，预检不符时不开始付费运行。原项目测试在独立基线副本执行。评分恢复支持分散在源码包中的测试目录，逐层检查父目录并拒绝经过代理创建的链接，保留相邻实现文件的真实改动。

上游存在可复现的基线故障时，`baselineIssues` 可在模型运行前声明精确测试身份、错误指纹、原因和公开来源。预检必须复现全部声明；完整测试照常执行，原始退出码和失败数保留。pytest 的 JUnit 记录用于核对原测试清单，新错误、同名不同错误、丢失用例和新增跳过都会判为回归。报告分别给出完整套件通过与相对基线无新增回归；双方任务附加相同基线说明。

使用准备结果中的 `controller` 路径执行 `node <controller> <attempt-directory>`。控制器从尝试独立副本导入评测依赖，运行前后核对文件哈希和 Python 依赖。`analyze.mjs <attempt-directory>` 汇总最终验收、请求、上下文和费用覆盖率。

能力使用由完整主线与支线 trace 汇总，按会话和调用身份去重，分别记录模块、操作和最终记录的状态。读取器兼容内联历史与带哈希的引用产物，引用身份或正文校验失败时拒绝汇总；缺失文件、缺失摘要与轨迹缺口保持未知或不完整。`capabilityUsage` 计数只表示真实模块调用，不与 Shell/Node 执行次数相加，也不把可用接口或替身模型测试算作自然使用收益。

Node 项目声明 `runtime: "node"`、`regressionRunner: "mocha-json"`、`"jest-json"` 或 `"ava-tap"` 和项目自身的 `regressionEntry`，回归路径可包含项目测试器支持的 glob；独立验收使用本目录中的 `test_*.mjs` 与 Node 自带测试器。Mocha 与 AVA 指向项目自身 CLI 文件，AVA 保留普通参数并提供 npm 风格的本地工具路径；Jest 指向提供 runCLI 的包入口（如 `node_modules/jest/build/index.js`），冻结适配脚本调用 API 并保留普通 Node 进程 argv，避免测试器参数被应用解析。campaign/sources 中先安装完整依赖，准备、执行、评分分别复制 node_modules 实体目录，参与者可以在自己的副本安装工具。冻结身份包含 Node 二进制与版本、依赖文件内容和权限、相对链接；链接限于任务副本内部。评分恢复冻结依赖及原测试。Mocha/Jest JSON 与 AVA 官方 TAP 的逐例结果用于检查原测试清单与新增跳过。AVA 核对逐项编号、尾部计划和所有计数，缺失报告、矛盾统计、worker 崩溃或异常进程退出不能通过。收集和 hook 失败同样计入；Node TAP 的测试总数、失败和取消分别记录，空套件不能通过。原 Python 任务清单和运行语义兼容。

`environment.processEnvironment` 可显式冻结终端颜色和区域变量，值为字符串或 null（清除该变量），准备与执行控制器在启动参与者及评分进程前应用相同设置。可配置 NO_COLOR、FORCE_COLOR、CLICOLOR、CLICOLOR_FORCE、TERM、TZ、LANG 与 LC_ALL；省略时保留原环境。它用于记录项目基线所需条件，不能在付费之后调整以放行失败。

Node 任务还可冻结相对各自工作区的 `NODE_PATH`，用于原项目的模块夹具，路径不接受绝对位置或父目录跳转。Node 回归入口同时支持普通脚本和没有扩展名的 Node CLI。

Vitest 项目使用 `regressionRunner: "vitest-json"`，`regressionEntry` 指向项目中提供 startVitest 的入口，例如 `node_modules/vitest/dist/node.js`。冻结适配器以单 worker 执行项目配置，通过官方 API 记录完整任务树、完成次数、取消状态及未处理异常。逐例计算通过、失败和跳过，套件收集/钩子错误独立保留；父套件错误导致未执行的测试也保留身份与错误。普通运行中状态、不完整报告、重复文件和矛盾结果均拒绝，测试器诊断与结构报告分开保存。

测试环境需要提前装配锁定依赖时，可声明 `environment.regressionPreloads`，每项是 node_modules 内的相对 JavaScript 文件。准备和评分的回归进程通过 NODE_OPTIONS 加载同一依赖，包含其派生 worker；双方任务附加相同的普通 Node 使用方法。源代码、构建与功能验收保持各自冻结配置，预加载只能在模型执行前登记。

Cheerio 文档变更订阅任务采用 Vitest、冻结的 Undici 回归预加载和项目自身 tshy 构建。原测试位于 `src` 中，`preserve` 逐文件恢复测试与配置，相邻实现继续使用参与者产物。独立验收覆盖 ESM/CommonJS 的普通与 slim 入口、browser 普通与 slim 入口、公共 TypeScript 声明，以及没有 Node 全局对象的浏览器 bundle。行为评分之外仍需复核维护源码的集成方式、局部变更捕获、文档与测试交付。

该任务的首个配对发现边界快照评分与操作过程中的文档归属存在歧义：原版 wrapAll/unwrap 会修改在调用前或调用后不在树中的父节点。原评分、候选和成本保留，cheerio-02 的有效对比资格排除；后续能力重放待独立契约核对。记录见工程报告的 Cheerio v39 审计；全树快照控制通过不单独证明时间归属语义正确。

Mocha/Jest 的 `baselineIssues` 与 pytest 使用同一套逐例合同：首次模型调用前复现精确用例身份和错误指纹，保留原失败计数与退出码。评分时允许相同已知失败或实际修复，新错误、指纹变化、缺失用例和新增跳过仍判为回归；原套件全过与相对基线无新增回归分别记录。

回归清单必须包含全部冻结原用例，允许额外通过的用例。逐文件恢复原测试时，模型新建的测试文件可能被项目测试器一并收集；这些通过项本身不构成原功能回归。新增失败、错误、跳过与重复身份仍拒绝，新增通过项也不能抵消原用例缺失或改名。原始计数与完整报告始终保留。

需要构建的 Node 项目可声明 `environment.build: {entry, args, optional?}`：entry 指向项目内冻结路径下的 Node 入口，可为 node_modules 中的构建工具或任务要求新增的项目脚本，也支持无扩展名的 Node CLI；args 按原样交给同一个 Node 可执行文件。迁移任务可声明 optional，以容纳尚无构建脚本的原项目：仅入口不存在时跳过并明确记录 skipped，任务验收仍须核对交付所需脚本与生成物。入口存在时的非零退出、断链与其他运行故障继续判为构建失败。基线、参与者初始副本和恢复原测试与依赖后的评分副本分别构建，日志单独保留。初始构建失败时停止该参与者的模型派发；评分构建失败时完整验收仍保留，但最终交付判为失败。省略 build 的任务保持原有步骤。

Python 参与者启动前，私有 venv 的 `.pth` 绑定其工作区的 `src` 与根目录，普通 Python、命令入口和 Node 派生的 Python 都优先使用当前源码。绑定只写入独占环境，拒绝系统 Python，路径记录在 `source-binding.json`。冻结评分环境继续由每次验收的 `PYTHONPATH` 指向对应评分副本。

Mocha 原始 stdout 可同时包含测试诊断和一个完整 JSON reporter 文档。解析器按 JSON 字符串与括号边界提取该文档，再核对计数和原测试清单；多个报告、截断报告、缺失报告和不一致统计保持失败。原始 stdout/stderr 始终保存，诊断文本不充当测试结果。

Mocha/Jest 的用例身份使用真实工作区与测试文件路径，目录别名指向相同文件时保持同一清单；尚未落盘的报告夹具按字面路径处理。路径解析的其他故障继续使评分失败。

模型从候选的正式供应商装配创建。预检在本地截获真实 SDK 出线，验证会话缓存键、显式断点、推理档与延续字段，再将结果写入冻结清单。`rich-01` 到 `rich-05` 直接接入 SDK，缺少供应商缓存翻译层；保留为历史开发诊断，费用与缓存不可用于完整产品接线下的收益结论。

本 campaign 的兼容端点在 `rich-06` 明确拒绝显式缓存断点，后续清单冻结该能力为 false，继续发送会话缓存键。该供应商能力选择和失败记录一同保留；不同端点应按实测能力单独配置。

新尝试在冻结清单中分配独立的 `scriptactSessionId`，Runtime、追踪、恢复和汇总使用同一身份；旧清单沿用其 `development` 身份。该身份决定产品的会话缓存路由键。历史运行共用了一个路由键，其观测仍保留；独立会话身份不代表供应商缓存一定是冷的。

新候选快照记录冻结时的源码提交与工作树是否有改动，准备阶段直接读取该身份；候选的完整文件指纹决定实际执行内容。缺少该元数据的旧快照在新尝试里标为 unknown，不使用当前检出的提交推断旧快照来源。已冻结的历史清单保留原值。

记录保存在运行目录：请求与事件、原始 trace、ATIF、带尝试签名的共享计费账本、独立验收、回归和变更清单。凭据只通过清单里的私有文件路径读取，业务进程拿到尝试凭据。任务工作区采用独占短路径，以避免上游测试的路径长度差异；根目录写入冻结清单。

## 约定

- 开发任务用于诊断与回归。改进后的同题结果不能代替冻结未见任务的泛化验证。
- 长程资格要求观察到真实上下文整理，保存整理结果、原始需求覆盖、后续执行和支线证据；运行轮数本身不证明合格。
- 模型与生成策略按冻结清单对齐，分别报告 ScriptAct 硬输入上限与 Codex 软整理阈值的实际语义。默认实际 API 为 Responses，参考报价与真实账单分开，失败和用量缺失均保留。
- 验收使用独立测试文件并恢复原项目测试，代理修改测试不能让回归自动通过。测试结果之外还要检查任务要求的文档与覆盖范围。
- 评分器若有可由原项目和原始需求确认的错误，保留原评分和冻结文件，在独立修正目录记录前后哈希、原因与双方全部重评分；不重新执行模型，不改动产物，不把更正算成产品提升。
- `rich-01` 的原始控制器在 ScriptAct 完成后因缺少 ATIF 版本身份而导出失败。原控制器、请求、最终事件和 trace 已保留。`--resume-codex` 只接受有明确原哈希、新哈希和终态时间证据的恢复记录，重新导出并验收原有产物后继续 Codex；不调用模型重做 ScriptAct。

独占任务根在 POSIX 上使用执行用户的 uid/gid，避免临时目录继承组影响权限行为。验收副本和冻结测试恢复均保留符号链接原文，链接不会在复制时被重写为源工作区路径。原有冻结尝试继续使用自己的准备器与控制器。

fs-extra 维护源码迁移任务要求将二十九个生产模块移到原生 ESM 的 src，同时维持 CommonJS 与 ESM 发布接口、函数身份和原测试。独立验收检查逐模块源码、入口行为、源码编辑传播、清空产物后重建、确定性与独立打包消费。打包沿用仓库受控工具；准备器将该工具与评分器一起复制并登记哈希。原实现的 API 清单作为合同夹具冻结，正向迁移控制及十种故障控制在任何付费执行前核验。完整交付仍须复核模型新增的测试、文档和示例，不能仅按有限功能得分认定。
