# Kernel 0.3 capability-injection migration

Kernel 0.3 removes concrete product and capability semantics from Core and Agent Runtime.
Products now assemble model and capability packages explicitly and inject their runtime ports.

## Package versions

- `@velaros-ai/core`: `0.3.0`
- `@velaros-ai/agent-protocol`: `0.3.0`
- `@velaros-ai/agent-runtime`: `0.4.0`

`@velaros-ai/kernel-sdk` remains `0.2.1`. Its composition API is unchanged, including
`createCapabilityToken`, `createKernelCallableCapability`, `defineKernelModule`,
`CapabilityToken`, `KernelCallableCapabilityService`, `KernelModuleDefinition`, and
`KernelModuleActivateContext`.

## Contract ownership

| Removed Kernel ownership | New owner / integration seam |
| --- | --- |
| Workspace roots, spaces, tools and result shapes | Workspace package and `CapabilityScopePolicy` |
| Browser element/result/recovery policy | Browser package and `ToolResultMiddleware` |
| Memory/Knowledge search and storage DTOs | Memory and Knowledge packages |
| Workbench product DTOs | Workbench product/package |
| Model provider ids, credentials, catalogs and fallback | Model package and `AgentModelResolverPort` |
| External-agent bridge wire messages | `@velaros-ai/agent-protocol/external-agent-bridge` |
| Capability-specific schema recovery | `ToolValidationHintProvider` |
| Capability-specific verification | `CapabilityValidationInterpreter` |
| Tool allocation prerequisites | `ToolAllocationMetadata` |
| Capability prompt text | `CapabilityPromptContributor` |
| Context collection and intent detection | `CapabilityContextCollector` / `CapabilityIntentClassifier` |
| Tool evidence extraction | `CapabilityEvidenceExtractor` |
| Worker taxonomy and allocation hints | `SubAgentTypeProvider` |
| Execution resource/isolation lifecycle | `RunnerExecutionEnvironmentPort` |
| Agent surface profiles and feature-category mapping | product-owned `AgentSurfaceProfileProvider` |
| Memory-specific observability spans/outcome mirrors | generic `CapabilitySpan` / `recordCapabilitySpan` with product-owned opaque metadata |

## Composition

```ts
import type {
  AgentRuntimeCapabilityPorts,
  AgentSurfaceProfileProvider,
} from '@velaros-ai/agent-runtime'

const capabilityPorts: AgentRuntimeCapabilityPorts = {
  extensions: [workspaceCapability, browserCapability, memoryCapability],
}

const surfaceProfileProvider: AgentSurfaceProfileProvider = productSurfaceProfiles
```

There is no built-in global provider collection or surface registry. A missing capability port
means that the capability is absent. Provider authentication, catalog loading, streaming and
fallback remain within the injected model package.

## Removed compatibility

The previous Core aliases are intentionally not retained. Consumers must import concrete
contracts from the owning package and translate them at the product composition root.

`MemorySpan`, `recordMemorySpan`, `ExecutionSpanDebugMemory`, and `attentionOutcomes` are also
removed. Consumers should emit a `CapabilitySpan` with a stable `capabilityId`, a
capability-owned `operationId`, and opaque `metadata`; the generic debug projection exposes
these as `capabilities` within a turn or `capabilityObservations` at session scope.
