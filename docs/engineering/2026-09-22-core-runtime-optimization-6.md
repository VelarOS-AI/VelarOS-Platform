# 核心运行时热点收尾差量

本轮按稳定性和用户体验筛选，只处理有明确影响的长会话目录、单条材料召回和原始输入路径。

## 修改与合同影响

| 路径 | 问题 | 修改及影响 |
| --- | --- | --- |
| ContextMemory.catalog | 对每条记录重新查找重置点、引用和重附来源，目录授权最坏为平方级扫描 | 一次收集当前代次用户明确重附的引用；按会话和引用身份授权；找到 limit + 1 条匹配材料后停止。保留过滤、最新笔记、through 和 nextAfter 语义。 |
| ContextMemory.read / readMaterial | 读取单条材料先加载所有当前笔记正文；无关笔记缺失也会阻断召回 | 读取授权所需的重置、用户来源和目标引用元数据，再调用既有原文读取器。笔记按引用读取仍要求当前代次；通用材料仍允许当前用户明确重附的旧材料。 |
| ContextMemory.retainMaterial | 执行结果租约也依赖完整目录及全部笔记正文 | 用选择快照授权；只有笔记驻留变更才读取笔记目录。结果租约不依赖无关笔记正文，旧笔记版本继续报告冲突。 |
| SessionContext.reference / ingest / readInput | 输入投影及每个附件校验都加载完整会话目录 | 复用精确引用读取；附件只选择用户清单，并在不可变 sources 中筛出相关清单，再核对 files 成员。正文分块不能冒充附件。跨会话、缺失引用和缺失正文继续明确失败。 |
| SessionContext.projectInput | 为查找摘要再次加载完整记录目录 | 读取元数据，或者使用仅元数据的选择快照；保留摘要 revision、原始输入及文件卡片。 |

本轮不增加公开 API、存储字段、模型操作、schema、发现项或模板。支持 records 或 selectSnapshot 的后端使用精确读取，只有完整快照的后端保留兼容路径。Context INV-7 与 Runtime INV-19 补充相应验收，原有权限、版本、恢复与正文不可变承诺保持。Runtime 模块卡片按当前登记表同步不变量总数。

## 可复现基准

```sh
bun run --cwd packages/context build
bun run --cwd packages/velaros build
node scripts/agent/benchmark-context-recall.mjs
```

独占临时目录中的同一份 SQLite 数据：10,000 条脚本控制记录、64 个当前笔记、64 条回复和一个用户输入，共 10,129 条。每条路径 7 次采样，比较完整返回值后测量。目录基线复现原来的逐条授权与全量收集；召回和投影基线复现原来的全状态读取，同时保留原有精确正文读取。2026-09-22，Node v24.15.0 / macOS arm64 的一次结果：

| 操作 | 修复前 p50 ms | 修复后 p50 ms | 修复前返回的目录项 / 正文读取数 | 修复后返回的目录项 / 正文读取数 |
| --- | ---: | ---: | ---: | ---: |
| 材料目录首页 | 798.423 | 8.296 | 10,129 / 64 | 10,129 / 64 |
| 单条用户材料召回 | 14.397 | 0.049 | 20,259 / 65 | 3 / 1 |
| 普通用户输入投影 | 13.202 | 0.029 | 20,259 / 1 | 2 / 1 |

目录仍加载一次完整元数据和当前笔记，收益来自消除重复授权扫描与多余结果收集。返回目录项数是各次查询的累计值，不能当作数据库实际扫描行数。测量受系统负载和缓存影响，不代表整个模型任务的耗时比例。

## 验证

- Context 与 Velaros 构建、类型检查通过。
- Context 原文、视图、存储合同、索引，以及 Runtime 笔记、上下文管理、维护、程序和决策依据联合回归：166 通过、4 跳过、0 失败；跳过来自不实现可选扩展的后端。
- 新增回归覆盖完整索引、仅选择快照、完整快照和旧选择字段后端；8,000,000 字符边界跨块读取、附件与分块身份、摘要版本、缺失清单和分块、无关笔记故障、结果租约、旧版本笔记、重置撤权、重附授权、取消、筛选分页和尾页。
- 最终索引、任务生命周期、完成恢复、子任务与正式评测回归：53 通过、0 失败；其中 20 项索引用例与上一组合重叠，并补验了无关笔记故障下的结果租约。
- check:module-ownership、check:code-style（37 项）、check:capabilities-arch、涉及实现与基准的 ESLint、git diff --check 通过。
- 基准逐项核对修复前后结果一致。

## 范围收尾

本轮发现并确认影响的热点已修复。历史 SQL 范围分页、子任务标题分组、更复杂的索引和 Worker 存储改造暂缓；当前证据不足以支持扩大改造，后续由真实长会话卡顿或压测数据触发。混合目录仍有线性增长成本，后端性能也受同步 SQLite 调用影响。

本轮验证使用本机存储和确定性模型，没有执行全仓库完整检查或真实供应商请求。已有并行工作保留在工作区。
