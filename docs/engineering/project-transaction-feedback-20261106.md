# 项目事务回执与模型使用说明差量

生产版 0.2.26 的实测中，两个编辑任务各一次提交成功；单文件修复在提交前仍用了两个准备程序，普通撤回在前后各重读源码，外部修改冲突只给出错误码与笼统文字。

本次把常用提交、检查与撤回的导出名、参数示例、准确状态及回执字段放入现有 Node 指令，并要求按模块定向发现其余能力。用户或搜索已给出完整唯一原文时可直接提交，并在同一程序完成必要检查。

`ProjectUndoResult` 新增 `status:'rolled_back'`、`changed`、`diff` 与 `diffTruncated`。反向净差量来自事务留存补丁的每个路径首尾内容，支持历史记录中同一路径多次修改，按现有 8192 字符预算返回。幂等撤回保留原 `changedFiles`，以 `changed:false`、`alreadyUndone:true` 和空差量说明此次没有再次写入。旧调用方使用原字段的行为兼容。

冲突路径复用现有错误详情的 `path`，由项目错误格式化器加入错误文字，继续通过现有 code/message 传输。冲突仍整批拒绝，事务和用户后续修改均保留。

另修复用户截图中多文件改动卡全部显示 `+0 -0` 的问题。项目提交事实新增独立的逐文件增删统计，从完整补丁计算，经有界诊断和追踪摘要交给 Desktop；模型差量正文截断不再使行数丢失。提交、撤回、旧宿主编辑路径共用此统计，诊断超限时统计与文件身份一起裁剪。Desktop 对缺失统计的旧记录显示未知，并在补丁数组为空时保留缺失说明。

生成模型合同、基线、模板和 README 同步更新。回归覆盖撤回的新建、删除、替换差量、完整原字节恢复、幂等撤回、差量截断和冲突路径。真实模型复测使用开发版、本地链接构建产物、原始冻结输入、同一本地代理的 gpt-6.1-sol 与 high，逐项保留轨迹和验收结果。
