# 执行会话上下文装配

## 原因与边界

宿主需要为主会话和业务子会话按执行身份装配职业说明、任务相关记忆、工作目录与浏览器资源。这些业务主体和资源归宿主，运行时只负责调用、传递与生命周期。

## 公开合同

`VelarosRuntimeOptions.prepareSession(request, signal)` 返回 `RuntimeSessionContext`。请求包含实际 sessionId、parentSessionId、profile 和 task，主会话后三项为 null。返回值可替换当前会话的 instructions、node 和 environment，并提供资源关闭函数。类型从现有运行时入口公开，不增加包子路径。

同一会话的并发打开只准备一次。主会话关闭等待该次准备返回的资源关闭；运行时关闭取消待准备的主会话，迟到返回的资源照常释放。业务子会话准备使用本次活动信号，关闭和建立失败沿相同规则回收。准备函数抛出前未返回的资源由宿主持有并清理。

接口统一用于主会话和子任务，不保留子任务专用的上下文装配接口。模型派发与模块合同保持独立，Platform 不引入人员业务。

## 验证范围

真实运行验证两个主会话的独立说明、并发打开去重、异步资源释放及准备期间关闭；父子任务验证独立说明和资源环境、准备期间取消和失败清理。相关类型经 Velaros 包构建检查，结构经模块所有权检查。

## 按执行会话选择能力环境

`skillCapabilityModules.create` 可通过 `context(sessionId)` 为当前真实调用提供独立的 `SkillCapabilityContext`，包含 lease、session 和 node。多个会话共用安装目录和静态合同，各自维护活动选择及 Node 依赖快照。准备阶段没有会话身份，只核对安装授权；实际调用与效果核对沿 Kernel 的真实会话身份解析环境，不激活父会话的默认环境。宿主持有各环境的关闭责任，Platform 不引入人员配置。

真实 Node 测试验证子会话激活不污染主会话、第三方能力在各自工作目录执行，以及既有宿主 SDK 派生调用和授权行为。此项为会话资源装配的配套接口，不复制能力实现或另建执行内核。

## 发行目标

基础包与能力包同步更新为 0.9.8，发行标识为 v0.7.9，平台代保持 0.7。能力包依赖同一标识下的正式基础归档，产品更新两份精确 URL、锁文件及源码快照，不将联调链接或依赖覆盖写入正式清单。独立上下文的公开接口由本次两份归档提供；人员、会话组织和记忆提供方仍由 Desktop 装配。
