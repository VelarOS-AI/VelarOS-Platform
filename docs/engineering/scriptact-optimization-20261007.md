# ScriptAct 后续优化与验证，2026-10-07

本轮针对评测复盘暴露的四类工程问题：交付项覆盖、运行资源回收、进程中断恢复、长会话用量索引。Platform 基线为 `44c029f8`，Desktop 基线为 `2ffd12f76`。改动在当前工作区，代码和测试均保留通用边界；没有按某道评测题的参考输出写特例。

以下数值与合同描述固定对应这批归档。后续的产物/原始需求/证明绑定、实际消息验收卡、增量统计与明细页、网络故障和更严格恢复判据见[完整目标验收清单](./scriptact-goal-audit-20261007.md)。

## 合同差量与行为

| 所属层 | 差量 | 原因与验证边界 |
| --- | --- | --- |

| Desktop 用量状态 | 按请求身份维护不可变 AVL 索引，分页读取，缓存不变账本的 UI 投影 | 更新与迟到修正为 O(log n)，保留第一次记账时间；旧磁盘数组仍可恢复。全量导出和磁盘序列化仍为 O(n)。 |

| 评测运行器 | 独占归属、资源锁、空间预算、流式归档校验、同步落盘后回收 | 准备阶段在复制边界检查；运行阶段每 15 秒检查。任务根与证据目录合计默认上限 16 GiB，两个位置所在卷保留空闲至少 2 GiB。异常现场、活跃锁或归档失败会保留原目录。 |

Runtime 的通用任务指引同时明确：多项交付须持续保留当前要求、剩余事项和证据；检查内容与边界行为；可以在同一脚本组合确定性的独立操作；恢复前核对操作身份与实际回执。

Bun 1.3.13 / macOS arm64 / Apple M5。相同请求序列与修正序列，双方交替先运行，五组采样；每组断言最终记录完全相等。基线取 Desktop 指定提交中的 `findIndex + array copy` 更新流程。测量时同时运行恢复压力测试。

## 中断恢复持续测试

持续测试使用冻结的运行时副本、真实子进程、SQLite 与 fsync 的外部写入。三类故障：响应接收尚未完整、操作提交完成、外部操作已生效但回执丢失。每次先验证活跃所有者排斥竞争进程，再 SIGKILL 并由新进程恢复；独立核对原始要求仍在、效果数量正确、旧请求没有自动重发。每轮使用独占现场，成功回收，失败保留。

持续运行 3601.969 秒，完成 748 轮、2,244 次中断恢复；三类场景各 748 次，失败 0。控制器正常退出，逐次记录与汇总一致，运行前后 5,503 个冻结文件的 SHA-256 均保持一致。每次恢复只发出一次新的继续请求，响应不完整场景未发生外部写入，另外两类各保留一次原始写入。

因此这批小时级结果证明的是这些受控路径下的副作用保留与不重复；部分响应场景的最终写入数为 0，不能据此证明原操作最终完成。当前夹具已将三种场景的最终写入数全部要求为 1，新判据的结果单独记录。

一小时副本在运行前冻结；其后补上的领域失败原因保留修复，由最终独立副本重建后的完整回归与一轮三类真实进程故障验证覆盖。逐次记录见 `durability-1h/cycles.jsonl`，结束证明见 `durability-1h/completion.json`，最终副本验证见 `delivery-platform/fault-check/summary.json`。

模型是用于控制故障点的确定性替身。这份证据说明这些故障路径的工程可靠性；ScriptAct 的模型任务质量、真实长任务成功率与对 Codex 的比较，仍需使用冻结的独立任务、相同模型预算和完整用量记录验证。
