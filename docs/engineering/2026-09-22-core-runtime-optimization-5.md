# 核心运行时第五批优化差量

## 实现与合同

| 修改 | 理由与影响 |
| --- | --- |
| ContextRecordSelection.titleSuffix | 按字面后缀过滤，配合 script 前缀选择结果记录，避免把源码、控制和租约目录传到投影层。运行时继续核验原有结果标题格式。 |
| ContextRecordSelection.latestPerTitle | 筛选后按标题取最大 sequence；笔记目录只接收当前版本。旧笔记读取按 refId 另行补选，原文和授权重置语义保持。 |
| ContextRecordSelection.sequence / last | 分别选择精确序号和最后 N 条匹配记录；历史检查点用它们读取目标结果与最近两次响应。结果仍去重并按 sequence 升序返回。 |
| LocalContextStorage.selectSnapshot | 所有选择与元数据继续使用同一读事务。分组在 SQL 层完成，返回所需目录后才解码记录 JSON。前后缀以 UTF-8 字节字面比较，支持中文、通配符和 NUL，空后缀不增加限制。 |
| RecentContext.checkpoint | 一次选择旧检查点、重置、最近两次响应、目标序号和证据；完成原有语义校验后用同一 version 增量提交。失败整体回滚；并发变化报告 CONTEXT_CONFLICT。缺少组合能力时继续完整 CAS。 |

sequence 必须为正安全整数，last 为 1–ContextLimits.recordPage 的整数；latest 不与 last 合用，latestPerTitle 不与 latest/last 合用。非法范围或组合返回 INVALID_RANGE。历史检查点无效 through 继续进入原有业务校验路径，不改变错误判定顺序。

新字段扩展现有可移植查询类型，不增加模型操作、schema、发现项或模板。Context INV-12 和 Runtime INV-15 / INV-19 增补分组、末尾查询、旧版本召回及检查点事务验收。正文不可变、版本冲突、重置范围、保留最近两次响应的承诺保持。

兼容测试覆盖完整快照后端、只支持快照读取的后端，以及忽略新查询字段而返回更宽结果集的旧选择后端。运行时继续执行去重、版本和业务范围校验；适配器升级应通过新增存储合同测试。

## 可复现基准

```sh
bun run --cwd packages/context build
bun run --cwd packages/velaros build
node scripts/agent/benchmark-context-directories.mjs
```

独占临时目录中的 SQLite WAL / FULL 持久性，10,000 条脚本控制元数据、同一笔记的 1,000 个版本、24 对响应/结果。每项 20 次采样，核对笔记 revision、历史页、检查点数量与 through、完整目录数量后清理临时目录。

旧路径忽略新增选择字段，并以完整 CAS 保存检查点；新路径使用本批筛选和增量事务。2026-09-22 本机 Node v24.15.0 / macOS arm64 的一次结果：

| 操作 | 旧路径 p50 ms | 新路径 p50 ms | 旧路径 p95 ms | 新路径 p95 ms |
| --- | ---: | ---: | ---: | ---: |
| 最新笔记目录 | 0.881 | 0.082 | 1.398 | 0.162 |
| 历史目录 | 14.356 | 0.727 | 15.717 | 0.768 |
| 检查点提交 | 20.419 | 0.191 | 25.374 | 0.267 |

| 操作 | 旧路径返回的快照记录 | 新路径返回的快照记录 |
| --- | ---: | ---: |
| 最新笔记目录 | 1,000 | 1 |
| 历史目录 | 10,048 | 48 |
| 检查点提交 | 11,048–11,067 | 3–4 |

这里统计返回给调用者的目录项，不等于数据库扫描行数。后缀筛选仍需检查候选标题，按标题分组仍需遍历相关索引；历史响应和结果很多时仍有增长成本。微基准受缓存与运行环境影响，不代表真实模型任务的整体加速。

## 下一批分析

1. **历史目录分页。** 已排除脚本辅助元数据，但仍返回所有响应与结果后在调用者分页。后续需要同版本的范围查询和有效结果计数，保留 through、nextAfter 与省略范围，不能截断后误判不存在下一页。
2. **混合材料授权读取。** catalog、readMaterial、retainMaterial 仍依赖完整目录。应按材料类型拆清当前代次、用户重新附加来源和旧笔记版本规则，再把候选查询下推。
3. **原始输入召回。** SessionContext.readInput 仍为身份与附件授权读取完整状态，长文本分块还会逐项召回。可复用精确引用/清单选择，但需保证附件成员关系与会话范围。
4. **其他按标题取最新的目录。** 程序帧的子任务状态等位置仍先取多个版本再 Map 去重；可用本批分组能力逐项缩小，分别验收任务边界和迟到终态。
5. **更长历史基线。** 本批优化减少返回与 JSON 解码，数据库扫描和同步调用仍存在。后续应增加结果数量、笔记键数和版本数的交叉负载，再决定索引形态和 Worker 存储适配器。真实模型重复矩阵与评测增量归档继续作为独立验证项。
