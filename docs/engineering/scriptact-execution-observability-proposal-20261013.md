## 建议行为

模型发出的普通 exec 先等待一个较短的返回窗口，建议初始为 10 秒。若程序仍在执行，返回具有稳定执行身份的运行中回执，程序继续受原执行时限、父任务取消和权限约束。返回窗口与程序计时时限分开；达到返回窗口不等于超时或失败。

`async:true` 继续表示立即后台受理；显式 `async:false` 保持前台兼容语义。省略该选项的模型调用使用上述短等待策略。宿主直接调用并等待完整结果的接口保持原合同。两种模型传输使用同一套 TS 定义和生成声明。

同一批程序保持原依赖顺序：原本应等待前序完成的后续程序继续排队；显式后台程序保留原并行语义。前台返回不代表后续依赖程序已经完成或可以重放。全部排队项及批次收尾在返回前登记，当前模型回合、作业状态和完成核查都能看见它们。

按现有执行身份提供有界的状态、stdout/stderr 读取和定向停止能力。日志使用流与偏移游标，区分尚在增长、完整、截断和未知；读取只覆盖当前任务获权的执行。停止只针对对应作业，保留已有输出、实际终态和清理保证范围。宿主不能确认脱组后代时继续报告未知。

等待机制复用当前作业与子任务唤醒链路。输出变化合并后交付，不按每一行触发模型调用；结束和真实执行错误及时可见。日志内容仍是任务资料，不因来自进程输出而获得指令权限。模型可做独立工作、检查执行或等待既有作业；完成核查须等待必需作业及依赖批次结算。

## 实施边界

1. Runtime 的批次派发登记全部执行身份、排队项与收尾状态，再启动保持顺序的执行链；短等待返回不取消仍受管的工作。复用现有持久回执和效果核对，不通过重新发起源码恢复作业。
2. 文本与原生解码保留 async 的省略、true、false 区别。模型接口、示例、类型和生成物一起更新；显式兼容调用及宿主完整等待调用分别回归。
3. 在现有进程输出与执行身份上接入有界读取、订阅及停止。取消、超时、父任务结束、队列未启动、输出交付与最终结算竞态均保留明确状态；未知效果不变成成功或无效果。
4. Desktop 展示相同身份的运行、进度及终态，恢复后不重复启动。模型输入按游标和当前版本呈现新增材料，控制日志和唤醒开销。
5. 本项不改变模型预算结算；预算逐请求结算按独立方案处理。外部 AbortSignal 没有公开期限时不推测截止时间，也不把可续期回合的期限冒充整个目标的硬期限。

## 验证与发布顺序

先做真实 Runtime 控制：短程序直接完成；长程序返回运行中；显式前台保持等待；同批前后依赖顺序保持；后台加依赖混合批次不重复执行；队列等待、进程失败、取消和父任务关闭正确结算。文本/原生、主线/子任务、同时有其他后台工作均覆盖。

增加日志与恢复控制：大量连续输出不会制造每行一次的模型请求；静默长程序仍可等待或查询；stderr 文本不自动宣称失败；真实退出码与最终日志完整交付；迟到输出、重复读取、取消后读取和跨会话越权读取有确定结果。重开进程不能把持久 running 记录当作仍活着，也不能自动重放副作用。
