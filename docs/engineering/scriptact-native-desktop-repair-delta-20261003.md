## 范围编辑的历史核对与定位约束

2026-10-04 核对 Git 历史后，范围编辑应作为既有规划器能力的重新开放研究。提交 `07e95aa7`（2026-09-27）把模型可调用的 `fileRef + edits` 改成按路径 `write/replace`，同时将读取的 `[行号, 原文]` 改为 `startLine + text`；内部范围选择、可见覆盖、同版本坐标与事务规划继续存在。ADR 0023 记录的动机是降低凭据复制、范围定位失败和整批重试负担。2026-09-13 的 Project 第二轮记录则已经报告过模型多选一行导致校验失败，并以系统生成的逐行编号改善定位。上述报告属于当时的开发证据，不能代替当前候选的效果验证。

下一实现同时解决定位与编辑：由框架提供准确的目标选区和位置，原始正文保持连续。具体行号用于诊断、歧义消解或精确范围核对时由工具给出，不让模型从起始行推算。定位标注是元数据，避免重复发送正文副本。脚本直接复用读取、搜索或经验证代码查询返回的选区与短引用。所有同文件编辑绑定同一版本的原始坐标，并继续检查可见覆盖和重叠。

逐行编号不能保证模型永不抄错。字符替换可使用范围与唯一原文共同定位；锚点和位置不一致、片段不可见、快照过期时明确返回结构化缺口，禁止静默扩大到另一个目标。整行/整段替换需要独立校验其选中范围，不能把字符匹配误当作整段替换的校验字段。定位协议和字段均需经正式合同生成与行为验收之后才能用于真实模型评测。

零模型验收至少覆盖非第 1 行开始的窗口、不连续窗口、空行和 EOF、CRLF/Unicode、超长行及部分可见范围、错误位置与锚点冲突、外部修改、同批插入后的原始坐标和重叠编辑。此轮仅完成历史与当前代码核对，产品接口尚未改变，也未派发新付费任务。
