# Platform Act 正式运行审查报告

状态：正式实现、确定性验收、仓库门禁和真实任务闭环验证已完成。四阶段持续任务通过修复后的同状态接续完成；一次运行的稳定性与调用效率仍须继续评测。

## 正式执行链

1. 宿主通过包根 `await createRuntime({workspace, dataDir, model})` 建立工作区 Runtime。现有 Project 内核、Context SQLite、隔离 Script 执行器和 Provider 驱动在内部装配。
2. `session.submit` 保存用户目标，组装 task、workspace、observation、recent、runtime 五分区，经现有 ProviderRequestCompiler 发送请求。图片保留原生附件。
3. 模型使用当前请求的控制标记声明 observe、execute、blobs、done。流式文本可先展示；完整响应闭合并校验后才派发脚本。每段脚本独立运行，源码自动保存版本。
4. observe 在下一次业务模型请求前读取当前世界，execute 仅执行一次。已知效果经模式与权限检查，真实操作进入 Kernel 回执；结果按租约展示，持久 store 与原文引用独立于租约。
5. 主线可调用 worker、高级搜索和上下文整理。子任务的能力来自显式授予；搜索和整理使用专项工具集合。共享状态、消息和材料通过 store 的版本、授权和持久确认衔接。
6. Runtime 在请求边界发布通过版本和预算检查的整理结果。观察采集和展示策略分别记录，未决效果先核对，未被接受的模型响应不会造成脚本执行。
7. 取消、关闭和重开复用同一持久存储。活动运行可以被相关 store 变化唤醒；已结束任务由宿主再次 submit。

## 尚未完成的验证与边界

- shell 的观察约束由实际受限宿主提供；执行任意命令的效果无法仅凭脚本文本证明。
- 外部发送、浏览器操作和文件修改各自有回执与恢复语义，不承诺跨所有外部世界操作的统一回滚。
- 真实模型仍可能写错脚本、算错业务结果或误用展示参数。类型检查、版本前提与验收能暴露这些错误，但业务正确性需要对应的任务判据。
- 最终版本从全新状态重复运行长任务、量化一次成功率与成本，尚未形成基准结果。已有长任务证据包含修复后恢复，不能宣称已经低成本、一次稳定完成。
- 跨 Provider、其他操作系统和全部外部服务尚未逐一实测；已有平台条件跳过明确保留。
- 工作区现有改动保留，代码尚未提交或推送。
