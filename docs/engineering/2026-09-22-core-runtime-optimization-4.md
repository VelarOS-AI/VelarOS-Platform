# 核心运行时第四批优化差量

## 实现

1. **程序帧。** ProgramContext.project 在同一选择快照中读取租约、任务边界、历史重置、输出摘要、用户图像和子任务记录，避免先查租约再读取完整目录。正文与来源仍通过原有引用召回，帧发布仍使用增量 CAS。
2. **笔记帧。** ContextMemory.project 选择笔记、重置、维护策略、维护请求/结果、交付基线和脚本目录，保持结果来源的序号排序。目录只包含投影需要的种类；更新后的程序帧仍由对应阶段保存，不将早期快照缓存为整个请求的权威。
3. **历史帧与目录。** RecentContext 选择响应、脚本、重置、检查点和最后记录；帧中结果按引用补选，以保留重置后的过滤语义。最后记录单独取最新，through 仍是原目录真实上界，包含无关事件。发现目录仍列出可召回观察结果，历史正文继续排除观察输出。
4. **不可变结果分类。** 每个 RecentContext 按 objectId 缓存“是否观察输出”，只保存身份和布尔值。上限为 4096 项；每轮重查授权边界，重置换代清空缓存，正文缺失不缓存，IO 失败继续抛出。达到容量后新条目直接读取，避免顺序扫描反复驱逐已有缓存。历史窗口关闭时跳过结果分类，检查点与重置行为保持。

公开存储合同、模型操作、schema、发现内容和模板保持现有形式；使用第三批已有 selectSnapshot，缺失时继续完整快照。Runtime INV-15 / INV-18 增补缓存容量、缺失重读、重置、索引投影及历史不改写的验收。历史检查点写入和混合材料目录仍使用完整快照。

工作区并行新增的请求展示代码补齐了输入类型守卫及仓库判断函数写法，以恢复构建和风格门；相应展示回归纳入验证；子任务追踪预算断言同步计算原始正文和展示摘要的总字符数，仍要求准确使用 64 字符预算。

## 可复现基准

```sh
bun run --cwd packages/velaros build
node scripts/agent/benchmark-context-projection.mjs
```

基准在独占临时目录使用 SQLite WAL / FULL 持久性，10,000 条背景审计记录、200 条结果记录，其中一半为观察结果，另有一条笔记。每项 20 次采样，核对历史省略计数、笔记正文后清理目录。

2026-09-22，Node v24.15.0 / macOS arm64 的一次结果：

| 操作 | 当前完整快照回退路径，冷分类 p50 ms | 索引路径，冷分类 p50 ms | 索引路径，缓存预热 p50 ms |
| --- | ---: | ---: | ---: |
| 程序投影 | 23.786 | 0.586 | 0.620 |
| 历史投影 | 7.916 | 1.147 | 0.291 |
| 五分区投影 | 57.487 | 2.551 | 1.504 |

历史投影的结果正文读取：冷分类每次 200 次，索引缓存路径第一次 200 次、后续 0 次。五分区投影在历史缓存预热后仍有 4 次必要正文读取，冷分类为 204 次。程序投影不使用结果分类缓存，其两组索引数值差异是测量波动。

完整快照对照通过省略 selectSnapshot 构造，因此也影响第三批的增量程序提交；它不是第四批相对第三批的单独增益。冷分类通过每次新建 RecentContext 模拟重复解析，预热路径复用实例。本结果只证明固定负载下的路径差异，不能推导整轮真实模型任务加速比例。脚本和笔记目录仍随相关历史增长，超过缓存容量的分类仍会读取正文，SQLite 仍同步执行。

## 下一批分析

1. **缩小脚本目录。** 笔记与近期历史帧仍选择全部 script 前缀目录，包含源码、版本、控制回执等不参与历史正文的记录。下一步应测量这些类别的占比，明确结果分类与查询语义后下推筛选；需要兼容旧归档、错误结果和控制回执。
2. **笔记版本增长。** 选择笔记前缀后仍在内存中按键取最新，旧版本多时有增长成本。下一步区分最新目录和旧引用授权读取，验证重置代次与 revision 冲突。
3. **检查点提交。** RecentContext.checkpoint 仍完整读取与提交；可以按检查点、最近响应、目标结果及证据选择，但最近两次响应、through 上界与来源必须来自同一版本。
4. **零散引用读取。** SessionContext.readInput、混合材料 catalog/readMaterial/retainMaterial 仍存在全目录读取；适合按明确授权关系逐一改为索引查询，不能只凭引用存在就放行。
5. **长历史与事件循环。** 分类缓存对容量以内的重复投影有效，更大历史仍需查询层优化。先建立不同结果/笔记占比的长会话基线，再判断 Worker 适配器收益。评测累计回合增量归档和真实模型重复矩阵继续作为独立验证项。
