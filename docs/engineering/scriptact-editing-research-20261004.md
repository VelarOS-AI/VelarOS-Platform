# ScriptAct 编辑协议研究与推荐架构

日期：2026-10-04。状态：选区绑定、批量事务、摘要回执和失败计划增量修正已实现，通过项目层和正式 Runtime 行为验收。实现及验证见 [差量报告](scriptact-bound-editing-20261004.md)。

推荐把编辑建立在“连续源码 + 明确选区 + 按改动规模选择粒度 + 确定性事务”上。模型理解代码并生成变化；框架解析位置、绑定版本、保留未改内容和执行验收。具体行号、列号、字节偏移由工具计算。这个判断来自下述研究及当前代码核对，还需要以当前 gpt-5.6-sol / high 的真实配对确认效果。

## 研究证据及适用边界

| 来源 | 直接支持的判断 | 边界 |
| --- | --- | --- |
| [Diff-XYZ，2025-11 修订](https://arxiv.org/html/2510.12487v2) | 编辑格式的效果随模型与任务变化，强模型在其跨格式测试中普遍受益于 search/replace；格式说明也可能改变模型的输出行为。 | 主要测 diff 生成、应用和反向应用，不能直接等同于长程解题成绩。 |
| [CodeStruct，2026-04](https://arxiv.org/html/2604.05407v1) | 用函数、类和方法等命名实体连接读写，减少坐标与旧文本复制。SWE-Bench 的 GPT-5 比较中通过率 66.0% → 67.2%，输出 token 减少 45.7%，论文计算费用减少 19.5%。 | 这是论文所用 GPT-5、代理和预算的结果；源码已有语法错误时结构工具有局限。语法有效不保证逻辑正确。 |
| [To Diff or Not to Diff / AdaEdit，2026-04](https://arxiv.org/html/2604.27296v1) | 数字坐标格式即使配有编号输入仍有定位失败；完整语法块与适应性粒度值得研究。 | 核心收益涉及模型训练；论文也报告仅靠 few-shot 的强模型存在格式选择偏置。不能把训练结果直接当作我们的新提示词收益。 |
| [SWE-Edit，2026-04](https://arxiv.org/html/2604.26102v1) | 局部小改与复杂重构适合不同策略；读取、编辑、任务推理的负担可以分解。 | 其方案包含编辑模型与训练，额外模型费用和串行延迟必须计入完整成本；不能直接视作本地工具改造的效果。 |
| [Line-Anchored Feedback，2026-07](https://arxiv.org/html/2607.12713v1) | 位置明确的修改反馈可能降低输出负担，将编辑应用交给工具也值得测试。 | 主实验使用生成的 R 程序；函数拼接是探索性结果。它测试反馈定位，不直接证明给源码每行加前缀会改善或损害 GPT-5.6 Sol 的阅读。 |
| [Hashline 作者实验，2026-02](https://stencil.so/blog/the-harness-problem)；[另一实现的语言分组结果，2026-03](https://github.com/nwyin/edit-bench/issues/14) | 短锚点有助于避免复制旧文本，格式收益需要分模型、语言和任务验证。 | 前者主要是 React 文件机械变异；后者为单次、限时且带模糊匹配的工程实验，在 Python 上出现劣化。不是“逐行哈希通用最优”的证据。 |

“加行号后不是连续 Unicode”暂时只能作为格式假设。字符仍是正常文本；每行增加数字、标记或 JSON 包装会改变输入形式、增加元信息，而准确提供定位也可能帮助模型。研究支持坐标生成和机械复制确实存在风险，但本次没有找到直接证明逐行标注导致当前 GPT-5.6 Sol 阅读退化的证据。后续应把读取呈现与编辑定位分别控制，避免把两个因素同时变更后作单一归因。

## 核心：已绑定的编辑选区

选区不是一个要求模型计算的 range。它是框架根据明确目标解析、展示并签发的纯数据记录，绑定会话、项目、路径、文件版本、原始字符范围、可见覆盖、定位来源和目标种类。内部保留完整校验哈希；跨轮可见引用继续使用已授权的 8 位身份，并保留类型边界。一次脚本内直接传递返回的选区对象，避免手抄引用。

目标优先由准确的符号/结构查询得到，例如 `src/cache.py::Cache.load`，或经唯一短原文匹配定位。存在同名实体、重载或重复文本时返回带连续上下文的候选，由模型明确选择；模糊检索只生成候选，不授予静默写入另一目标的权利。当前代码查询带 `degraded`、`coverage.versioned` 等标志，候选结果不能直接冒充可靠可写节点。

读取交付完整、连续的相关语法单位；路径、符号和引用放在代码块之外。必要的调用关系、导入与周边作用域按相关性补齐，不因选区很小就剥夺解题上下文。同一正文只进入模型一次，定位元数据另存，不为每行都增加随机标记。诊断、歧义消解和精确范围核对可以提供工具计算的行号。

定位后返回的连续正文与选区元数据可以展示为：

```text
src/cache.py · Cache.load · target:7ac92f10
```

```python
def load(self, key):
    return self.cache[key]
```

替换这个方法时，模型直接传递 `select` 返回的 `target` 对象和完整新方法正文即可。较长方法的单个表达式修改则用 `select({targets:[{within:target,match:...}]})` 在方法内定位小片段，无须重新生成整个方法。

## 粒度选择

| 修改类型 | 模型提交 | 工具承担 |
| --- | --- | --- |
| 一处表达式、常量或调用 | 已确定作用域里的短匹配与新片段，或已签发的片段选区 | 唯一定位、版本与覆盖校验 |
| 控制流、函数、方法等较大修改 | 明确语法块的完整新正文 | 解析边界、保留其他块、校验完整文件 |
| 多文件重复规则 | 在明确目标集合上执行的一段 JavaScript 变换或有能力证据的语义操作 | 枚举覆盖、匹配数量断言、一次规划全部差量 |
| 新建、小文件整体改写或改动密集文件 | 完整新正文 | 文件级事务与必要验证 |
| 文本、配置或无法可靠解析的源码 | 唯一短原文、明确候选选区或格式专用定位，例如 JSON Pointer | 清晰说明定位能力与覆盖，不伪装成语义修改 |

粒度由实际改动、原文规模与定位可靠性共同决定。先提供简单可解释的选择规则并测量结果，逐步校准；不能直接要求未经训练的模型总能自动选出最便宜格式。对大范围改名，语义改名必须由能解析绑定和覆盖的语言服务执行；普通文本变换只承诺对确定集合的精确文本修改。

## 执行与失败恢复

1. 编译所有选区为同一原始版本上的字符拼接，复用现有范围/匹配规划与事务内核。检查覆盖、版本、权限和重叠后落盘，保持同批原子性。
2. AST/CST 用来定位，真实拼接以原始源码为准，保存注释、装饰器、空白、编码与物理换行。适配器明确 UTF-8 字节与 UTF-16 等位置语义，工具统一转换；模型不计算偏移，不擅自规范化 Unicode 正文。
3. 目标、版本或覆盖不一致时返回错误与准确候选；初期按版本冲突拒绝，任何后续重定位必须以唯一目标和未变内容为证据。不能用相似度直接放宽写入。
4. 原本语法损坏或解析能力不足时，使用明确的文本选区修复并重新验证。结构解析成功只证明位置和语法信息，不证明解题正确。
5. 一批里多个定位问题汇总为结构化缺口。失败规划可保留供增量修正，使模型只更正失败部分；只有完整批次重新通过校验才提交。复用当前程序与精确 edits 能力，避免重写所有正确步骤。
6. 回执支持简短摘要；完整 diff、原始调用、失败、原文和撤销证据继续保存，可从短 changeRef 获取。模型可见回执与审计原始负载分别统计。

长正文的承载可进一步研究“操作元信息 + 原始代码载荷”，以减少嵌套字符串转义；先独立验证边界、反引号/协议样式正文、Unicode 与恢复行为。首阶段沿用经过验证的 ScriptAct 程序承载，定位优化不依赖同时重做整个控制协议。

## 当前实现与落地顺序

`ProjectContentEdit`、`selectProjectMutations` 和 `planProjectFileEdits` 提供范围/匹配选择、可见覆盖与同版本一次拼接；`file-refs` 存原文、签发并检查视图。新增的 `select` 与 `patch` 直接复用这些组件及事务内核。公开的 `ProjectEditStep` 继续提供路径 write/replace 等操作；`read` 和 `search` 的连续可编辑窗口现在附带选区目标。

第一、二阶段已落地：连续源码绑定、准确结构与字面目标、批量摘要和失败计划增量修正，以及正式声明、模板、验收承诺和差量报告。结构定位使用内置 TypeScript/Lezer Python 解析器，解析错误明确交给文本选区。后续按实测缺口扩展语义变换、密集改写和原始载荷能力。

源码解析和快照可按版本复用；已授权的缓存断点保持。缓存用于复用稳定部分，陈旧源码不能因命中缓存而取得编辑权。优化目标仍是质量、端到端时间和完整费用；请求数量、缓存命中、输入/输出与模块调用用于诊断。

## 验收与效果证明

零模型行为验收覆盖：函数/方法/嵌套同名与重载、注释和装饰器、初始坏语法、非代码文件、重复片段、空行/EOF、CRLF/Unicode/位置编码、不连续可见范围、部分读取、目标引用误抄、跨会话与项目、版本冲突、重叠与同批插入、校验失败/回滚，以及多文件多处重复编辑。测试在隔离目录执行，不向生产侧栏灌入临时验收会话。

真实验证分开测“可应用的编辑”“正确修复任务”和“完整开销”。记录定位错误、协议错误、语法错误、最终验收失败、模型等待与本地规划时间、可见输入/输出、缓存与模块/工具次数。失败和未知用量保留，第三方实际扣费未知时不把参考费估算当完整扣费。先在冻结的开发候选上用同模型、多语言和不同改动规模校准，再与同期 Codex 配对，并保持独立验证池隔离。研究中的具体题例若用于开发分析，不能再计入独立验证。

本报告给出的是最有依据的实施方向。论文、工程实验和当前代码能力都不能替代本产品上的效果证据；没有据此宣称当前 ScriptAct 已经加速、降费或超过 Codex。
