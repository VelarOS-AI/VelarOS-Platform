# 核心运行时第二批优化差量

## 交付行为

1. 任务续租、模型预算预占和用量记账通过元数据快照更新，不再读取或重写历史记录目录。任务切换时，旧任务归档与新任务元数据在同一事务提交；归档失败保留原任务。
2. 调用日志索引先按 refId 查重，再增量追加，保留跨连接唯一占用。调用准备、派发和终态回执继续使用既有持久化合同。
3. 评测完整证据快照合并在途请求，并在成功保存后间隔至少两秒才启动普通快照。events.ndjson 仍逐条追加；收尾等待在途快照并重新读取最新状态，覆盖迟到回执。失败后最终导出会重试，但保留原错误。summary.checkpoints 暴露写入、合并、跳过次数和写入耗时。
4. RuntimeDiagnostics 透传并采样元数据扩展，外部适配器缺少扩展时仍走原有完整 CAS。

## 合同与验收变化

| 合同 | 理由与影响 |
| --- | --- |
| ContextMetadata | 从根入口及 contracts 导出的可移植类型，等于去掉 records 的 ContextState；不引入另一份状态权威。 |
| ContextStorage.loadMetadata | 可选小快照读取，返回独立 JSON 数据，与完整快照共享版本。 |
| ContextStorage.compareAndSwapMetadata | 可选增量事务：替换元数据并追加目录项，保留已有目录。存储分配 sequence，检查非空正文引用和重复身份，失败整体回滚。与完整 CAS、appendRecord 共用版本，旧版本提交失败。 |
| Context INV-7 / INV-12 | 扩展覆盖无历史扫描的记账、原子任务归档、索引并发占用与增量事务兼容；原有一致性和恢复承诺保持。 |
| 评测周期快照 | 运行中的完整报告可能落后于事件流；默认成功快照后的节流窗口为两秒，实际新鲜度还取决于写入耗时。最终报告经过一次新读取。 |

任务写入仅在两个元数据方法同时可用时启用快路径；调用索引还要求 records。适配器可逐步接入，缺少能力时完整 CAS 仍可用。没有数据库格式迁移。模型操作、schema、发现内容及模板保持现有合同。

## 可复现基准

```sh
bun run --cwd packages/context build
node scripts/agent/benchmark-context-metadata.mjs
```

独占临时目录中的真实 SQLite，WAL / FULL 持久性，每组 20 次操作；完整路径与增量路径使用同样的数据和业务操作，完整路径仅省略元数据扩展。结束核对记录数、用量和索引后清理目录。2026-09-22 本机 Node v24.15.0 / macOS arm64 的一次结果，历史记录 10,000 条：

| 操作 | 完整路径 p50 ms | 增量路径 p50 ms | 完整路径 p95 ms | 增量路径 p95 ms |
| --- | ---: | ---: | ---: | ---: |
| 续租 | 21.108 | 0.045 | 37.398 | 0.077 |
| 预算预占 | 15.885 | 0.039 | 22.155 | 0.047 |
| 用量记账 | 20.422 | 0.039 | 78.174 | 0.042 |
| 调用登记 | 15.599 | 0.200 | 22.776 | 0.272 |

同次采样，续租期间 setImmediate 让出延迟 p95 从 37.473 ms 降到 0.091 ms，调用登记从 22.948 ms 降到 0.286 ms。这是固定负载的微基准，包含缓存和调度影响；不是生产事件循环延迟或整轮任务加速比例。SQLite 仍同步执行，完整快照仍有随历史增长的成本。

## 下一批分析

1. **程序状态与版本查询。** ProgramContext.state/update 仍 load 完整目录，version/receipt 也在全量记录中找最后一项。应先增加带版本边界的索引读取，覆盖任务 startedSequence、同一控制身份回放和来源验证，再将多条记录与状态合并提交；不能把分别读取的元数据和目录当成同一快照。
2. **工作笔记与上下文帧。** ContextMemory.notes 按标题前缀整理所有记录，update 用完整 CAS；acknowledge 为精确标题读取整个目录。应分别测量笔记目录和精确帧查询，保留 reset 边界、来源授权及笔记 revision 冲突。
3. **长任务归档。** 本批减少完整导出的频率，单次导出仍随累计回合和子任务增长。下一步需要稳定回合的明确完成边界，区分持久事件追加和仍会结算的回执，验证崩溃恢复与迟到结果后再做增量导出。
4. **同步数据库剩余阻塞。** 高频记账已避开大扫描；程序和笔记查询优化后再测真实长会话，并据事件循环延迟决定是否引入 Worker 存储适配器。Worker 的关闭、取消和事务队列需要独立验收。
5. **真实模型统计。** 固定模型配置与源码身份后运行既有四场景重复矩阵，用成功率、成本和阶段计量决定上下文策略变化。当前微基准不提供模型质量结论。
