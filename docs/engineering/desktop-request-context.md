# Desktop 请求上下文查看差量

日期：2026-09-22。

## 本轮范围

封存模型请求 → Platform 只读摘要 → Desktop 可靠 notice → 调试面板 → 会话保存与重开。

调试面的请求数据来自本回合的 ProviderRequestCompiler 审计快照。模型身份、输入 token 计量及精度/依据、输出预算、系统指令、请求消息和原始指纹可查看。封存发生在调用供应商之前，不能据此断言供应商已接收；界面保留这一事实边界。

## 公开合同差量

- ActTurnTrace 增加 requestSummary，类型为 ActRequestSummary 或 null；新数据类型由根入口和 contracts 入口导出。
- 历史没有封存 providerRequest 时返回 null，缺失输入计量为 null，不从文本长度推算。
- 系统指令最多 8000 字符，消息最多 24000 字符，分别标记截断；二者计入 trace 和分页 trace 的 maxChars 总正文预算。
- 摘要优先占用本次追踪预算，剩余预算再分配原始请求、回执和调用展示；完整原文仍由 Platform 保存。展示截断不改变完整请求指纹。
- 图像块与带类型标签的字节数据替换成占位，mediaOmitted 明确标记；原始存储内容不改写。
- provides/requires 的方法、模型操作和工具定义不变。构造 ActTurnTrace 的消费者需要补齐 requestSummary。

## Desktop 归属与生命周期

每个 turn 的持久身份构成 platform-request 信封身份。主进程在收到 turn 时读取追踪，沿用上一轮的执行记录读取口与可靠流。生产者和消费者异步调度，通知可能发生在供应商 stream 已开始之后；模型生成期间的可见性有实际集成回归覆盖。

renderer 只校验产品信封并填充既有调试快照，界面对 Platform 快照使用专门展示分支。按请求身份去重，修复请求和不同运行中同序号的回合分别保留；最多缓存最近 24 个。历史持久化沿用会话存储，新的请求身份进入即时保存指纹，无需等待额外输入事件。

contextGovernance 能力门保持按执行端口判定，错误提示统一描述当前运行时的接入状态。主动整理、替换工作集与恢复操作需要使用 Platform 的正式控制接口；本轮交付只读查看。

## 验收差量

新增 INV-46 和请求展示测试，覆盖真实封存字段、媒体占位、截断、未知计量、总预算、关闭后无模型读取。已有执行追踪与宿主指令验收保持。

Desktop 新增模型生成期间请求可见、跨提交身份隔离的集成用例；既有收尾追踪用例增加请求开始时的读取断言，原取消与晚到回执承诺保持。renderer 新增去重、修复隔离、24 条上限、非法信封、保存恢复及即时保存指纹回归。
