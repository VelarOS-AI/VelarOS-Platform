## 本轮公开合同差量

`ContextCompletionPort.requirements(view, signal)` 可同步或异步返回 `ContextDeliveryRequirement`。每项包含唯一 id、说明、全部预期产物身份 `artifacts` 和当前任务用户记录 `sourceRefs`。使用 `checks.check` 取得核查证明；仅有 passed/complete 声明不能满足必需项。最终报告携带已固定的 `requirement`，核查证明的事实字段与签发记录一致，并在发布前重新探测产物。

Desktop 的验收事件保存报告范围、时间、必需项、产物版本、证明引用及其他证据引用。消息 UI 由 Desktop 自有渲染入口显示这些数据；投影身份随验收修正改变，已有消息会随状态更新。

## 增量统计的本机测量

Bun 1.3.13、macOS arm64；1 万条相同请求记录上连续修正 50 条历史记录，5 组交错顺序。双方逐次使用同一组输入，核对最终 Token 与费用；数组基线提前展开记录，不计其展开时间，增量方案首次建索引汇总单独计时。最终冻结源文件哈希的复测中位数为全量汇总 315.25 ms、增量汇总 0.48 ms。1000 次每页 25 条的历史查询合计 1.24 ms。

这个测量只说明本地统计与查询路径的开销，不包含模型、IPC、磁盘和完整 UI 渲染，也不证明 Agent 整体加速或任务质量提升。逐组原始时间、第一次建汇总的耗时、前后源码哈希与测量脚本保存在 `delivery-coverage/usage-aggregation-benchmark.json` 和同名 `.ts` 文件中。
