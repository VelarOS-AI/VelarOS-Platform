# 同批预检失败的执行记录

真实浏览器任务提交两个程序，其中一个语法错误。派发器原先只保存失败程序的回执，其他未执行程序在 Desktop 保持排队；如果失败程序位于第二段，其回执还会被追踪层误配到第一段的位置。

现在整批预检失败时保留所有执行声明的原始顺序、执行身份及源码引用。实际检查失败保留原错误；其余段落得到 `CANCELLED` 回执并明确本段未执行。发布仍是原子拒绝，不创建任务租约、不启动程序、不切换观察，也不放宽语法检查。被取消段落的源码随控制回执持久保存，追踪界面可以解释取消原因。

没有新增公开操作或参数，使用已有拒绝回执及取消错误码，不需要旧版本兼容。回归通过真实运行时覆盖第一段失败、第二段失败、观察检查失败和后续修复重试；均逐项核对执行位置、源码、错误及终态。Windows 本地新增三项全部通过；既有观察运行测试依赖 Linux 只读隔离，在 Linux CI 完成整套验证，不放宽隔离边界。
