# Observe 动态上下文差量（2026-11-09）

本批以 `v0.7.4` / 基础包与能力包 `0.9.3` 的固定源码为起点，保留 observe，并修复观察正文反复进入普通增量历史的问题。新发行准备为 `v0.7.5`、基础包与能力包 `0.9.4`；旧发行不改写。

## 合同与行为

完整理由、数值边界与公开 API 差量见[设计与合同差量](../architecture/observe-dynamic-context.md)。本次主要变化如下：

- 普通 exec 结果进入增量历史；当前观察、显式历史片段和完整原生观察往返只进入本轮动态区。编码器新增 `layout()`，稳定前缀与协议尾区分别处理，完整请求身份仍包含动态变化。
- observe 新增互斥的 `history` 目录和局部读取选择，沿现有 Context 引用、journal 和索引定位正文。A→A 不新增变化，A→B→A 记录本次变化时间并复用真正同值内容；业务 revision 保留。
- 观察业务材料默认 2048、动态合计最多 4096 个 UTF-16 字符；采集与 journal 结算前拒绝巨大载荷，Node 观察日志使用专属小额度。完整协议组另受完整请求预算约束，不能截组满足正文额度。
- 宿主与执行器报告真实只读能力。缺后端时程序登记、刷新和重跑拒绝，历史选择与清除继续可用；普通 execute 不受观察能力门限制。没有普通执行冒充只读观察的回落。
- 原生 observe 与 exec 混批在执行前拒绝；宿主及文本复合提交保持原子预检。任务、授权重置和源请求归属共同约束待交付材料，未接受响应不消费材料。
- Agent 两个公共端口仅增加可选字段和方法，已按 additive 类型差量更新既有 API baseline。观察额度、混批限制和 `compiledPrompt` 分区属于可见行为变化，自定义驱动和适配器应按设计文档迁移；不宣称所有旧调用的行为完全兼容。

正式 tag 前另纳入一项独立 sandbox 数据边界修复：恢复 mirror 清单时，`ignored` 必须是 `link/copy/skip` 字符串，不能先经 `String(...)` 强转而接受单元素数组。沿已有新宿主恢复夹具验证非法值不登记、合法枚举仍可恢复；未混入既有风格表的其他清理。

## 验证与范围

本地验证使用 Windows、真实 SQLite 和本地模型/执行夹具。覆盖了当前材料及历史归属、A→A→B→A、真实键缺席、巨量载荷结算前限制、日志取消、并发预算、任务与授权失效、原生往返完整性、交付证明及普通执行回归。缺只读后端的场景正面核对真实拒绝理由与零执行；需要成功只读进程的集成路径没有伪造成功。

实际 SDK wire 夹具截获了四轮 A/A/B/A 请求：每轮只出现一次当前观察，稳定部分保持前缀，动态变化影响完整消息身份。HTTP 全部在本地截获，不调用付费模型；这只证明编码机制，没有测量模型自然选择率、供应商缓存命中率或真实提供商费用。

公共请求分区变更的消费方按 AST 清单及别名追踪一起迁移：原 61 处 `compiledPrompt` 读取中，3 处生产读取和 50 处测试稳定正文读取保留，8 处错位读取迁往 protocol、dynamic 或完整编码消息；另外修正稳定前缀比较边界。发布消费者、Harbor 与 act-eval 的控制标记均走 protocol，没有把尾区拼回稳定帧。发布前基础包与能力包候选各生成一次，同一组摘要字节通过独立安装、真实 foundation/host/session-trace JavaScript 和严格声明消费。

既有评测限制单列：Harbor 六个定向用例及 act-eval 两个无证据负例在模型构造前被搜索预算校验拒绝，评测宿主冻结 profile 缺少必需 `reads`。一条代表 Harbor 用例使用起点 `308b3f30` 的原测试复现相同拒绝，相关 profile、验证器和运行入口源码与起点相同；没有改产品预算或验证规则，也没有把未进入模型的用例记作通过。真实请求分区仍由合法最小场景及同候选归档消费者验证。

生成声明、Act 目录、README 类型示例、错误构造、公开 API baseline、格式化与发布预检按对应检查器验证。正式 CI、发布源码身份及归档独立消费结果由正式 release manifest / validation 记录。
