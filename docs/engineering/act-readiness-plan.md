# Act 完整运行审查与实测方案

## 完成条件

1. 正式 createRuntime 入口可以从工作区、持久目录和模型配置建立可用会话，常见装配在框架内部完成；底层依赖注入仍供测试和专用宿主使用。
2. 模型能发现实际可用模块、profile 和完整用法；协议、observe/execute、输出租约、笔记、store、共享、搜索、子任务、交互、完成及恢复用语一致。
3. 运行、取消、关闭、重开、并发、权限、版本、未知效果、上下文容量和长期持久化有可执行证据。
4. 可读取真实发送前上下文、模型原始输出、脚本版本、Kernel 调用、回执、下一帧差量和支线轨迹；评测产物不包含凭据。
5. 代码审查和确定性验证完成后，使用用户指定端点的 gpt-5.5、高思考力度，运行后台真实工作负载。仅在证据指向模型能力问题时使用 gpt-5.6-sol 二次核验。
6. 每类模块有对应能力测试或真实任务验证；长期任务覆盖动态上下文、整理、结果租约、协作、恢复和真实落盘。记录问题、修复和复验，逐项列出证据及未验证边界。

## 推进顺序

| 阶段 | 工作 | 进入下一阶段的证据 |
| --- | --- | --- |
| A 静态审查 | 入口、依赖方向、协议、模型说明、能力发现、生命周期、持久化和追踪 | 问题清单与可复现定位；完成已发现的设计修正 |
| B 正式实现 | 单入口默认装配、简明模型手册、profile 发现、追踪归档和修复 | 单元与集成验收、构建、类型和架构门禁 |
| C 后台验证台 | 复用正式 Runtime 与既有 Agent Lab，建立分模块及长任务负载、独立判据、进度和完整追踪 | 确定性驱动可走完各条链路，错误会判失败而不是仅看模型宣布完成 |
| D 真实模型 | 指定模型逐项执行；检查每轮上下文与世界效果，发现问题后回到 B/C 复验 | 真实归档、独立判据、用量与已知限制；不以少数成功任务证明所有情况 |
| E 交付审计 | 按本表逐项复核仓库和验证产物 | 交付报告中每个完成项对应可检查证据 |

## 已完成的接入

- 正式入口负责默认项目、证据源、隔离执行器、持久存储及可选模型工具装配，专用宿主仍可提供现有端口。
- agents/search 的 profile 从实际配置生成发现目录，声明和用法与装配保持一致。
- 后台评测接通现有 Provider 的思考参数，覆盖读改观察、共享协作、高级搜索和四阶段持续处理。
- 主线和支线追踪写入同一持久证据源，评测持续导出原始请求、响应、脚本和回执。
- 关闭重开、初始化失败、长期状态和取消收尾均有确定性验收。最终通过数量以差量报告和最后一次日志为准。

本轮 A–E 阶段均已交付。真实模型调用在 A/B/C 证据齐备后执行；四阶段持续任务经同状态恢复通过独立判据，最终版本的从零重复成功率和成本基准仍待后续评测。实际结果与边界见 [交付报告](act-readiness-report.md)。密钥从进程环境读取，配置、源码、追踪和报告只保存变量名及非敏感配置。
