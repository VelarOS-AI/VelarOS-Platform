# 项目事务调用简化

普通文件读写、遍历与搜索使用 Node 和现有成熟库。项目能力不再把简单改动引导到 read/select、目标引用、patch 的固定流程；保护事务直接使用现有 `edit`，需要撤回时使用回执的 `undo`。

## 合同变化

- `write` 新增可选 `expectedText`：传入已读的完整解码原文，在该步骤的当前视图上核对；`null` 要求文件不存在；省略保留已有覆盖行为。无需额外读取、引用或版本号。字符串比较只忽略开头编码 BOM，换行仍精确比较。
- 任一步原文不匹配报 `BASE_REVISION_MISMATCH`，整批不写入。核对在事务编译器使用同一文件视图完成，提交仍经过原有磁盘版本检查和失败回滚，撤回仍拒绝覆盖外部修改。
- 文本比较不承诺识别内容相同的历史往返修改，也不是读取时编码的指纹。Node 应按实际编码解码；写入继续保留事务读取时的编码和换行。
- 精确片段替换继续使用 `replace.oldText`，保留片段外的外部修改；结构定位 `select/patch` 保留，不要求日常编辑使用。
- 常驻 Node 指令、受限执行说明、生成声明、README 和按需模板使用同一规则。未增加依赖，也未把完整项目声明加入常驻上下文。

## 不变量与覆盖

INV-2/3 增补可选原文保护，原来的无条件 write 与片段替换语义不变。INV-42 从模板额外批量读取再 patch 改为接收 Node 已读原文后一次 edit，原因是取消用户指出的重复读取和引用管理；独立的 read/list/search 操作及其原有测试保留。INV-1 将操作数量修正为实际已有的九项，未新增操作。

项目编辑回归覆盖多文件提交与撤回、外部修改导致整批拒绝、只允许新建、空文件与删除、步骤内连续编辑、BOM/换行保留、换行冲突、非法参数和撤回冲突。模板测试使用生成的真实声明，并检查批量提交仅发生一次 edit；原有内核提交竞争与回滚测试继续运行。Desktop 增加真实 Node 子进程与宿主桥集成，验证 edit → undo → 冲突拒绝，无 project.read/select/patch。

此变更证明调用路径和保护行为，不代表模型实际采用率已提升；未重跑完整游戏任务。
