# 标准运行时：输入精简与原生模块发现

本轮在标准 Node 执行环境上优化每轮输入和宿主能力文件，再与原 ScriptAct、首版 Node 同时对照。依据是首版轨迹中的通用开销：工作帧持续携带空观察、空笔记、内部统计与使用说明，宿主客户端各自重复整段传输实现。

## 执行与模块边界

| 范围 | 当前执行方式 |
| --- | --- |
| Desktop 主会话、默认业务子任务 | 真实 Node.js，标准库、项目依赖和普通文件；命令使用标准子进程 API |
| 浏览器、界面、图片交付、会话协作、持久后台任务等 | 按需读取宿主目录中的正式合同，import 普通 ES 模块客户端，经 Kernel 调用真实宿主 |
| 上下文维护、受控观察、证据检索、未注入 Node 的嵌入宿主 | QuickJS，在受限模块范围内执行；Desktop 由独立 utilityProcess 承载 |
| 文件和项目模块的底层实现 | 继续支持受限程序和产品服务；Node 业务目录中的通用 I/O 由标准库承担 |

执行环境在会话装配时确定。Node 程序出错时交付实际错误与输出；调用端按结果继续工作。业务程序不需要学习 QuickJS 的虚拟模块、blob 或输出协议，内部受控程序维持自身权限边界。

QuickJS 执行器在实际运行受限程序时才启动子进程；业务代码由 Node 执行，受限内部程序按需调用 QuickJS。保留这一边界使上下文维护和证据读取仍只能访问其授权能力，业务会话则可以使用标准 Node I/O。

## 差量与理由

- Node 工作帧采用精简展示：保留任务归属、目标、非空工作记忆、观察安全信息、执行结果、失败与未知效果、后台任务、材料缺口及停滞状态。宿主完整帧、授权水位、正文交付证明、容量判定与不可变归档继续保留。
- 空状态只在明确的运行时结构层省略；业务材料中的空对象、空数组以及 `false`、`0`、`null` 保留原始含义，数组顺序和重复项不改变。
- 能力文件名由模块身份确定，目录排序变化不影响相对文件名。`.d.ts` 使用 TS AST 将正式生成声明转为普通文件模块，保留合同注释及依赖类型；同名 `.mjs` 提供导出，共享一个标准 ES 模块传输文件。
- 常驻说明指向普通文件目录，能力索引和合同均按需读取。接口声明仍只有正式 TS 来源；能力授权、参数校验和回执继续由原 Kernel 负责。

本轮没有新增公开业务操作。`MemoryFrameDisplay.presentation` 是内部展示标记，实际业务源代码与 Node API 语义保持标准行为。模块物理文件名是本次执行目录的发现结果；会话通过当前目录取得客户端。

## 验证设计

前版有效比较和失败保存在 [首版报告](scriptact-standard-runtime-20261004.md)。这轮使用六个新任务：标准输入命令、原始字节清单、并发映射、已安装统计包、真实宿主会话查询、不可变配置迁移。验收器先用独立参考实现验证；输入和依赖的原文保护纳入判定。每类固定重复两次，每侧 12 次，共 36 次，三种环境轮换先后顺序。

三个代码版本分别冻结为 `baseline`、`previous`、`standard`。原 ScriptAct 的基线提交为 `7c226247`，前版 Node 提交为 `d0f9ccda`；运行前固定最终候选、任务集、评测器的 SHA256。使用同一 `gpt-5.6-sol`、high reasoning、Responses 参数、每题 8 次请求与 240 秒上限。每次在独立工作区执行，模型收到同一任务；正式模型请求前先完成三侧真实 Shell 预检。

成功要求独立产物验收与运行正常完成同时成立；统计保留所有尝试。用量缺失保持未知，输入输出与参考费用只比较双方用量完整的配对。参考费用沿用输入 $4/M、输出 $20/M 的固定未缓存折算，不代表实际账单。任务用作后续诊断时，新泛化结论需要再冻结独立任务。

证据目录：`.velaros-workspace/bench/standard-runtime-v2-20261004/`。原始结果和轨迹逐次保存；本机检查日志位于 `/tmp/velaros-standard-runtime-v2-20261004/`。

### 运行中的异常与恢复

服务返回了 7 次中断：原 ScriptAct 4 次、首版 Node 1 次、本轮 Node 2 次，均自行恢复。这些请求缺少完整用量，因此相关运行保留 `null`。具体任务、轮次及中断类型保存在结果文件中。

标准 API 误用出现 3 次：首版 Node 的配置迁移第 1 次，本轮 Node 的异步并发第 2 次和配置迁移第 2 次。模型给异步 `execFile` 传入其不支持的 `input` 选项，调用 `apply_patch` 的子进程持续等待 stdin，约 120 秒后达到程序时限。模型随后改用 `spawn` 并关闭 stdin，重新核对文件并完成任务。三次等待均保留在总耗时中；标准 Node 语义和统一时限保持原样。

这说明熟悉 JS 并不保证每次正确使用标准库。减少常驻说明与专用封装降低了输入成本，独立产物验证、明确的进程状态及超时回收仍有必要。36 次均成功并不能推导出更复杂任务、其他模型或其他操作系统上的同等成功率。

### 同帧展示开销

将首版的 35 个归档工作帧分别按完整和精简展示重新生成，文本从 150,025 字符降至 66,346 字符，减少 55.78%。两种展示使用相同状态和业务正文；这是展示层的确定性开销比较，区别于上面的真实任务输入 Token、费用和耗时。旧轨迹用于诊断，泛化验收使用本轮运行前冻结的新任务。
