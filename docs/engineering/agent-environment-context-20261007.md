## 数据来源与刷新

- 能力来自本会话 `allowedModules()` 和 Kernel 的真实模块描述。Office、Project、Computer、Browser 等已挂载能力自动出现，用途沿用生成合同的摘要。系统成员表示为公共模块 `velaros:system` 加成员名，模型可以据此找到实际导入入口。
- npm 来自基础包和当前 `acquireRuntime` 快照，版本重新读取安装目录中的 package.json；别名保留实际导入名。损坏条目保留读取诊断。这里展示 Agent 环境的安装事实，工作区同名依赖仍由程序入口按 Node 规则优先解析。
- Skill 来自当前 Node 环境所选的 Skill，提供名称、版本和用途；说明及资源通过执行目录查询。
- 主会话、子任务和专项会话共用 RuntimeSession 的投影入口，各自按照实际授权生成能力清单。环境信息在每次模型请求前读取；安装、更新、回滚、删除后的下一帧反映新状态。
- 清单读取期间持有 npm 快照租约，结束即释放，不启动探索脚本或业务操作。整个环境读取失败时交付诊断并继续显示能力，便于模型决定恢复步骤。

## 上下文与合同变化

`RuntimeSession.project` 将 `runtime.inventory` 放入动态帧，计入工作内存预算和 `memoryStatus.footprint.runtime`。固定指令只解释清单和发现方式，环境变更不改写指令前缀。

索引使用不超过本帧四分之一、最多 12,000 字符的展示目标，每条用途与诊断最多 180 字符；完整数量保存在 `totals`。预算不足时折叠目录条目，模型可通过已有目录入口补读。不可进一步压缩的数量和诊断仍经过最终请求预算核对。

本轮增加的是模型上下文数据，已有模型操作、宿主 Runtime 配置、包导出和授权行为保持兼容。`RuntimeNodeOptions` 文档明确 `acquireRuntime` 也会用于请求前的清单读取，读取结束释放，宿主应将其视为取得快照而非进程启动信号。内部 `RuntimeInventory` 类型明确清单形状，纯投影函数统一公共导入名映射和预算处理。
