# ScriptAct 评测与故障诊断经验

运行时优化需要同时改善任务质量、稳定性、端到端时间和完整费用。此处保存本机历史中反复出现的失败机制，配合现有 [评测规范](scriptact-acceptance-criteria.md) 使用。带版本编号的实测状态和原始记录摘要见 [交接快照](handoff-state-20261015.md)。

## 修复通用根因并保留独立验证

2026 年 9 月明确形成的约束是“必须防止针对已测样本过拟合”。任务名、仓库名和参考答案用于证据定位；实现应针对协议、状态、资源或公开 API 的通用原因。

1. 在分析前记录任务、来源提交、依赖、候选、评分器、成功条件和预算，冻结实际执行输入。
2. 一旦任务被用于诊断、调提示或修改实现，就把后续复测解释为开发回归；历史评分与原有 split 原样保留。
3. 新修复使用事前冻结、尚未用于修复的任务验证，覆盖不同数据形状、任务类型、能力组合和边界。
4. 比较时保留所有失败、中断、取消、恢复和未知值，按同一候选与同一比较口径分组。

一次同题改善支持根因判断和回归结论。总体优劣需要足够独立任务与相符的比较设计；具体复跑次数由研究问题决定。适用方法见 [Agent Lab 测量方法](../agent-lab/methodology.md)。

## 验收覆盖最终真实交付

最终回复、流程终态、冻结功能评分和完整交付分别记录。功能检查通过的产物，仍可能缺少默认测试覆盖、文档、构建传播、兼容性或任务要求的长程证据。

| 触发或症状 | 已遇到的机制 | 下一次应验证的证据 |
| --- | --- | --- |
| 类型检查退出 0，新增断言却没有约束产物 | 不同 tsd 版本对 `--files` 的支持不同，绝对路径也可能被错误拼到 cwd 下 | 在独占消费项目中调用真实安装的工具；正确实现通过，故意错误声明必须失败；确认永久断言进入默认测试命令 |
| 新功能和维护测试通过，旧用户仍编译失败 | 声明从 `Promise<Buffer>` 变为 `Promise<Uint8Array>` 等变化损坏真实消费代码 | 编译独立旧调用方，核对公开声明与运行值；追加反例作为诊断，保留原冻结评分 |
| 编辑工具返回后，目标源码实际没有变化 | 猜测命令存在性或误读返回字段；旧轨迹曾把无输出当成成功 | 读取真实退出字段、工作树 diff 和最终文件，再执行需要该变更才能通过的验收 |
| 维护源已改，发布产物仍旧 | 构建未传播命名导出，或重新构建删除了测试文件 | 干净重建、再次构建、产物导出检查、打包后独立安装消费 |
| 模型声称修复某条路径 | 最终 diff 与实际执行范围不足以支持声明 | 将报告逐项关联到最终产物身份、具体命令、测试发现范围和回执 |
| 墙钟运行很久，长程任务仍不合格 | 空闲、失败恢复或进度间隔超限被混入有效时长 | 按冻结要求核算真实工作区间、唯一事务、故障类别和相邻进度事件，关联进程与源码证据 |

验证器也需要正反控制。改变评分器时记录故障原因、原始文件和身份，对保留产物重新评分；判分修复与模型重新执行分别记账。

## 模型输入与执行身份

标准 Node 和 npm 适合通用执行，领域能力按任务实际需要发现。项目内裸导入遵循该项目依赖树；宿主预装包有独立身份。例如历史任务中的项目 Execa 5 与宿主 Execa 9 具有不同导出形状，错误解析会造成真实执行失败。交接时的本机候选为此提供显式宿主包命名空间，具体 API 状态见快照。

对长执行保留 `executionId`，读取或等待同一执行，并在取消后核对收束。高频轮询、重复定时器程序和重跑原命令都会扩大成本或改变外部效果；等待接口应明确到期、取消、自身等待和归属语义。

目标正文、原始输入和模型看到的投影具有不同身份。长目标在持久账本中截断，可能使尾部验收要求失去持续可见性。验收应覆盖全文、Unicode、重启、完成核对、原文分页以及跨会话权限；紧凑投影仍要能定位完整原文。

## 上下文与缓存

减少输入字符只是局部变化。历史对照中，逐轮重建当前状态减少了输入，却显著减少缓存复用并增加时间和参考费用。诊断要同时检查最终发送的请求体、已接受前缀、工具结果表示、供应商 usage 和整题结果。

先确认可用的有界当前投影，再判断是否需要替换历史段。机械负载能证明封段次数、原文归档和操作次数保持正确；实际缓存命中、token、延迟和费用仍要通过真实请求验证。短题未触发上下文溢出时，其成绩无法验证溢出修复。

未知模型容量应由所属驱动、实际请求编译和供应商反馈校准。配置里写出的窗口、字符估算、供应商接受的请求及真实 usage 分别保留，不把一种计量直接当成另一种。

## 完整费用与故障分层

请求账本覆盖主任务、子任务、整理、完成核查、重试和取消后的迟到结果，并按稳定请求身份去重。记录已知用量、缺失用量数、参考费率日期及预算占用。缺失 usage 的请求保持未知；已知参考费用只能给出对应部分的成本。

耗时分开记录模型等待、程序执行、排队、准备、验证和清理，再按双方一致口径计算总时间。请求数减少可能同时遇到更长的上游等待。缓存命中率帮助解释结果，不能单独证明完整成本或速度改善。

连接重置按证据分层排查：客户端是否先取消、网关硬截止、最后数据时间、上游终态及 usage 是否到达。历史本地 65 秒等待控制通过，只能排除被测网关自己的相应截止；远端服务或中间代理仍需要各自证据。

## 长任务的资源生命周期

每次尝试有独占的任务根、证据根、进程归属和容量预算。准备、执行副本、评分副本和归档余量都计入预算；取消后收束资源与账本。判分依赖不足时，可对完整保留产物做离线恢复并记录环境修正。

历史配对出现过一个参与者向另一个参与者的进程发送信号，污染比较。隔离需要真实 worker 中的行为探针；串行执行还应记录同机其他负载。针对一个进程能力的隔离证明，其覆盖范围仅限该能力。

大轨迹采用流式写入、逐 turn 身份和内容摘要。恢复 gzip 进度时区分未完成尾部与完整记录损坏。统计按条目读取并保留摘要，核对修改前后结果一致；V8 old-space 限制和进程 RSS 分别报告。

归档先校验完整性、来源身份和可恢复性，再回收已结束的工作副本。完整复制实验目录可能把输入轨迹再次复制进评分目录，容量准入应按实际需要的产物集合计算。实现入口见 [长任务运行器](../../scripts/agent/long-tasks/README.md) 和 [轨迹制品](../../scripts/agent/harbor/TRACE-ARTIFACTS.md)。

## 每次实验最小记录

- 身份：任务与来源 SHA、依赖锁、候选与评分器摘要、模型及推理设置、宿主工具版本和实际 PATH。
- 控制：成功条件、预算、执行顺序、对照范围、开发或独立验证身份、同机干扰。
- 结果：实际终态、冻结评分、最终 diff 和产物摘要、原测试与新增测试的执行覆盖、逐项交付声明。
- 计量：每次物理请求与重试、完整用量覆盖、参考费率、未知费用、分层耗时及完整总账。
- 恢复：失败原件、重新判分原因、资源归属、归档校验及回收状态。

这些事实应随实验保存为可独立读取的记录。阶段经验进入仓库后，后续工程工作仍以当时的源码与新证据更新结论。
