# 发布事实、注册与审批身份的继续清理

本批四项分别独立提交。公开模型操作签名、效果、模式、限值与生成面均未改；Archive 的重复运行身份行为按既有不可变证据承诺落实，并先核对消费约束。main、版本与发行不变。

## B1：网页模型请求与撤销错误共同保留

ExternalModelDriver 的 finally 原来直接等待宿主撤销；发送、协议或取消先失败而撤销再失败时，后错会覆盖主错。现在撤销由同实例私有方法归集：单错仍是原对象，两错通过 AppError.errors 按主错、撤销错顺序保留。pending、timer 与 listener 仍在撤销之前释放，提前 return 仍执行撤销；成功 finish 后的撤销失败继续如实报告。

五个定向场景包含四条新增回归（发送双错、协议双错、单错原对象与 finish 后清理、消费者 return）和既有超时/迟到拒绝。既有 INV-1/2 的租约及完整回复承诺保持，无新增错误码。

## L1：探测器与看门狗设置整批发布

DetectorRegistry.registerBuiltins 原来先替换 settings，再逐项 register；重复注册失败仍能改变看门狗阈值，或把冲突之前的探测器部分登记。现在本地构造候选，先完整核对所有 ID，再同步发布注册表与 settings。失败保留原探测器对象、阈值和工具名单，未增加另一份设置权威。

两条回归分别证明已注册内置的失败重注册不改变实际 watchdog 判定，以及后位自定义 ID 冲突不发布前半内置。类 API 和已有看门狗同源承诺保持。

## L2：运行归档只首次发布

LabArchives.writeRunArchive 原来的 rename 可以覆盖相同 runId 的证据，违背 README 的不可变归档承诺。内部 CLI 使用独立运行 ID，既有测试的不同试验也没有依赖同 ID 覆写；协调同时只读核对九个当前产品仓，未发现相应代码消费，不以此推断未知外部用户。

仅此发布路径使用同目录独占临时文件：完整写入并关闭，再用 hard link 原子首次发布；已有目标只在本次序列化 UTF-8 字节完全相同时幂等返回，不同内容明确报错、保留原件，不忽略时间或扩展字段。其它 I/O 错误仍原样报告；主错和临时句柄/文件清理错共同保留。成功发布后的收尾失败不删除已发布目标。不支持 hard link 的文件系统沿实际 I/O 失败返回，不回退覆盖。

类上方 API、README 与 INV-3 明确同 ID 的精确幂等/冲突条件。这是撤回错误覆盖行为、落实既有不可变承诺；不迁移、规范化或修复旧档。普通报告与真实任务三件套仍沿原覆盖写法。四条回归覆盖相同/差异内容、非规范但已存在的原字节、并发不同内容仅一赢家，以及普通报告仍可更新。

## S2：确认与执行同一条沙箱命令

SandboxOperations.run 原来在 awaitConfirmation 后再读原 command/timeoutMs。现在在等待前固定已校验的 id、command 和规范化时限，规则、确认、执行及返回值复用同一事实；省略时限及原有钳制保持。确认 barrier 回归同时覆盖默认和超限钳制两种时限，期间改写原输入仍不能改获准执行。

INV-7 的危险命令先确认、拒绝不起进程承诺保持。新增测试不执行真实命令；既有通过完整程序链的确认用例按当前平台的原条件跳过，没有为本批扩跨 OS 矩阵。
