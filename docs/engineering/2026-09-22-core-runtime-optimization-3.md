# 核心运行时第三批优化差量

## 实现与合同

| 修改 | 原因与行为 |
| --- | --- |
| ContextStorage.selectSnapshot | 可选读取端口，在同一读事务中返回元数据和指定记录。避免分别读取任务边界、租约和引用时混合版本。 |
| ContextRecordSelection / ContextRecordSnapshot | 根入口与 contracts 导出可移植类型。选择字段为精确标题、字面标题前缀、引用身份、记录类型及 latest；字段取交集，多选择取并集，按身份去重、按序号升序。空选择只读元数据，不存在的会话返回 null。结果中的 records 是部分目录，与 metadata 分离，不能作为完整 CAS 的替换目录。 |
| LocalContextStorage | 使用一个读事务固定元数据和所有选择的版本；精确标题、身份与类型走索引，标题前缀按字面比较。首次打开旧库增加 kind 表达式索引，已有数据和身份保持。 |
| ProgramContext | 状态、版本和控制回执按指定记录读取。发布一次提交中的源码、版本、控制占位和租约时使用增量 CAS；来源验证、任务边界、控制身份冲突与失败回滚保持原语义。 |
| ContextMemory | 笔记目录、笔记读取和更新选择笔记及重置记录；有来源的更新另选来源和用户重新附加的证据，并要求两个快照版本一致。提交前版本变化由 CAS 拒绝并重试。帧确认选择目标帧和最近交付记录，并检查取消。 |
| RuntimeDiagnostics | 透传并采样 selectSnapshot；缺少可选方法时保持原适配器能力。 |

程序和笔记增量写入要求 selectSnapshot 与 compareAndSwapMetadata 同时存在。只有读取扩展的适配器仍采用完整 CAS，原有适配器仍可用。完整回退路径按最后一个实际 sequence 追加，允许目录序号存在间隔。

Context INV-7 / INV-12、Runtime INV-6 / INV-19 扩展到上述一致快照和增量提交验收。脚本提交的三个故障注入用例改为拦截实际增量事务，继续验证丢失提交确认、在途重复调用和竞争占位后的核对行为。模型操作、schema、发现内容与使用模板保持现有合同。

## 可复现基准

```sh
bun run --cwd packages/context build
bun run --cwd packages/velaros build
node scripts/agent/benchmark-context-queries.mjs
```

独占临时目录中的 SQLite，WAL / FULL 持久性。完整与索引路径使用相同数据和业务方法，完整路径仅省略选择快照扩展；每项 20 次采样，完成后核对记录数、程序状态和笔记 revision 并清理目录。2026-09-22 本机 Node v24.15.0 / macOS arm64、10,000 条背景历史的一次结果：

| 操作 | 完整路径 p50 ms | 索引路径 p50 ms | 完整路径 p95 ms | 索引路径 p95 ms |
| --- | ---: | ---: | ---: | ---: |
| 程序状态读取 | 6.099 | 0.016 | 9.736 | 0.021 |
| 程序状态更新 | 16.369 | 0.132 | 26.591 | 0.166 |
| 程序版本读取 | 6.255 | 0.020 | 6.603 | 0.039 |
| 笔记目录 | 6.697 | 0.022 | 10.635 | 0.027 |
| 笔记更新 | 15.478 | 0.169 | 23.350 | 0.192 |

这是固定负载微基准，背景历史多、笔记和用户记录少；不代表整轮任务或大量笔记版本下的加速比例。标题前缀查询仍会扫描匹配候选，笔记整理仍读取每个键的最新正文；同步 SQLite 和首次索引建立仍占用调用线程。

## 下一批分析

1. **每轮上下文投影。** ProgramContext.project、ContextMemory.project 和 RecentContext.project 仍分别 load 完整目录。后续可先建立投影阶段共享的一致读取上下文，再逐步选择所需记录；脚本/笔记/历史阶段会追加新帧，不能简单缓存最早快照贯穿所有步骤。
2. **历史结果正文扫描。** RecentContext.project 为排除观察结果，会读取所有候选结果正文后再取尾部。应先测量这一阶段，再考虑记录分类索引或具有一致版本边界的倒序查询。不能丢失 omittedRecords、恢复范围和历史重置语义。
3. **笔记版本目录。** 本批避免读取无关记录，titlePrefix 仍返回所有笔记版本；高频修改同一笔记时，需要“按标题取最新”与旧版本授权查询分别建模。来源授权还会查询用户记录，长对话需测量其增长。
4. **混合材料目录。** catalog、readMaterial 和 retainMaterial 当前保留完整快照路径，以维持历史重置、用户重新附加来源及类型筛选。下一步把授权候选和分页边界显式下推，验收跨页版本变化。
5. **评测增量归档与真实模型基线。** 周期快照仍完整读取累计回合；先定义迟到回执和子任务终态的稳定边界，再分离增量事件归档与最终报告。真实模型矩阵仍需要固定配置、源码身份和重复样本。
