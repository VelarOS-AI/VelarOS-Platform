# Desktop 工作笔记与计划模式接入差量

日期：2026-09-22。

## 结果与归属

Desktop 的工作笔记目录、正文查看、归档与恢复直接操作当前 Platform 工作笔记。模型和宿主共用稳定 key、revision、来源与不可变记录；正文、并发校验和上下文投影继续归 ContextMemory，Desktop 只持有 IPC、交互及运行期互斥。

计划模式采用“先列计划，再继续执行”。Desktop 将模式写入可信主会话指令，要求模型通过现有 memory.list/update 保存并维护 `plan` 笔记，记录目标、验收条件、步骤状态、进展和阻碍。目录查找遵循分页和 revision；更新保留现有驻留状态，恢复已归档笔记需要用户明确要求。计划完成与回复结束分别判断。

## 公开合同差量

- `VelarosSession` 增加 `listNotes`、`readNote`、`setNoteResident`，分别提供笔记目录、确定版本的正文页和版本化驻留修改。它们共用 ContextMemory；会话关闭先中止并等待在途笔记请求，关闭后拒绝新请求。
- 根入口与 contracts 入口导出 `WorkspaceEntry`、`RuntimeNoteRead`、`RuntimeNoteRetention`、`RuntimeNoteContent`。正文页有字符上限，内部归档封装不作为产品正文泄漏。
- `ContextMemoryApi` 增加内部 `readNote` 正文投影。现有模型操作、模板与注入合同保持原义；模型和宿主不会各保存一份计划。
- 新增 INV-47。已有验收承诺未修改。

## Desktop 差量

- 新增三个有类型的私有 IPC 请求与笔记变更事件，登记来源校验和有界参数 schema。写请求必须带当前 baseRevision；旧版本返回冲突。
- 空闲时使用无模型、无业务能力的 Runtime 读取或变更笔记，并核验原工作区绑定；尚无状态目录的会话列举为空。
- 每个会话的笔记操作串行；发送时避免与笔记控制重叠，活动运行期间明确提示等待收尾。关闭和删除等待笔记连接释放。
- 运行结束与归档/恢复成功后广播变更，已经打开的笔记面板刷新。界面按会话及请求代次丢弃旧响应，支持正文和目录分页。
- `WorkspaceNotebook` 展示“当前使用 / 已归档”。旧长期指令以只读资料保留；原会话数据不迁移或重写。面板、样式及模式相关名称按现有职责整理，清理无调用的文案与样式。

## 语义边界

归档笔记只改变后续请求工作区的驻留，不删除原文、撤销既有世界效果或从已发送历史中抹去内容；模型仍能通过正式记忆接口召回。恢复使用同一 key 和新的 revision，正文保持。

目标的结构化生命周期见 [目标接入差量](desktop-goal-lifecycle.md)。工作笔记、目标生命周期和整段历史上下文分别使用各自控制面；Desktop 通用 contextGovernance 门保持反映当前接入情况。

- 两仓库模块归属检查、Desktop 21 个受影响类型分区、IPC 构建和生产入口构建通过。
