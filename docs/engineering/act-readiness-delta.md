## 正式入口和生命周期

- `createRuntime` 统一为异步入口。`workspace` 复用 Project 内核和证据来源，`dataDir` 复用 Context SQLite 与长期记忆，`model` 可接既有驱动或声明式 Provider 配置。脚本仍由既有 subprocess runner 执行；请求继续经 ProviderRequestCompiler。
- workspace 与 dataDir 组合默认持久保存项目事务状态，按真实工作区身份分目录；项目内核先恢复中断事务，再装配能力。仅注入 storage 时，项目事务的跨进程持久路径仍由专用宿主负责。
- 状态目录要求位于业务工作区之外；核验真实路径，覆盖符号链接和以 `..` 开头的目录名。构造失败只释放框架自行创建的存储；成功后 Runtime 拥有连接关闭职责。
- 关闭会话撤回缓存、作用域、模型和 store 句柄；同 ID 重开恢复持久材料。并发关闭共享同一收尾 Promise，初始化失败可重试。
- 主要对外合同：VelarosRuntimeOptions 增加 workspace/dataDir 和声明式模型配置；依赖端口可按需注入；运行预算支持部分覆盖。RuntimeModelConfiguration 复用模型包的 Provider/思考力度合同。AgentProfile 增加 description，运行预算支持部分覆盖，缺省输出使用实际驱动的额度。
- Velaros 版本为 0.6.0；模型模块装配合同为 16。宿主实例统一通过包根 createRuntime 创建，系统模块端口从 `/act/system` 引用。

## 模型使用合同

- `agents.profiles()`：返回实际配置名、用途、模块、共享权限与预算。start/resume 的 profile 可以从该目录直接选择。
- `search.profiles()`：返回真实档位、默认项和全部预算。search 继续是一次性 execute 操作，read 是不调用模型的快照或刷新操作。
- `search.read`：snapshot 返回有界 text/offset/totalChars；current 返回分页 items，每项以 ok 明确区分真实内容与错误。声明、运行时校验和模板使用同一合同。
- runtime/utils/model-instructions.ts 根据实际可用能力生成工作说明，解释脚本生命期、五分区、原文引用、笔记、共享状态、消息确认、支线与完成语义。受限作用域只收到实际可用成员的说明。
- Act 目录按真实投影生成，用法表去重；模板继续由 modules.describe 返回。公开文档同步异步入口与 system.memory/store 的使用方式。

## 追踪和后台验收

- `runtime.trace(rootSessionId, {sessionId?, after?, limit?, maxChars?})` 从同一持久存储读取原始请求、响应、协议判定、脚本与 Kernel 回执。可读取已关闭支线；跨根归属会被拒绝。正文分页有明确截断，活动回合需要重读以取得后续回执。
- 原有 session.trace 继续支持精确回合读取；终态切分补齐 needs_reconcile。
- 现有 Agent Lab 评测改用正式工作区入口，并持续保存 events.ndjson、主线 traces.json 和 branches.json。
- 工作负载包括 read-edit-observe、system-cooperation、semantic-search、reconciliation。各自核对磁盘、持久状态、消息确认、证据及真实行为，模型宣布完成不能替代验收。
- 评测配置接通模型包现有 reasoningLevel。凭据只从指定环境变量读取；配置和身份归档保留非敏感参数。

- Agent 6.1.0 的公开合同基线纳入可选 store 授权、父任务身份、交付反馈，以及等价的 Optional 类型引用；没有移除公开成员。Velaros 的项目版本常量与 0.6.0 包版本一致；Context 包补齐公开元数据和使用说明。
- 打包消费者使用唯一 createRuntime / ActRunService / Kernel ApprovalPort，实际验证独立安装、浏览器导入、隔离脚本、取消、关闭后重开和长期记忆。业务能力测试使用现行 Script surface 与能力端口。
- 原 agent-portable-core-error-parity 测试针对已不存在的复制错误类型；当前公开类型和环境边界由 Agent public API、browser、打包消费者门共同验证。没有保留一份运行时错误实现供测试对比。
- shell 模板的后台启动返回当前快照；后续 execute 调 taskOutput 获取进度，示例不调用脚本环境未提供的计时器。模板验收保留真实日志及停止断言，改由测试宿主等待后再执行读取脚本。Shell 回执的可选字段保留键缺席语义。
- ProjectCapabilityPorts.shell 转接宿主的 runObservationCommand，沿用项目资源门、真实路径边界、取消信号和原始回执；没有受限宿主时不装配该入口。新增转接和越界回归测试。
- 语言门修正集中在空值合同、类型守卫、条件字段装配、错误处理与 TimerScope。严格 JSON 数据在字段存在时才写入；观察/回执解码的键存在语义保持不变。输出采集器的纯数据守卫同实现注入 QuickJS 闭包，宿主对象不进入模型脚本。
- Kernel 架构扫描器只合并真实 import/re-export 语句，避免把 export interface 的正文误当成跨层依赖。

## 真实调用发现与修正

- 使用指定端点、gpt-5.5 和 high 思考力度。初次运行的协议拒绝保留原文，未执行文件操作；另一次流发生连接中断，按失败归档。
- Provider 的分段文本此前在 AiSdkModelDriver 中被直接拼接。Responses 可将说明和正式答复放入不同文本消息，前段末尾没有换行时，下一段控制标记就被粘到说明文字上。适配器现在保留文本消息边界；同一文本段内仍逐字传输，JSON 输出路径继续使用 SDK 结构化输出。
- 新增两项真实 AI SDK mock 流回归，把两个独立文本消息送入 ScriptTurnDecoder，分别覆盖前段有/无换行，均能还原正确执行块。驱动调试日志记录文本分段身份，帮助核对真实端点行为。
- 模型说明补齐完整控制块示例与 output.priority 的合法取值。脚本执行仍要求响应完整、闭合、校验成功；示例不放宽接收门。
- 后台工作负载自行处理的输入请求在回答落盘期间保持 running，避免评测轮询把瞬时 pending 错当成等待外部用户而提前结束。

- 后续真实任务发现模块合同整体包含 schema、声明和模板，模型应按需读取 `template` / `declarations`。modules.describe 的返回 schema 补齐这些真实字段类型，modules.list/search 接受省略参数；自管理合同代际为 20。模板与常驻说明提供直接输出用法正文的路径。
- output 采用明确的 JSON 归档语义：对象省略 undefined 可选字段，数组空位与 undefined 保留为 null；真实模块的可选字段可直接输出。循环引用、getter、非有限数和其他不支持的值仍拒绝，并指出对应 JSON Pointer。隔离执行回归覆盖可选字段与稀疏数组。
- 后台常规验收沿用正式 Runtime 的上下文额度，再由实际模型输入容量编译；小容量与容量恢复继续由独立确定性测试覆盖。之前固定 48,000 字符的评测覆盖值导致多份合同争抢每结果展示份额，不代表正式入口的默认配置。

- 首次完成真实文件修改与后一轮观察后，模型只给出了完成说明，Runtime 按协议进入等待。完成说明明确展示带当前帧标记的 `done` 行，完成判定继续要求显式声明和实际校验。

- 真实服务出现 ECONNRESET：ModelTurnDelta.error 增加可选 retryAfterMs，驱动复用 ModelProviderRetry 判别瞬时故障，原生 Error/cause 现在参与分类。Agent Loop 对尚未接受的响应最多按既有恢复额度重试，退避服从取消和总期限，每次重新预留预算并归档；已接受脚本及未知效果不会重跑。新增恢复、耗尽、取消与原生错误分类验收。

- 整理材料 list/read 的返回 schema 改为真实 ContextRecord 目录和 ContextContent 正文；补齐模板编译验收。整理指令按“先读原文、下一轮输出最小补丁”说明，明确输入摘要版本、历史边界和引用所属会话。System schema 20。
- 子任务用法明确 store.write 须为同项 read 的子范围，保证子任务能够读取版本再写入；失败派发身份及错误保持可读取，续跑可替换授权。

- 搜索档位发现与调用的档位类型从同一次宿主配置派生。`profiles()[i].name` 可直接传给 `search({profile})`；模板实际演示这个流程，避免模型需要硬编码档位或强制转换类型。

- 搜索和整理的专项工作说明直接列出其两个核心读取操作的实际返回结构；搜索明确字面查询、候选 ID 与已读证据 ID，整理明确正文 `text` 和分页目录。两者都要求分批选择必要正文，减少因返回字段猜测和整批材料展示造成的反复调用。

- 输出说明明确 `full` 的完整性语义：超出展示上限时返回引用；`auto` 可以按预算摘录。指导模型在脚本内先选字段和聚合，再选择租约保存必要材料。真实轨迹里把大对象反复指定为 `full,maxChars` 会看不到正文，不能用提高全局预算掩盖这一使用错误。

- 后台协作判据按已投递消息的唯一 ID 汇总，并核对持久 ack 回执；确认后再次读取空队列仍可通过。持续任务允许有凭据的纠错更新和额外确认，仍严格核对四阶段数据、同一子任务、输入版本和最终文件；整理必须有 applied 回执，启动过整理支线不代表成功。

- 后台归档逐个回合读取主线和支线，每回合使用明确的 8 MB 正文上限，避免多回合共用分页预算截断后面的证据。summary 分别报告主线及包含所有支线的总调用次数与用量；任一调用缺少用量时累计 token 保持未知。

- 搜索 Runtime 增加有界已读证据目录：真实 ID、版本、原文引用与短摘录进入 runtime 分区，并随真实请求归档和计入预算。执行结果租约或展示压缩不再隐去全部证据身份；版本失效在下一帧前移除，容量省略和摘录截断明确显示。目录是来源数据，不进入系统指令。
- 持续核对验收以实际唯一共享空间及其 ID、授权、子任务作者和四阶段结果判断；该工作负载没有依赖空间的展示名称，避免把合理命名差异判成协作失效。协作工作负载明确要求名为 handoff，仍核对该名称。

- 模型说明直接解释“数据在脚本中处理、output 只提供必要思考材料”：先检查源返回的分页/缺口，再计算和聚合，展示被引用化不表示真实读取失败。持续任务允许对同一子任务纠错续跑，仍要求全部实际版本和阶段结果成立。

- 正式 Runtime 的工作响应必须给出控制决策。无在途任务时，纯说明/“继续”走现有有界协议修复；需要用户回答走 interaction，完成走 done。在途后台任务仍可用纯进度消息等待。纯 Markdown 的解析与展示保持原样，通用 Agent 接收器不承担该 ScriptAct 策略。
- 相应调整原“无 done 的普通文字直接 waiting”验收：它会把未执行的进度宣告与用户交互混淆，真实任务因此提前停住。现在验证修复耗尽不执行，以及修复成功后只执行一次；已有后台等待与交互测试继续约束正常暂停行为。
- 协议说明明确由宿主消费文本程序段、真实执行脚本并返回回执，模型原生工具列表为空仍可通过当前授权的 JS 模块工作。

- 搜索查询额度耗尽时仍可读取已经找到的候选，直到读取额度、时间或模型额度要求收尾。Runtime 目录明确区分未读候选与已读证据，候选不能用作报告证据；容量上限同时覆盖两部分。新增仅一次查询、随后读取、最后报告的验收。

- 真实轨迹中出现把数组标成 code、把对象标成 text 的输出错误。采集器诊断现在给出声明类型、实际类型和修正方向，宿主与隔离堆共用实现；不会自动改变输出语义。新增两端一致的拒绝测试。模型说明明确执行语言为 JavaScript，并提示枚举字面量参数的写法。

- 项目证据源的候选范围统一为 EvidenceAccess 和 evidence.query 已声明的 1–100；原内部 32 上限会拒绝合法调用。真实项目测试核对 64/100 上限和越界拒绝。
- 单一职责模型工具可带缺口完成只读报告，避免早期必需展示项被引用化后挡住有效交付。真实证据 ID、发布版本、上下文补丁 CAS 和未决效果仍分别校验；主线及业务子任务继续要求必需正文完整。新增“旧必需项不能展示，但真实证据报告可部分交付”的最后一轮验收。

- 真实子任务完成后仍被已更新对象的旧读版本阻塞。决策依据现在按持久执行结果顺序采用可见的最新真实读取/写回版本，并在 superseded 中明确记录被替代的版本；当前 observe 仍最后覆盖。模型展示排序、自由文本、笔记或未展示正文不能推进版本。Kernel 在写入/完成前照常验证真实当前版本。新增无 observe 的读改完成、执行重读恢复，以及随后发生外部竞争仍拒绝完成的验收。

- 模型工具普通请求的预估额度若将侵占最后一轮预留，控制器先进入 token-budget 收尾阶段，并通过现有 CONTEXT_BUDGET 恢复路径重新编译交付请求；该次预检不计为真实派发、不消耗最后一次调用。此前直接返回硬上限会在仍有预留时提前终止。新增真实 Runtime 中工作调用、预算重编译、最终证据报告的两次派发验收。

- 整理期间并行子任务可能改变父材料。固定快照读取首次发现 CONTEXT_CONFLICT 后即停止后续读取，并在下一请求准备阶段终止该整理活动；保留原始冲突码，主循环沿既有 STALE_VIEW 路径重新编译当前帧。避免对已经失效的同一快照重复调用模型。新增并行父材料变化后只调用一次整理模型、主线仍继续且未发布旧补丁的验收。

- 组合验收任务明确完整数据在脚本中计算，以及整理成功以 applied 回执为准；子结果不匹配时续跑同一 worker 纠正。持续核对把必要的整理放在子任务收束后的阶段边界。独立文件、版本、作者、订阅、确认、四阶段数值与原始输入判据均保持。

- 整理模型提交 `output(patch)` 时，复用完整候选编译和操作校验执行预检；预检只暂存元数据，父会话不发布变更。错误作为同一支线的脚本反馈，允许沿现有两次修复额度纠正；连续三份无效补丁结束该活动。正式完成仍重新验证快照、编译父请求并 CAS 发布。补齐 recentRecords 的整数说明；新增预检不发布及同支线纠错验收，原超大候选不得发送给 Provider 的有界验收保持。

- 真实整理支线因自身早期 required 预览退出展示，反复尝试交付而停滞。只读模型工具现在可在普通工作轮主动交付带缺口成果，交付仍通过搜索证据或整理补丁的专用校验；主线/业务子任务的必需上下文门，以及所有世界写入前提保持。新增旧预览缺席时两次调用完成有效补丁的回归。

- 主模型说明明确区分 required 缺口的修复位置：observe 调整持续代码；execute 的旧结果通过其真实 ref 主动 release 后重新输出必要小值。同名 key 属于各自执行结果，重新输出或召回原文不隐式解除旧项。该说明来自真实任务反复修复错误位置的记录，存储和写入保护语义保持。
