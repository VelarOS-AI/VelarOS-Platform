# ScriptAct 优化实现与收益证据

2026 年 10 月 1 日。当前视图、领域模板、核查报告、原子自动收尾和可信观察复用均已实现。机制回归证明了少采集、保留完整请求范围和避免过早完成；第一份组合候选的三项独立小任务更快，最终候选的新独立任务则更慢、更贵。当前证据支持机制收益与正确性改进，尚不能证明稳定的整体性能提升。

设计依据见 [Platform 运行主链](../architecture/platform-runtime.md) 和 [ADR 0026](../decisions/0026-scriptact-current-state-and-verification.md)。

## 实际落地结构

```text
宿主核查过的观察覆盖 → 实际采集 / 复用已有成功结果
                               ↓
当前状态完整呈现 + 冻结原文历史 + 首次或变化正文
                               ↓
模型使用现有操作与领域模板执行、核对真实结果
                               ↓
领域核查实际范围 → 任务、目标、成功报告同次 CAS 发布
```

当前视图让模型直接判断约束、待核对输入、失败、作业和材料缺口。原文、源码、完整诊断与笔记继续按身份和版本在历史中承载；当前状态与正文交付分别管理。

## 合同与行为差量

| 归属 | 改动 | 理由和影响 |
| --- | --- | --- |
| Runtime / ContextMemory | 每帧列全当前分区与有序列表；驻留笔记身份目录独立于段内改动卡片，超限明确 omitted 与召回入口 | 减少跨帧状态重建；重复小型元数据仍计入窗口与成本。冻结原文、required 覆盖证明、租约、图片和缓存前缀保持既有验收 |
| Context | 可选 ContextVerificationReport，包含范围、时间、passed/failed/unknown、证据引用及产物身份/版本/哈希；32 项、24,000 字符上限由常量和校验统一 | 报告只证明实际检查范围；既有 verified/reason 核查器继续可用 |
| Context | 任务 completionRef、不可变 ContextCompletionRecord 与 readCompletion(ref?) | 失败与成功报告都可回看；报告绑定原 task 和宿主对象。当前自动投影遵守授权重置水位 |
| Context / Runtime | 中立 ContextCompletionCommitPort；自动 done 先核查，再同次 CAS 发布 task、goal 和成功报告 | 领域语义留在 Runtime；并发替换、取消和 CAS 竞争不会让旧成功证明归属新目标。竞争仅重试 prepare，不重复领域核查 |
| Agent / renderer | verification 事件可带 report，成功报告持续到终态并支持重放；恢复提示只带 reportAvailable | 原始报告由事件与审计保留；当前摘要按帧预算展示，大失败报告不会挤掉修复窗口 |
| Runtime 宿主 | context.observation 可接 reuse、scope、probeTimeoutMs、maxAgeMs；刷新控制 refresh:true 随观察发布原子接受 | 完整覆盖与可靠版本由宿主保证。源码、输入、任务、授权、模块代际、scope、provider 生命周期及 token 均匹配时复用完整成功结果 |
| 观察恢复 | unknown、失败、超时、过期、重启、附件缺失或 refresh 回到采集；迟到探测收束前不累积新探测 | 未配置复用时仍每轮采集；复用不改变原 observedAt、resultRef、executionId，也不把旧调用算成新调用 |
| Project / Files | 读取缺口保留整个请求范围，模板先停止依赖写入；批量成功和领域事务/部分提交按原合同执行 | 防止把缺失文件静默排除后写入子集；现存文件保持原字节 |
| Shell | 模板保留退出、信号、超时、取消、截断、后台和 confinement；顺序阶段失败即停 | 不能把取消或失败解释成空结果，也不能只保留 error 关键词 |
| Office | 生成报告/表格后解析实际产物，保留检查结构与裁剪范围 | 增加一次真实检查；解析范围与版式、业务正确性分别说明 |
| Search | 展示保留 partial、coverage、gaps、ref、stamp、complete、分页范围与未读候选 | 减少中间材料，同时让不完整证据保持可识别 |

本次没有增加领域模型操作。AgentView 与模板的模型面由生成器统一重算；Agent 的可选事件字段增量已审阅，版本从实施基线 9.2.0 调整为 9.3.0，公开 API 基线与 lockfile 同步。报告和观察类型经现有公开入口导出。

README、invariants、生成声明、Act catalog 与相应验收已同步。Runtime INV-74 更新当前视图承诺，新增 INV-77/78；Context INV-15、Runtime 原 INV-44/48 及各领域模板承诺覆盖新增行为。

## 机制收益

### 可信观察复用

相同六轮决策、真实 Runtime 与 Node runner：

| 指标 | 每轮采集 | 可信版本复用 |
| --- | ---: | ---: |
| 真实观察采集 | 6 | 1 |
| 本地总耗时 | 696.91 ms | 385.63 ms |
| 观察脚本耗时 | 390.46 ms | 81.20 ms |
| 联合探测耗时 | 0 | 1.295 ms |

实际采集减少 83.3%，本地固定决策总耗时减少 44.7%。原结果身份和采集时间跨复用保留；追踪中的观察调用为 `[1,0,0,0,0,0]`。这是机制证据，不能转述成真实模型整题提速 44.7%。unknown、超时、ABA、权限与程序变化、暂停、refresh、年龄、图片恢复和整个 Runtime 重启均有正反例。

### 完成与领域模板

相同模型决策、领域核查第一次失败、第二次成功时，冻结旧版在两次核查中看到 goal 都已经 complete；新版两次均仍为 active，核查成功后才原子完成。真实 Runtime 对照保存在 completion/comparison.json。并发替换、取消、报告重放、授权重置和 21,118 字符大失败报告的小窗口恢复均有独立回归。

七个开发回归任务、旧新共十四次真实隔离执行，10/10 机制检查通过：

| 场景 | 冻结模板 | 新模板 |
| --- | --- | --- |
| Project 搜索后目标文件消失 | 继续写入可读子集 | 0 次写入，保留完整范围与缺口 |
| Files 一个目标不存在 | 提交另一个文件 | 0 次 commit |
| Files 两文件成功 | 2 次操作、1 次 commit | 同样 2 次操作、1 次 commit |
| Shell 取消且 exitCode=1 | 报没有 TODO | 保留失败、取消、信号、退出与诊断 |
| Office 生成文档 | 只给路径，1 次操作 | 解析实际文档，2 次操作 |
| Search 部分结果 | 展示 11,732 个 JSON 字符 | 展示 719 个字符，保留范围、缺口与来源 |

成功批量路径的调用数没有下降；Office 增加了必要检查。搜索字符量变化属于固定 fixture 的展示指标，不能等同于 token 或通用费用收益。

当前视图的真实 Runtime 回归覆盖底座驻留身份、列表与约束变化、失效、封段、重启、原文分页和 required 正反例。引用展示与原文交付分别标记；只有当前和先前帧实际包含原文才声明正文此前已交付，首次附上正文会重新交付。这组回归证明最新状态可以独立读取、原文证明没有被摘要或引用替代；单靠回归不能证明模型状态判断准确率提高。

## 独立模型任务结果

三项任务的精确产物、保护文件和后续真实观察均通过，旧新各 3/3。质量与完整核查结果相同。

| 独立任务 | 旧版耗时 | 新版耗时 | 耗时变化 | 模型请求（旧→新） | 完整参考费用（旧→新） |
| --- | ---: | ---: | ---: | ---: | --- |
| 分区订单台账 | 143.29 s | 64.86 s | -54.7% | 5→5 | 旧版 1 次请求未知；新版 USD 0.186702 |
| 嵌套配置修改 | 55.75 s | 51.35 s | -7.9% | 6→5 | USD 0.270295→USD 0.190426，-29.5% |
| 跨文件日志统计 | 122.94 s | 65.77 s | -46.5% | 9→5 | USD 0.680746→USD 0.265986，-60.9% |

这三个配对样本中，新版均更快；逐题耗时比例的中位数为 0.535，约减少 46.5%。原始耗时中位数为 122.94s→64.86s。总请求为 20→15。

费用完整的两题合计 USD 0.951042→USD 0.456413，减少约 52.0%；三题整体费用仍不完整。台账旧版的中断请求保留未知用量，不能用已知费用部分计算整体降幅。

本批未配置观察复用。因此模型任务结果支持组合候选的初步收益，不能拆分成当前视图、模板、核查报告各自的因果贡献，也不能推广为大任务集上整体领先。真实业务质量仍需更大冻结独立集、多次重复和单机制消融。

### 最终候选的新独立任务

最终一般呈现修复后，冻结一项新的 TSV 会议时间区间任务，包含重复、重叠、相邻与取消预约。预期结果由外部独立验收生成，产品和模型工作区都不包含该答案。两版各只运行一次，随后直接按结果收束，保留退化。

| 指标 | 实施前基线 | 最终候选 | 变化 |
| --- | ---: | ---: | ---: |
| 精确 JSON、输入保护、接受后真实 observe 核验 | 1/1 通过 | 1/1 通过 | 同质量 |
| 总耗时 | 73.96 s | 135.02 s | 增加 82.6% |
| 模型请求 | 5 | 8 | 增加 3 次 |
| 完整参考费用 | USD 0.268578 | USD 0.751532 | 增加 179.8% |

两次账本均已 settled，未知用量为 0；费用仍是参考计量，不是实际扣费。未启用观察复用，固定旧版先、新版后的顺序也可能受供应商时延和缓存影响。原始产物、最终完整 traces、用量与冻结核对保存在 final-validation/comparison.json 和各自 runs 目录。

完整 trace 显示两版所有响应均被接受，协议修复为 0。候选将多份大合同与模板标成 required，探索可用操作，并多轮补齐合同正文；基线一次合同读取后进入业务执行。这是本次额外往返的直接轨迹，尚不能判定哪项优化导致模型采用这种策略。

因此前三题的提速不能用来宣称最终候选普遍更快。最后一题显示额外模型往返的成本足以超过局部呈现节省；多次独立重复与消融后才能判断各项改动的因果贡献。两份候选版本与任务集分别报告，不合成一个整体成功率或平均收益。

- 全仓构建、typecheck、格式检查、模块所有权、模型面生成一致性、Act catalog、公开 Agent API、README 示例、错误构造与 lockfile 检查均通过。
- Runtime 全量 Node 回归 562/562；其后相关回归 120/120，最终呈现修复的完整 ContextMemory 回归 96/96。各组有重叠，不相加。
- Context Node 回归 78 通过、4 个可选存储能力跳过；相关 Agent/领域 Bun 回归 165/165。Search 验收 6/6。
- 新增源码 scoped ESLint 通过。全仓 lint 仍有四个实施前问题：旧评测目录的三个 AppleDouble 二进制文件被扫描，以及 script 的既有测试导入排序。
- code-style 基线 37 项，最终 36 项；规范化诊断差量为 0 个新增。原 WIP 的风格债保留，未通过改写门禁或豁免隐藏。
- git diff --check 通过。当前共享工作树包含实施前 WIP，本次变更保持在各自职责范围。

默认观察仍按轮采集。复用依赖宿主真实兑现完整覆盖、权限代次与 ABA 保证；接口本身无法证明任意观察程序的外部依赖。核查报告与 Office 解析只证明实际范围，未配置领域核查器的交付仍明确 unverified。

## 下一代优化方向

1. **优先降低模型往返、能力发现与重复程序生成成本。** 前三项新版任务需要 5 个模型请求，最后的新任务增加到 8 次，额外代价集中在大合同发现与正文补齐。优先让声明与模板按生成版本、指定导出和依赖类型直接取得并复用，测量发现轮次与合同交付量。对跨任务反复出现、带明确失败语义的组合，提供可参数化、可按版本复用的程序入口；据生成量和恢复次数决定哪些组合值得形成领域高阶操作。临时业务判断继续由模型组织。
2. **把当前视图做成有来源、有优先级的状态编译。** 当前状态应继续独立可读；下一步按真实决策需求裁剪重复目录与运行元数据，保留障碍、未知效果、约束和 required 缺口。用真实状态误读与重复读取定位瓶颈，并分别消融视图和模板的贡献。
3. **建立领域核查过的观察目录。** 先在可提供可靠版本的资源上积累命中率、失效正确性、探测成本和实际节省，随后接入事件快照与阶段退役。覆盖未知时维持采集；观察目录与领域所有权一致。
4. **把完成证明绑定到产物和业务验收范围。** 现有报告先解决“何时完成、实际检查了什么”。下一代将复用已有有效检查、标明产物变更后的历史性，并支持领域业务标准；每项检查的时间和费用进入同一任务账。
5. **补齐终端计量，再扩大独立样本与消融。** 旧版台账的一次请求仍缺失用量，当前参考费用也不是实际账单。完善完成、取消与收流结束的用量收束及 Provider 能力契约，之后在更大任务集、多次重复下同时评价质量、总耗时和完整费用。
