# 执行等待时的补充输入修复（2026-10-13）

证据索引中的 `archive/` 指向本地归档根目录 `~/Documents/VelarOS-Evaluation-Archive/2026-10-11-real-tasks/`。

主分支已修复一个核心生命周期缺口：ActLoop 等待后台作业时只订阅运行级取消，ActRunService.steer 取消的是回合级信号，所以用户已成功追加的指令不能及时唤醒主循环。后台作业没有输出或结束时，输入可能长时间滞留。

等待现在同时订阅运行与回合信号。新输入取消等待后，循环先等待输入持久化，再建立下一轮；后台作业继续持有原运行信号与执行身份。真正取消、等待错误仍沿原路径收束，不恢复已取消的任务。不增加公共 API。

两组先失败的回归覆盖普通与延迟持久化，修复后均通过。两种传输的真实 Runtime/SQLite/Node 回归证明：没有作业输出时，补充指令仍唤醒模型；同一进程随后继续执行并交付。Agent 97/97、执行观测 20/20、Runtime 全量 1043/1043 通过。

本轮还发现既有 model-stream 测试把取消与非法计数同时到达时的诊断文本固定为协议错误；当前取消先返回是合理行为。测试现在实际检查非法计数既不发送给消费者也不进入计费回调，取消仍返回。生产流处理代码没有因此变化。原失败日志保留。

真实执行测试首次失败是夹具在 Node 子进程启动落盘前读取启动标记；随后发现作业结束引起的最后一次组帧更新允许多一轮。夹具现等待实际启动，并验证第三次请求收到补充指令和原作业身份，最后收束限制为三至四轮。失败与修正记录均保留。

这项修复证明用户引导的响应性，不证明历史长任务失败能被救回，也不作为模型任务性能提升。上下文重复投递修复的实际任务收益仍需冻结版本验证。
