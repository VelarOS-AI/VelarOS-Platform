# 评测规范

评测按任务质量、稳定性、端到端时间与完整费用报告结果。开发任务用于诊断与回归；改进效果在预先冻结的独立任务上验证。模型、费用预算、并发和运行范围由每次评测的明确授权与冻结配置确定。

## 入口

- `bun run eval:act --model-config /absolute/model.json --output /absolute/results`：Agent Lab 驱动正式 Runtime，归档观测并独立核验结果。配置里的 `apiKeyEnv` 指向凭据环境变量。
- `bun run test:act-eval`：评测接缝、证据检查点与 Harbor 记录的确定性回归。
- [长任务运行器](../../scripts/agent/long-tasks/README.md)：冻结候选、隔离任务资源、独立验收、完整计量与恢复。
- [Agent Lab 接入](../agent-lab/integration.md)与[测量方法](../agent-lab/methodology.md)：驱动、验证器、归档、统计和可复现性。

这些命令依赖当前包构建；执行付费模型前固定源码身份、工作树状态、模型和推理设置、供应商、依赖、任务版本、资源、验证器与计费口径。

## 冻结与独立验证

任务、验证器、候选、对照与成功条件在执行前登记。根因修复面向通用机制，使用不同数据形状、任务类型和能力组合验证。开发题的再次成功只证明回归；不根据已看见的独立集答案修改实现或补题直到显著。

评分覆盖原始需求和最终真实产物。保留原项目测试，模型新增测试不能代替它们；同时检查行为、公开接口、生成物和要求的文档。评分器故障的修正单独记录原始文件、哈希、原因与双方重新判分，不重做模型产物，不把重新判分算成产品提升。

## 记录与比较

保留全部计划中的尝试、失败、超时、中断、重试、恢复与未知状态。每次模型请求分别记录身份、用量和费用；业务、整理、核查及子任务共同计入总账。供应商未报告的用量和未知实际价格保持未知，参考估算与实际扣费分列。

端到端时间从正式派发计到验收、资源回收与归账完成，排队和环境准备另列。解题时间、模型等待、程序执行、验证及清理使用双方一致口径。底层操作、外层工具和模型请求分别计数；缓存数据用于解释实际时间与费用。

总体成功率包含失败与超时，未知判分单列并给出保守边界。成功效率只比较双方成功的配对；失败耗时和费用同时报告。版本、任务、资源或对照身份不同的尝试分别分组，报告样本数、配对差异和不确定性。

## 资源与收束

每次尝试使用独占任务根、临时目录和证据目录；运行前核对容量与资源归属。取消和关闭等待模型、进程及计量收束。未知外部效果先查原始回执，恢复操作保留身份与证据。原始归档、冻结配置及验收记录作为复核依据。
