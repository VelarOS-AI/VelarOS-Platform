# 标准编程环境与宿主能力发现

本轮把日常执行迁移到真实 Node.js：文件、路径、网络、进程与第三方依赖遵循标准运行时语义。模型通过代码组合操作；应用专有能力以会话目录中的 ES 模块和局部类型文档按需发现。执行权限、取消、进程回收、记录和界面交付仍由宿主负责。

## 执行合同

1. Node 在宿主提供的命令执行端口内运行，继承同一工作目录、进程约束与取消语义。脚本经标准输入交付，项目依赖按 Node 的工作目录解析。
2. 标准库与现成工具负责通用操作。宿主能力目录仅提供当前会话可用的应用连接；客户端为普通 ES 模块，每次调用仍经过 Kernel 的真实授权与回执。
3. 常驻说明只描述环境、执行入口、结果位置和能力目录。能力的参数与返回类型从正式接口按操作生成，使用时读取。
4. stdout/stderr、退出状态和可读取的日志路径自动交付；源码、原始输出与失败均可回查。跨轮数据与复用程序使用普通文件。
5. 业务子任务使用同样的标准环境，独立授权、目录和调用身份。上下文整理等受控宿主程序保持自身的能力边界。

## 验证

先验证真实 Node 标准库、项目依赖、宿主连接、权限拒绝、超时、取消、并发会话和长输出，再验证 Desktop 的正式装配与界面链路。端到端对照使用相同模型和生成参数、独立工作区、固定任务与统一验收；完整记录成功率、请求数、输入输出、耗时、费用及失败。开发题与冻结的独立任务分别记录，未知用量不按零计。

所有能力桥参数继续从正式操作接口生成。通用文件操作由标准库完成；浏览器、图片交付、应用命令台、持久后台任务、交互与协作等宿主能力在磁盘目录中按需发现。主会话常驻说明不展开这些合同。

Desktop 正式装配注入固定 Node 24.15.0 二进制，六个平台/架构的依赖锁定在 `package.json` 与 `bun.lock`。可执行文件解包至 ASAR 外，并经发布门校验；Electron `RunAsNode` 保持关闭。ASAR 回归使用实际安装依赖和空 PATH，验证正式解析路径及真实执行。

## 权限与运行边界

- Node 进程拥有宿主批准的 OS 范围，直接文件、网络和子进程操作由该范围约束。Desktop 的「每次询问」在启动整段程序前批准；能力桥调用仍逐次经 Kernel。
- 语法检查不推断任意程序的副作用；直接 Node I/O 不形成逐条 Kernel 回执。应用原有的工作树快照仍记录本轮文件差量。
- 普通子进程随当前执行回收。需要跨轮运行或接入应用命令台时，使用按需发现的宿主后台任务接口；专门回归证明任务可在下一次 Node 执行中查询并停止。
- 每次执行有独立目录和随机连接凭据；凭据只在进程环境中，目录保存客户端与类型文件。授权目录不是额外的 OS 沙箱，实际约束以 `confinement` 回执为准。
- stdout/stderr 保留有界预览，输出日志上限 16 MiB；退出失败、取消、超时和清理未完成均以失败交付。成功退出不等于任务验收通过。

## 评测设计与记录

最终对照使用相同 `gpt-5.6-sol`、high reasoning、Responses 参数、8 次模型请求和 240 秒上限。每个任务在独立工作区运行；四类新任务各重复两次，交替新旧环境顺序。验收程序独立检查实际文件和行为，宿主发现任务还必须产生真实宿主调用。

最终题目为递归 JSONL 汇总、使用已安装 ESM 包、异步函数缓存修复、宿主会话分组，运行前将题目与标准运行时分别冻结并记录 SHA256。模型的“完成”状态与独立验收分别记录，比较成功要求二者同时成立。用量缺失保持未知；耗时包含运行时和命令执行，供应方排队也会影响结果。

开发集与第一轮对照的评测装配展开了 Shell 类实例，丢失原型方法，导致基线 Shell 调用失败。这些记录归为无效比较，保留原始失败、用量及日志，不能用于性能结论。修复采用显式转发实例方法；最终评测在任何模型调用前，让两套运行时各经真实能力桥执行同一 Shell 探针。修复后另行冻结新题目，完整保留此前记录。

本机证据根：`.velaros-workspace/bench/standard-runtime-20261004/`。`invalid-comparison.json` 标记早期记录，`validated/` 保存有效对照的包快照、冻结清单、预检、逐次 trace 与独立结果。外部依赖链接精确安装版本，评测期间不执行依赖安装；工作区包全部链接到各自快照。

## 复现与结论

`scripts/agent/freeze-standard-runtime.mjs` 从已构建的 checkout 生成独立包快照。新比较需使用新的输出目录，分别准备基线与标准环境快照，并将任务文件哈希写入 `suite-freeze.json`。在仓库根目录调用：

```sh
node scripts/agent/standard-runtime-evaluation.mjs \
  "$EVALUATION_DIRECTORY" acceptance 2 "$CREDENTIAL_FILE" \
  scripts/agent/standard-runtime-acceptance-cases.json
```

凭据文件按评测器要求提供 `chat.apiKey` 与 `chat.baseURL`。评测器先执行双侧真实 Shell 预检，再交替运行模型并独立验收。上面的任务集适合回归；后续若据此修改实现，泛化结论必须来自另行冻结的新任务。

当前可以确认：标准环境把通用操作交回模型熟悉的语言与工具，显著缩短常驻说明，并降低本轮完整用量配对中的输入消耗。此次小样本没有证明整体更好用：正常完成率低一次、请求总数相同、耗时更高。宿主发现题的请求数还从 6 增至 8，需要继续检验按需发现的实际成本。

本轮只覆盖一个模型、四类任务与 macOS arm64；六个平台/架构已锁定二进制依赖，其他平台未做真机验证。更长期任务、真实浏览器操作、多轮恢复与不同模型表现仍需要独立验证。当前交付是可运行、可回归、可审查的完整分支，效果判断应以这些已测边界为准。
