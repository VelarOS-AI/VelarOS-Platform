# ScriptAct Desktop 原生评测

目标：在实际 VelarOS Desktop 的项目会话中，使用 macOS 原生环境持续进行 ScriptAct 与同期 Codex 的配对评测、诊断和修复。先保证稳定性与完成质量，再控制解题速度，在这些约束内降低完整费用。

## 执行协议

- ScriptAct 经 Desktop 的正式 Hook → renderer → ChatService → Platform 会话执行，过程、脚本、命令与文件改动在真实界面可见。任务各用独立项目会话，后台派发保留用户当前选择。
- Codex 使用本机官方 CLI，首批固定 0.159.2。每个候选冻结实际可执行文件、Desktop 与 Platform 的运行产物摘要和模型配置。
- 双方精确模型为 `gpt-5.6-sol`，推理档位 `high`，通过同一签名计量网关访问 `https://ai.hedgeho9.cn/v1`。每个任务、参与者、尝试具有独立身份，真实请求不允许静默换模型。
- 模型总容量与实际工作窗口分别冻结。工作窗口从所有已装配 Agent 产物的 `ContextPlanTuning` 取得；各副本必须一致，Codex 的输入整理阈值使用同一窗口。付费前核对策略文件摘要，收尾时核对每个 ScriptAct 宿主帧的实际输入上限与 Codex 启动参数；缺少证据或不一致时记为基础设施故障并停止比较。相同窗口不表示两套系统的整理算法相同。
- 用户授权 ScriptAct 完全访问：由主进程读取设置，`workspaceSandboxEnabled=false`、`permissionConfirmationMode=never-ask`。Codex 使用相应本机完全访问模式。任务用独立工作树防止改动混合，工作树不是操作系统隔离边界。
- 每题固定源仓库提交、初始文件状态、题目、依赖锁、测试与验收条件。双方使用相同 macOS 工具链和条件；复用 Git 对象与包管理器下载缓存，可写依赖、构建输出、端口与进程按任务分开。
- 最多两个 Agent 执行槽；先以一组配对验收，增加并发前验证主进程、工作区、消息流与费用归属。排队任务仍显示为独立会话。
- 环境准备与判分阶段不调用模型。付费前先确认环境可启动、测试能实际执行且基线行为与题目一致。任务环境故障单列，原失败保留。
- 原生 runner 支持 pytest/JUnit、Django/unittest 与 SymPy 的 verbose `bin/test`。Django 保留官方标签，通过实际方法头、说明别名、失败摘要、退出码与总数核对结果；SymPy 将短名称绑定到实际文件与函数，同名标签保留全部匹配，核对文件计数、完整报告与退出状态，跳过和预期失败不算通过。配置、测试补丁、依赖锁、官方 parser、准备器及判分代码的指纹写入零模型验收记录，冻结时逐项核对；输入改变后重新验收。
- 判分在新的干净工作树中应用源补丁，用冻结测试验收；验收程序与参考答案不提供给参赛模型。用户追加指引单独记为人工干预，不进入无干预成绩。
- 循环分为诊断、通用修复、零模型回归、候选冻结、同题开发回归和独立验证。运行中的候选保持不变，未知状态的付费源任务不重发。
- 完整轨迹通过正式 IPC 取得同一快照，按有界片段读取并核对完整长度与 SHA256；读取失败保留源终态和费用，官方判分仍继续，但完整轨迹缺失会阻断比较。界面截图是辅助证据，截图失败保留回执，不阻断官方判分。
- 日常循环使用有针对性的本地回归、真实修复题和既有环境凭据。A/B 接线验收会话只用于首次环境接入，当前循环不派发这类会话；验收工具结束时按明确的会话身份与工作目录删除其临时会话，真实任务与其他会话保持。

## 任务选择与难度

优先使用公开任务中能在本机 Node、Bun、Python 直接运行的仓库修复与功能题。已有公开数据集只读取任务与环境信息来筛选兼容性；不读参考解法来定制产品。必要时安装一次可复用的本机工具链，而不是为每题建立环境镜像。

首轮使用已暴露的开发题验证 Desktop 接入。后续按跨文件修改、异步状态、并发、复杂构建与长程定位逐步提高难度。预先登记开发与独立验证归属；已用来诊断或修复的题目不能重新标为独立验证。任务在 macOS 的迁移、环境差异和验收变化均进入清单，成绩属于本机协议。

## 衡量与诊断

主要指标是验收完成质量、框架/工具故障率、解题端到端耗时和全尝试费用。准备、解题、判分分别计时，并记录整体周转时间；成功题的配对效率之外，同时统计全部失败成本与每个验证成功的总成本。

记录实际输入、缓存读取/写入、输出与推理 token，首字延迟、模型等待、上下文准备、脚本与工具耗时，以及上下文峰值与整理。请求数量只作诊断。缓存断点保持现有机制，以完整结果判断收益。

工具分层统计：模型外层调用、Runtime 脚本、Kernel 模块与操作、Shell 原生命令及文件修改。次数、失败、取消和未结束状态分别列出，不同层的数字不相加。保持完整轨迹，界面摘要不能代替原始证据。

第三方实际费率未知时，官方价只作参考；缺少用量或计费分项时保持未知，不按零补齐。历史预算 `unlimited` 沿用，仍保留所有归账和身份门。

并行批次用于诊断与吞吐观察。关键耗时结论在固定并发、相近宿主负载下复验，采集 CPU、内存与磁盘压力，不声称 macOS 进程拥有容器式硬配额。

## 预先固定的停止条件

同时满足下列条件，才完成持续目标并报告具体证据：

1. 本机协议已累计至少 24 个有效配对任务，覆盖至少 6 个项目和 3 档难度；简单任务持续打平时增加难度。
2. 最终候选冻结后，在至少 12 个未用于修复的独立任务、至少 4 个项目上验证；连续 10 个任务没有框架、身份、归账、取消或消息交付故障。
3. 同期同配置 Codex 对照下，ScriptAct 验收成功率至少达到 Codex 成功率减 5 个百分点；双方成功题的配对解题时间中位比不超过 1.10，P90 比不超过 1.25。
4. 完整参考费用的配对中位比和计入失败尝试的每次验收成功成本均不超过 1.10。参与费用结论的请求用量完整，未知费用与失败保持在总报告中；实际扣费仍按供应商依据标明。
5. 没有未解决的高影响通用缺陷，修复均有行为回归，独立题没有被用来反向定制候选。

这些是本机范围的工程验收条件，不推广为所有任务上的总体领先。仅开发题打平或单轮改善不满足停止条件。认证、身份、归账、取消、清理或系统性判分故障发生时，停止受影响队列，先诊断修复，再建立新候选。
