# ScriptAct 新任务对比、产品修复与证据发布

2026-10-07。延续 `evaluation-retrospective-20261007.md` 的清理与经验归档。本轮完整原始材料位于 `/Users/mac/Documents/VelarOS-Evaluation-Archive/2026-10-07-followup`；公开材料在 Website 的 `public/research/scriptact-2026-10-07/`。最终结果以公开 `results.json`、评分修正记录和人工复核一并阅读。

## 本轮差量及原因

| 层 | 变更 | 合同和实际影响 |
| --- | --- | --- |
| Platform model | `retry.ts` 在 65,536 字符上限内解析 SDK JSON responseBody，收集 code/type，并优先显示服务端原因 | 永久失败码优先于 HTTP 429/503 的暂时性提示；保留原有重试策略与有界诊断，不序列化请求对象；新增 INV-22 |
| Desktop 流收尾 | EOF 经过运行状态判断；运行中按错误收尾；保留已有终态、用户等待卡片和 stopping 屏障 | 流关闭不再自动生成成功；英中本地化错误在当前会话可见 |
| Desktop 用量 | IPC 用量加入可选 requestId，以 run/turn 身份发出；重复或修正替换；完整保留已报告的行 | 解决最近 200 条截断与同毫秒合并；旧存档继续按 turn/time/model/provider 回退识别；保存恢复保留统计。历史被截断条目无法凭空恢复，完整研究成本由网关账本确认 |
| Desktop 冒烟 | 在 Runtime.enable 前等待当前主文档 DOMContentLoaded，并支持事件重放、超时 | 修复 Electron 44 预加载上下文初始化与调试器竞争；这是验证工具修复 |
| 评测准备 | campaign 配置显式指定模型、限额、参考价格、PATH；构建前置本地 bin；TAP 12 兼容适配 | 配置与源码、依赖在派发前冻结；TAP 原断言保留，关闭的覆盖率工具不计为验证 |
| 评测额度 | 各参与者独立请求与预占额度，账本重开拒绝变更；超额用永久错误表示 | 缺用量仍保留预占，不让先运行的一方消耗另一方的全部预算 |
| 产物留存 | 评分前导出相对冻结基线的 Git 二进制补丁与全部非忽略新文件，含 JS/TS 和二进制摘要 | 源码扩展名不再形成归档缺口；先还原、构建、验收，再回收副本 |

新模型工具合同、surface 和能力接口未增加。Desktop IPC 的 requestId 是兼容性的可选字段。运行候选为 `candidate-v1-7eec0019c2b1`：Platform 的工作树快照有既有改动，源码提交和完整文件指纹分别记录，期间其他任务的修改未写入该冻结候选。

## 验证

- Platform 驱动与重试：22 项、153 次断言通过；修复前新增覆盖有 3 项失败。运行包增量构建与 module ownership 门禁通过。
- Desktop：14 项生命周期、5 项真实路由、3 项长用量保存恢复及重放、4 项通知、2 项冒烟时序测试通过；四个类型检查分区和 59 项针对改动的架构检查通过；真实 Electron dev:smoke 通过。
- 评测基础设施：61 项通过，包含独立额度、账本重开、回归用例身份和最终代码证据保留。
- Website：最终完整检查、双语言桌面/移动预览、公开证据重建、数据重算与线上核验见归档中的 website/publication 日志。

单测与集成检查说明修复的特定行为。新对比没有提供修复前后的随机配对，所以不将对 Codex 的速度差归因于这些修复。

## 设计与审计

三个新任务与验收在产品源码修改前冻结：JSON5 源位置、jsdiff 原子补丁集作为开发验证，js-yaml 惰性文档迭代器作为最后的保留验证。同一 gpt-5.6-sol/high 标识、兼容端点、生成策略和固定依赖环境，ScriptAct 后跟 Codex，单次正式配对。时间上限 45 分钟；长程资格根据真实上下文维护及其后续执行判断。

公开包保留所有原评分和修正。JSON5 探索运行受共享预占限额影响，Codex 没有上游请求，单独列出而不参与配对比较；TAP 名称中的时间注解造成过误判。jsdiff 的 ESM 路径与删除夹具也有经原版上游确认的评分错误，修正后对双方同一份产物统一重判，文件摘要、原成绩与新成绩均公开。原模型调用和源码不重做。

人工复核另指出 ScriptAct 的 jsdiff 示例只包含一次重命名，不能展示题目要求的多补丁原子事务；自动验收与交付缺口分别记录。YAML 补充探针还发现 ScriptAct 会提前报告后续 NUL 错误；Codex 时序正确，但错误消息与行列标记不匹配原 loadAll。双方原冻结分数不变，附加复现和原始产物一并保留。未将该任务的特殊要求写成运行时通用提示规则。任务由研究作者编写，样本数、固定顺序、单次重复、兼容端点身份未独立验证及缺失 usage 都限制了总体结论。

## 后续优化依据

1. API 产物通过之后，按原始要求逐项复核文档、示例、维护源、发布入口与类型消费者；任务成功不应仅由一个综合分表示。
2. 评分器在负控制“原项目拒绝”之外，需要正控制和基于原 API 的夹具自检。本次两处 jsdiff 错误均可在首次模型调用前发现，应进入后续任务准备流程。
3. 研究总费用保留缺失状态；完整值与已知下界可以作有界比较，两个不完整值的大小不能直接推断总费用优势。
4. 拓展独立任务、交错执行次序和多次重复，检验时间分布及数小时、多日、跨重启的持久任务；当前结果只覆盖实际测到的时长和操作。
5. 参考归档应压缩去重，执行依赖和评分工作区在还原校验后立即回收。保留身份、原始证据、源码与汇总之间的关联。

Platform 与 Desktop 的本轮修改留在用户现有工作树，范围由 `final-scoped-changes.json` 和初始状态记录定位；官网发布只提交 Website 本轮内容及展示改动。
