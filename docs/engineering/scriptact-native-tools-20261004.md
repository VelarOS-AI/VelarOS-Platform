# Shell 与 Node 原生入口：实现与验证

基础环境直接向模型提供 `shell({code})` 和 `node({code})`。Node 标准库、工作区依赖和普通文件承担通用操作；应用能力通过当前授权目录发现，再按包名 import。四项优化均已实现，生产实现与冻结评测快照逐文件一致。

## 公开合同与模块差量

| 所有者 | 变化 | 理由与影响 |
| --- | --- | --- |
| Kernel / Model | 新增工具声明、完整调用事件及配对回执；SDK 声明真实 tools，调用定义参与审计指纹 | 模型在首轮看到可用执行入口。支持 Responses 与 Chat Completions；SDK 不持有执行回调 |
| Agent / Runtime | 完整响应验收后统一执行；调用与真实持久结果按 executionId 配对，重开恢复 | 错误参数或中断不执行前序合法调用。取消和恢复不会重跑已接受程序 |
| Script / Shell | 文件入口与能力预加载分离，子进程 PATH 指向宿主 Node，NODE_OPTIONS 继承当前包解析 | `node saved.mjs`、普通 Node 子进程和 `fork` 使用相同包名，调用仍经 Kernel，凭据仍限定于本次执行 |
| Script | 从正式类型声明生成单操作 `.d.ts`，目录新增 operationDirectory | 每个文件包含用途、签名、递归类型、共同规则和最小调用示例；整模块声明可按需读取 |
| Model / Agent / Runtime | 上下文字节分项、旧状态开销阈值、原生源码去重 | 定位和减少重复文本，保留任务、实际结果、失败诊断与完整输出日志路径 |
| Desktop | 扩展 Electron 与 ASAR 探针，覆盖 Shell 文件和 fork 导入 | 空 PATH、关闭 RunAsNode fuse 的打包环境使用随产品分发的 Node |

`ActTurnDecoder` 增加可选 response/acceptTool，`ActExecutionPort.invoke` 增加可选调用参数及配对结果返回；现有文本驱动和执行端仍通过回归。Agent 版本同步为 9.4.0，公开 API 基线、锁文件及包目录由正式工具更新，本轮未发布包。

`ModelDriver.nativeTools` 显式声明传输支持。默认 SDK 驱动启用原生入口；自定义文本驱动及显式受限协议继续使用其原有合同。`NativeExecutionInput` 的 schema 由 TS 生成器生成。完整原生响应与配对记录一起恢复为供应商 assistant/tool 消息；正文被摘录或退出历史时，只交付中立资料，避免孤立调用。

自定义进程宿主应使用 `NodeProcessRequest.entrypoint` 启动 Node，并把 `preload` 追加到子进程 NODE_OPTIONS；审批仍使用 source。提供的 Native/Shell 宿主已统一实现。入口缺省时，原 ESM stdin 启动合同继续可用。当前进程凭据、授权和进程树回收边界保持一致。

## 上下文与验收承诺

累计旧状态相对权威逻辑历史的开销超过 `max(4096 字符, 逻辑历史字符数 × 0.5)` 时，重新组织请求。Agent INV-48 与 Runtime 的前缀保留约定据此更新。常规任务、源码与结果继续从权威历史恢复；超出逻辑条目上限的必要长正文，必须完整重新发送并重新核对交付证明。对象和数组长材料、取消、重启、未知效果及重复写入的正反例均通过。

`ModelInputEstimate.composition` 记录估算编码文本的 UTF-8 字节分项：system、tools、assistantHistory、userHistory、toolResults、current、framing，合计为 total。图片和不透明推理容量另计。该指标用于解释请求构成；实际 token 与费用依据供应商用量。状态重建可能改变前缀缓存，因此缓存命中不能替代成本判断。

## 固定工作量测量

冻结版本各执行相同的 24 段 Node 源码，逐项写文件并核对完整结果，共 25 轮请求。此项使用确定性模型桩，固定容量估计并提供足够窗口，隔离观察暂态状态收束；只测文本体积，不测模型智能或供应商速度。

| 指标 | 前版 | 本版 | 变化 |
| --- | ---: | ---: | ---: |
| Runtime 请求序列化累计字节 | 2,094,010 | 845,102 | −59.6% |
| ModelDriver 编码文本累计字节 | 2,113,374 | 791,139 | −62.6% |
| 最后请求的 ModelDriver 编码文本字节 | 188,917 | 52,129 | −72.4% |
| 最后请求所带旧状态正文 | 125,410 | 5,375 | −95.7% |
| 最后请求所带旧状态帧数 | 24 | 2 | |

原生工具 schema 也有成本：这组固定任务的首轮编码文本为 4,601 → 4,933 字节（+7.2%）；收益主要来自后续轮次的状态收束。

从 9 个生成模块取 79 个操作，按每次只需一个操作的读取场景等权比较：整模块读取合计 1,971,845 字节，单操作文档合计 249,033 字节，减少 87.4%。多次使用同一模块时可复用已读合同，不能把该比例直接视为实际 token 或费用降幅。

同一授权包和脚本的独立进程探针：直接 Node 两版均通过；Shell 启动保存文件及 `fork` 在前版均失败，在本版均通过。真实模型仍可能在前版主动配置 loader 来完成任务，因此实测按最终产物和正常完成共同评分。

## 独立真实模型对照

六类新任务在付费调用前冻结：含引用与跨行字段的 CSV、URL 规范化与去重、稳定队列修复、已安装包与可重跑脚本、保存脚本及 fork 调用宿主、长 JSONL 审计。每类重复两次、每次两版交替先后，共 24 次尝试。基线为本轮开始时的 `c0117ef6`，它已经具备 Shell 与 Node 基础环境。两侧使用各自冻结的 Model driver 和 Runtime，固定 gpt-5.6-sol、high reasoning、Responses、12,000 输出 token、8 次请求和 240 秒单次上限。
