# 代码面：模型用写代码的方式使用能力

> 2026-09-17 立。用户裁决：押注模型的代码能力，把能力面从 provider 的 tool-calling 规范升级成一套自有的 TypeScript API。
> 本文是这件事的权威设计；实施进度记在 `foundation-refactor-log.md`。

## 为什么

今天模型面走 provider 原生的 tool-calling：一次把所有工具定义摆上去，模型吐一个 `{name, input}`，宿主执行，回执整个进上下文。
这套规范的三条限制，在这个仓库里各长出了一套补丁：

| 现有机制 | 它在补的限制 |
| --- | --- |
| `tooling:map` / `tooling:read` / `tooling:replace` 整套工具空间分页 | 所有工具定义必须一次性全摆上。browser 32 个工具 = 14,153 字，每轮都在 |
| 各工具的 `files[]`、`steps[]` 批量字段与「一个批量维度」的规矩 | 一次往返太贵，只好把循环塞进参数里 |
| 结果截断、当轮句柄化、`distill_context` | 每个工具回执都必须整个进上下文 |

代码面把这三件同时解掉：工具空间分页变成 `import`，批量变成 `for`，中间结果可以在程序里过滤掉、只把要的交出来。

还有一条更根本的：**说明是第二个真相源**。今天的模型面说明是手写的，实现改了它不会跟着改——本轮修的四条缺陷
（`op="read"` 枚举里没有、`nextActions` 字段不存在、`version` 实为 `revision`、`statusContinuation` 少一层嵌套）全是这个病。
最能说明问题的是 `system:read`：结果类型里有 `hasMore: boolean` 直接回答「读没读完」，而手写说明教模型拿 `range.end` 自己推算，
`hasMore`、`totalChars`、`encoding` 三个真实字段模型从来不知道存在。声明从源码生成之后，这一类缺陷在编译期就炸。

## 定下来的

1. **模型写 JavaScript，但照样过 TypeScript 的检查**（`checkJs`，类型从生成的声明里推）。不自造语言——
   这件事唯一的依仗就是模型见过海量 JS/TS；自造语法等于把依仗扔掉。「自己定义规范」定的是 **API 表面与调用约定**，不是语法。
   写 JS 而不是 TS 是实测换来的：四类缺陷（字段拼错、读不存在的字段、入参形状错、输出被截断）`checkJs` 一条不漏地抓住，
   而中间**不必转译**，于是转译带来的行号错位整块消失——那正是这一版最先出 bug 的地方。
   手滑写了 TypeScript 不废掉一整轮：整份诊断都落在「这个语法只能在 TypeScript 文件里用」那一族时，
   按 TS 再查一遍（真类型错照样拦），剥掉类型照跑，并在回执里提醒它下次写 JavaScript。
2. **原生协议压缩成一扇门。** provider 那层去不掉（模型总要吐出点什么、宿主总要收到点什么），但可以只剩一个工具：
   入参是一段 TS 源码。其余能力不再作为 tool 暴露。
3. **声明从源码生成。** 能力包的入参与**出参** TS 类型 → 模型读的 `.d.ts`。生成物进仓，门禁守着它与源码一致。
   出参这一刀最关键：今天回执根本没有 schema，所以回执类缺陷只能靠人眼抓。
4. **执行前先 typecheck。** 编译错误回灌给模型，不执行。报错比 schema 违规更有信息量（它直接给出正确的字段名）。
   诊断**必须带代码帧**：模型吐出来的程序是一段裸文本，它自己看不见行号，只回「(2,29)」等于让它靠数行定位。
5. **改上一份程序不必整份重写。** 协议照 `system:edit`（`oldText` 一字不差、范围里必须唯一、一组全成或全不成、
   各处不许重叠），**不用 `project:edit` 的行号那套**——同样是因为模型看不见自己刚写那段代码的行号。
   一处适配：`system:edit` 的 `range` 必填是因为它来自 `system:read` 的回执、模型照抄即可；
   这里的程序是模型刚写的、没有回执可抄，所以 `oldText` 升为主键、`range` 只是可选的收窄手段。
   上一份程序由宿主记着并传进来；传了 `edits` 却没有上一份时明确拒绝，**不猜一份出来**。
6. **代码跑在子进程里，它自己没有任何能力。** 每次 API 调用 RPC 回宿主，审批与危险判定还在原来那道端口后面。
   **不用 `node:vm`**：模型写的代码可能被提示注入影响（浏览器页面内容能诱导模型写出恶意代码），
   `vm` 挡得住「够不着」，挡不住有心的逃逸。子进程顺带白拿超时与取消。
7. **审批下沉到 API 实现内部。** 今天「危险命令硬门化」成立，是因为一次调用就是一个可审查单元；
   代码块里几十条语句不是。解法是同一道端口在 API 函数实现里撞，而不是在协议层撞。
8. **中间结果不自动进上下文。** 只有返回值与显式输出进。
9. **每次 API 调用发运行事件**，界面照旧显示卡片。
10. **旧的 tool-calling 面留着，直到代码面在 agent-lab 上打平或更好，然后删掉。**
   留它不是对赌注不放心，是**没有对照就没法证明赌赢了**；它今天已经存在，留着不花额外成本。

## 哪些东西进模型可观测面（`@AgentView` 与双向门禁）

**问题**：改 `SystemReadFileResult` 的人，在编辑现场看不到任何迹象说明模型在读它。
可观测面靠「从操作方法可达」隐式决定，这是最容易出事的一类无形契约。

**根**由登记表声明（命名空间 → 接口），并且**每个放出去的方法要打 `@AgentView`**——
同一个接口里可以只放出一部分，不是全有全无。

**闭包由机器算，不手工维护**（手工标一定会烂），但闭包里的每个类型**必须带 `@AgentView`**，门禁双向守：

| 情况 | 门禁 | 为什么 |
| --- | --- | --- |
| 在闭包里、没标 | 红，并列出要加标记的类型名 | 你让一个类型进了模型可观测面，得知道 |
| 标了、不在闭包里 | 红，让你删 | 免得标记烂成装饰 |

这样标记不可能过期：加一个字段引用了新类型，门禁当场告诉你「它进模型面了」。
与仓库既有的 `check:agent-public-api`、提示词指纹是同一套路子——生成物进仓，改了要重算并说明。

## 注释写什么、不写什么

判据不是品味，是一个能执行的测试：**「字段名 + 类型」能不能推出它的含义和用法？能，就不写。**

**不写**：`path: string`、`command: string`、`timeoutMs`（名字里已经带了单位）、
「可选」（`?` 已经说了）、把字段名翻译一遍的话。

**要写，只写这四类**：

1. **缺省行为**——不传会怎样。「不传用宿主给的默认目录。」
2. **条件语义**——什么时候才有、才有意义。「`hasMore` 时把 `range.end` 当下一次的 `offset`。」
3. **跨字段约束**——和谁对应、和谁互斥。「`files` 与入参的 `files` 一一对应。」
4. **名字里没带的边界**。「一批最多 20 项。」

**一句话说完**。说不完的是设计有问题，不是注释不够长——那种情况该改形状，不该加字。

分节注释（`// ── …… ──`）是给读源码的人用的，**不进模型面**，生成器要滤掉。

## 能力怎么给：常驻、索引、导入

**分三档**，理由在下面那条「为什么不许猜着写」：

| 档 | 给什么 | 谁在这一档 |
| --- | --- | --- |
| **常驻** | 完整声明 | 这个空间的核心几个（system 的 read/edit/run 这类） |
| **索引** | 模块名 + 方法名，一个方法十来个字符 | 其余内置的，以及**用户 mod 注入的** |
| **导入后** | 完整声明，**留在本会话里** | 模型 `import` 过的 |

**索引只说存在性，不说类型。** 一百个方法一两千字符——今天光 browser 32 个工具的说明就 14,153 字。

### 非常驻能力必须先导入才能用（不许猜着写）

`import` 本身就是请求，不另立「查签名」的工具：

| 程序里的情况 | 怎么处理 |
| --- | --- |
| 只用常驻能力 | 正常检查、正常跑 |
| `import` 了本轮已给过声明的模块 | 正常检查、正常跑 |
| `import` 了**没给过**声明的模块 | **不执行**，回它的完整签名，让模型据此重写 |
| 直接用既不常驻也没 import 的名字 | `Cannot find name 'git'`，去看索引 |

**检查器只加载「常驻 + 本会话已导入」那几份，不加载全量。**

**为什么不许猜着写**（这条一开始想反了，记下来免得再反一次）：
代码面里写错一处的代价**不是一次调用失败，是整段程序不执行**——中间一句猜错字段名，
前面写对的十行一起白费。所以「猜着写、让诊断教它」在代码面比在工具面**更贵**。
更糟的一种：猜出来的调用**恰好过了 typecheck 但语义是错的**（漏了必填默认值、用错枚举档），
那就不是白跑一轮，是真的做错事。

### 租约：写在 import 上，不做单独工具

导入过的声明留在会话里，但**它不能只增不减**——长会话里装十几个 mod，前缀会一直长。
租约是这块的回收机制。它**不是一个工具**，就是 import 上的一个属性（实测 tsc 收这个语法）：

```js
import { log }   from 'velar:git' with { lease: 'once' }  // 查一下就完
import { diff }  from 'velar:git' with { lease: 'task' }  // 接下来一直要用
import { blame } from 'velar:git' with { lease: 'done' }  // 用完了，退租
```

续租与退租因此**不独占一轮**：任何一段程序都能顺带带上它们。

**三档是意图，不是期限。** 不让模型报「几轮」——它看不见前缀预算，报短了被回收白花一轮重导、
报长了前缀膨胀它也感知不到。**这是个它没有信息去填的旋钮**，而这个仓库一向把这种旋钮拿掉
（office 的 `cwd`、memory 的 `workspaceRoot` 都是这么删的）。`once` / `task` / `done` 它答得对。

**宿主拥有回收策略**（预算 + LRU），模型给的是优先级信号，不是合同。

**回收必须不花模型一轮**：被回收的模块又被用到时，宿主**静默重新装上再检查一遍**，
而不是回一个 `Cannot find name` 让它重导。没有这一条，租约就是拿「模型白跑几轮」换「前缀小一点」，
那笔账不一定划算。有了这一条，回收对模型完全不可见，只影响前缀大小。与「钳制不拒绝」同一条铁律。

三档里**最值钱的是 `done`**：`once` / `task` 宿主看用了几次也能猜个八九不离十，
但「我用完了」只有模型知道——它知道自己的计划走到哪了。

### 和今天的工具空间分页差在哪

今天的分页是**能力闸**：没换进来就调不了，而且**运行期**才发现。
这一套是**编译期闸**：没导入就写不出能过检查的程序，**在执行之前拦住**，副作用一个都没发生，
而且报错直接给出正确签名。差别是拦在哪一侧。

另一个白捡的性质：导入过的声明留在会话里，**前缀按需长大**——用到才付那一份的字数，之后一直在缓存里。

### 还没定的

索引这么薄，模型第一次写得准不准，是**可测的经验问题**。agent-lab 那一步正好量它：
「只给索引」与「给全量」跑同一批 journey，比首次通过率，再定哪些进常驻档。现在凭推演定详略是拍脑袋。

## 实施顺序（按风险，不按工作量）

**先建最薄的端到端回路，不要先建生成器。** 生成器是机械活；真正的未知是执行回路能不能安全跑通。

1. ~~**回路**：打通 `typecheck → 子进程执行 → RPC 回宿主 → 审批 → 运行事件 → 结果回灌`。~~
   **已完成**，落在 `@velaros-ai/code-surface`（12 条不变量、27 条测试、门禁零条）。
   过程中实测抓到三件：转译漏做、大回包被 `process.exit` 截断、以及**隔离静默失效**——
   `fork` 缺省用 `process.execPath`，宿主跑在 bun 下时起出来的是 bun，它忽略 `--permission`，
   命令行看着正常而隔离一点没生效。因此立下 INV-9：**隔离必须自证才接活**，只信旗标不算数。
2. **生成器**：能力包 TS 类型 → `.d.ts`，先 system 全量，再铺开。加门禁守生成物与源码一致。
3. **接进 agent**：作为一种执行模式（`listExecutionModes()`），与今天的工具面并存。
4. **对照**：agent-lab 上两种形态跑同一批 journey。
5. **收口**：代码面打平之后删掉旧工具面，连同它的三套补丁（工具空间分页、批量字段、回执截断句柄）。

## 还没定的

- 那扇门叫什么名字（`code`？`run`？要避开 `system:run`）。
- 网络缺口：`node --permission` 不覆盖 socket，`NodeSubprocessCodeRunner` 因此**不可发版**（INV-5）。
  正式版换 WASM 里的 QuickJS；`CodeRunnerApi` 已抽成注入面，换的时候不返工。
- 审批中途挂起怎么回到界面：API 函数是 async，`await` 一下审批即可，但交互与界面要跟着改。
