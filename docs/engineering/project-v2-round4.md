# Project 2.0 第四轮：Workbench 持久化召回与引用稳定性

日期：2026-09-13。实现、自动化验收与两次真实模型续作完成；正式发布、消费者锁文件和提交待收口。

## 本轮修复

1. **Workbench 原文只在内存，淘汰或重启后丢失。** `WorkbenchContextRecall` 现在只装配召回服务；`agent/context/WorkbenchContextPayloadStore` 负责缓存与有序访问，`WorkbenchContextPayloadDiskStore` 负责不可变记录、引用索引和完整性校验。生产启动注入 `chat-context-payloads` 目录。400 条 / 32M 字符是内存缓存上限，磁盘仍保留可召回原文。执行器等待输入保存成功后执行工具；落盘失败不会伪装成成功缓存。
2. **不同会话的重复调用 ID 会串用参数。** 回归先复现 `first original` 被错误读成 `second original`。查找现在优先使用会话内索引，再兼容已有跨会话引用；当前会话的原文不会被另一会话同名调用覆盖。会话删除同时清理缓存、磁盘内容和索引，保留其他会话。
3. **真实历史中的引用包装被再次归档。** 本轮实际 `project:read` 调用生成了 24,584 字符的原文及 26,483 字符的引用包装，两者共用调用 ID。Agent 的 `ToolPayloadReferencePlanner` 现在复用既有原文地址，保留逐次工具结果的引用关系。重复规划三次不会增加包装记录。旧记录的召回会追到原文后再应用 JSONPath；循环引用、有界查找和原文缺失均有确定结果。

Agent 对外调用参数保持一致，版本更新为 **0.6.25**。公共声明检查捕获的是 `ContextRetrievalPayloadReader` 新增的私有拆分方法；已审查兼容性并更新 API 基线。

## 数据与执行边界

- 内容文件先通过临时文件加 rename 发布，再发布索引；只有全部完成才确认保存。中断后的重复保存可修复缺失索引，同内容重写保留首条记录，冲突内容拒绝覆盖。
- 路径中的会话 ID、调用 ID、hash 均经 SHA-256 转成目录或文件名。记录包含版本、长度、身份与校验和；损坏如实报错。macOS 文件权限为 0600。
- 一个 Workbench 主进程持有一个 store，串行化写入、读取和删除，失败不会阻塞后续队列。进程关闭保留磁盘数据，用户删除会话才删除对应记录。
- 保障覆盖进程退出与重启；现有 Core 原子文件助手没有 fsync，本轮不将其等同于突然断电后的持久性保证。
- 新存储覆盖启用后保存的记录。旧版只在内存且已经丢失的原文不能从这份新存储恢复。磁盘内容按会话生命周期保留，没有静默的容量淘汰。

## 额度恢复后的真实续验与最终收口状态

同一大型 Workbench worktree 中完成两次真实 GPT-5.6 Sol 续作，中间完整退出并重启 Electron。实际执行历史累计 41 次工具调用、4 次 `project:edit`，编辑调用全部成功。协调修改最大的一次为 2 个文件、2 个操作、6,456 个 UTF-16 code unit 的参数。完整过程见 [真实续验历史](project-v2-round4-resume-history.json)。这组数据反映实际修复任务；大事务压力仍以 Project 规模测试和 53 次全工具验收为依据。

真实模型先召回重启前的 `project:read`；第二次重启后又以 `input:call_o1mynKLzzZbZrYEFlQx3yrP9` 和 `$.edits[1].text` 恢复上轮新增的回归源码。审计直接比较模型拿到的正文和原始调用参数：1,538 个 UTF-16 code unit 完全相等，整份 2,466 字符输入的磁盘 hash 也未变化。

新增且已经审查合入主工作区的修复：

- 裸调用 ID 始终限定当前会话，删除会话后不能退回另一会话同名调用；完整 payloadRef 可显式查找其他会话。旧版仅有全局索引时，仍允许其所属会话读取。
- 目标会话删除容忍无关损坏索引，并清理目标会话可归属的语法损坏或结构损坏索引（null、空对象、数组、字符串）。另一会话的有效全局索引必须按地址判断，不能因文件名重合被误删。
- 全局清理成功后才移除会话索引，保留失败重试所需的信息。通过真实 EISDIR 故障验证：第一次如实报错，排除故障后重试清理成功，其他会话数据与有效索引保持完整。

真实过程中的非零命令全部保留：一次 Bun 参数顺序错误、一次预期的修复前回归失败、一次 Bun 不支持嵌套 `node:test` 子测试。参数化回归改成顺序迭代，每种数据使用独立临时目录。

最终验证：Workbench **618** 项 + 发布脚本 **15** 项通过，持久化测试 **13** 项、执行栈相关测试 **8** 项。Project **360** 项通过，类型、lint、架构、工具契约与构建预算通过。最终候选依赖下的全部 Project 工具继续执行 8 工具 / 53 调用验收。
