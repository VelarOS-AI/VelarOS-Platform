## 运行范围

- 正式 Runtime 宿主，装配 Node、Project code、search、agents 和默认 context maintenance；本轮不覆盖 Desktop renderer 链路。
- 应用内 Codex CLI `0.159.2`，模型均为 `gpt-5.6-sol/high`，Responses API，经同一尝试归属网关。
- 模型总窗口 65536，实际工作窗口与 Codex 整理阈值均为 32768，输出上限 12000，并发上限 4。
- ScriptAct 先运行。候选、任务、验收器和工具版本在首次模型请求前冻结。工作区与验收副本独立，使用相同原项目测试。
- 原有测试在长路径下有一条 traceback 换行断言失败；独占短路径预检为 855 passed、25 skipped。新增功能验收在原项目上失败，确认能区分缺失的功能。

**前五轮的供应商接线限制：** Runtime 已正式装配，但评测控制器直接创建 SDK 模型，跳过产品的供应商适配层。第五轮 101 份实际出线均缺少 `prompt_cache_key` 和显式缓存断点，其他轮次使用相同接线。因此下列缓存与部分费用描述的是这些真实执行，不能代表完整产品接线下的收益。原始证据保持；后续控制器使用 `createModelRuntimeComposition`，付费前通过真实 SDK 的离线截获检查缓存键、断点、推理档和加密状态字段。

## 输出交付根因

首次真实请求在 26325 字符投影预算下，将 5 条输出各限制到 1462 字符；外层状态和召回元数据占用后，文件正文只剩约 300 字符。后续单次检索和测试命令也受到同样分配规则影响。全套 pytest 的失败正文未进入最后一次模型请求；最后请求保留了完整需求，却只显示输出开头。因此完成范围与验证误判同时受工具结果交付不足影响。

当前修复将一半投影预算作为结果共享池，并将短回执剩余容量分给实际需要正文的结果。普通结果仍保留 12000 字符单项上限，完整原文继续归档；历史正文一次完整编码，放不下时交给当前帧展示。预分配预算、按需包操作、所需输出证明、授权重置和最终模型输入容量检查继续生效。

同样 26000 字符预算、5 个原生 Shell 调用的回归用例中，120 行源码和 4 个短回执现在完整进入下一次模型请求；旧实现失败。小窗口证明测试按新的容量边界收紧输入，继续覆盖部分交付、未知旧证明、分页缺口与引用身份，未放宽证明要求。

## 产品差量

1. **受限 Node 作用域使用原生工具。** 运行时按真实执行器和允许的控制项选择原生调用；上下文整理与高级搜索继续通过原有受限执行器运行 Node。工具列表及接收门核对 allowed、maxChars、maxBlocks。原先主会话与专项支线使用不同交互协议，真实整理支线出现无接口说明与协议修复。
2. **搜索模型透传工具能力。** SearchActivation 将底层 nativeTools 标记沿调度链传递，避免支持原生工具的模型在搜索会话中退回文本接口。
3. **修复成功整理的终态错误。** 整理补丁完成验证并发布后清除已恢复的中间协议错误；清理、结算等后续真实错误仍保留，原始支线审计继续保留修复过程。
4. **强调完整任务范围。** Node 工作说明加入一条通用要求：阶段成果之后继续剩余事项，结束前按原始需求核对交付和验证。没有任务名称、项目路径或参考答案的特例。
5. **优先交付实际结果。** 有界结果池按实际编码需求复用余量，历史冻结复用同一完整表示，避免重复裁切 JSON；普通输出和完整日志使用相同的读取边界。
6. **同一运行共用容量验收。** Agent 增加宿主方法 `validateContext`，整理候选使用当前运行的实测校准、工作窗口、模型限制和取消信号。无活动运行时拒绝，不调用模型，不推进回合。`@velaros-ai/agent` 版本升至 9.5.0，公开 API 基线由检查器按新增兼容能力更新。
7. **推理延续继续保守校准。** 无图片请求持续以全部实测输入作为文本用量上界，不扣减采用量未知的不透明状态；编译仍独立预留状态 token。保留现有滚动样本上界与安全余量，供应商超窗拒绝仍清空校准。
8. **按真实 Node 执行器选择展示。** 受限整理和搜索支线也使用简洁状态展示；候选验收与主循环采用相同展示方式。作业身份、原文引用和权限核对保持有效。
9. **最终请求超窗先恢复展示。** 附加 ContextStatus 后超过窗口时，先重新投影到恢复预算并重算完整请求，再决定是否受阻。新增边界测试，60 次真实读取后的搜索最终交付继续成功。
10. **专项产物受理即进入完成核查。** 原生调用成功发布整理补丁或验证搜索报告后，由宿主 `deliveryReady` 触发普通完成检查，省去额外模型确认请求。执行失败、未通过验证的报告和待处理工作继续阻止完成。INV-52 覆盖这些边界，硬上限最后一次调用仍能交付合法产物。
11. **分离固定开销与正文增长。** 滚动样本通过线性趋势估计文本增长，固定开销上移到覆盖全部实测样本后统一加安全余量；趋势不可用时回退保守比例。原始估算仍是上限，精确计数、图片和不透明状态独立预留。Model 的可选校准字段 `overheadTokens` 随 0.10.0 发布，Agent INV-40 与编译器测试覆盖样本密度变化、回退、重置和容量边界。
12. **准确交付普通命令结果。** 根引用卡标记为 reference、bodyIncluded=false，不冻结为已读正文；恢复容量时重新交付正文。历史预分配同时识别短 ID 与 UUID，已完整交付且仍在本次历史中的普通输出不再挤占新结果预算，附件仍独立提供。三项新测试在旧实现全部失败，新实现通过；既有跨载体证明测试增加短正文锚点，明确维持“部分正文已冻结、所需大块未交付”的前置条件。
13. **整理原文按实际范围前进。** 用户原文的预载额度独立于父任务压缩目标；材料预算不足时携带精确 offset、nextOffset，只确认实际交付的范围。已经读过的前缀不再反复挤占后续页面。近期响应、命令结果和工作笔记按来源与缺口预载，授权重置重新起算。
14. **按可用能力给出用途入口。** Shell/Node 基础说明只在实际授权时列出子任务、深入检索或整理材料的包名与用途；操作签名继续按文件发现。整理支线原文与近期证据优先，验证通过的原生交付在正常工作阶段即可收束。
15. **先恢复容量再保留最后交付轮。** 第五轮暴露初始保守估算触发提前 finalizing：随后缩小投影虽能发送，但最后请求已消耗在读取接口上。Agent 现在先尝试恢复窗口，可发送就保持工作阶段，仍超窗才触发 pressure。两类边界回归先红后绿，真实 Runtime 的“读取后提交”路径通过。此项从第七版候选起生效。
16. **明确子任务起始材料。** 按需读取的 AgentStart 合同说明新会话从 task 和显式 materials 开始，任务应自足地说明目标、约束、交付及并行编辑分工。权限和工作区继承保持原合同；任务内容由派发者决定。
17. **封段后重新学习增长。** 第七轮某业务子任务的增长估计长期固定为 10298 token，后续实际相邻帧仅增长数百至一千多，却在第 5–9 段反复报告只剩一轮。ContextPlanner 在成功封段后清空两种布局的增长样本与上一帧锚点，使用既有冷启动增长值，随后按新段取样；实测容量校准、抖动检测和最终容量发送门继续生效。普通与保留布局两种回归在旧实现失败，新实现通过；新段真实大增长仍触发压力。此项只进入 candidate-v8。

模型操作与生成 schema 保持当前合同；宿主新增上下文验收方法。INV-40 调整为无图片的推理延续可以保守取样，INV-51 登记活动运行候选验收边界。测试中作业展示解析兼容 Node 的简短标题；稳定历史断言排除按既有开销阈值重建的暂态运行帧，仍核对任务、响应和结果原文的有序前缀。
