# Project 统一文本协议

模型只负责"文本是什么"，框架负责"这些文本在磁盘上怎么编码成字节"。模型只处理 Unicode 源码和逻辑行；磁盘字符编码、BOM、物理换行、分块解码及回滚由框架负责。所有 Project 工具、当前文件视图、历史召回使用同一规则。

## 边界规则

1. JSON 传输只解码一次。JSON 解码后的 `text`、`match` 和文件行文本就是字面源码；字符串中的 `\\n`、`\\u1234`、Windows 路径和正则反斜杠不再次解释。只有 JSON 中真正的换行字符表示换行。
2. 模型的行表示为 `[行号, 原始行文本]`，行文本不携带物理换行和文件头 BOM。跨行文本使用 LF；CRLF 与 LF 的坐标映射由同一个源码层维护。孤立 CR、Unicode 组合字符等正文不被擅自规范化。
3. 新建文件默认 UTF-8、无 BOM、LF。已有文件的编码、BOM、换行和权限由底层维护。无 BOM 的 UTF-16 修改后若缺少可重新识别的字节序特征，框架自动加同字节序 BOM，保持 Unicode 正文一致；撤销恢复原始无 BOM 字节。模型工具不增加 encoding、BOM、EOL 参数。
4. 文件字符编码在一个读取会话中确定一次，分块读取沿用同一个有状态解码器。UTF-8、UTF-16 或 GB18030 字符跨越读取块时保留未完成字节，不能因截断而换编码或生成替代字符。
5. 完整文件先验证 BOM，再检查无 BOM UTF-16 的交错 NUL 特征，然后按严格 UTF-8、GB18030 的顺序识别。无 BOM、无字节序特征的任意字节流不能保证唯一推断原编码，规则是集中且确定的；新写入内容须能被同一规则再次正确读取。无法安全解码的字节不被伪装成空文本；无法无损编码或孤立 surrogate 在事务准备阶段拒绝。
6. 可编辑项目正文的读取、搜索、代码查询和事务统一走文本边界；调用方不各自使用 `readFile(..., 'utf8')` 或再猜编码。读取预算按逻辑 UTF-8 字节和 Unicode 字符计算，CRLF 计一个换行；内部续读保留物理 UTF-16 坐标，显式列边界不能截断 surrogate。
7. 版本、冲突检查和撤销以原始磁盘字节身份为准。逻辑换行等价不能抹平真实外部修改。事务在私有字节计划中保存恢复材料，公开事务、工具回执和上下文只使用受控文本视图；不可恢复的旧 SDK 操作继续明确标识其恢复能力。

字符编码、换行格式与 JSON 转义是三种不同的边界。统一规则的目标是让模型始终使用同一种文本协议，同时让底层准确读回和重建文件。整仓磁盘格式迁移需要作为独立、可预览且可撤销的文件变更执行，不能让只读调用暗中改盘。

## 批量编码转换

`project:file` 的 `recode` 动作是唯一改变字节表示而不改正文的模型入口，留作统一项目编码的备用能力：按路径列出文件，可选 `encoding`（utf-8/utf-16le/utf-16be/gb18030，默认 utf-8）、`bom`（默认不写）、`newline`（lf/crlf，省略保留原换行）。框架读取并探测每个文件的原编码，Unicode 正文经换行转换后由事务字节计划按目标编码整体重编码；已是目标格式的文件跳过并在回执 `recode.unchanged` 中列出，转换的文件报告 `from/to` 格式。转换与其他文件动作共用事务：版本冲突拒绝、无法无损回读的字节拒绝写入、撤销恢复完整原字节。读取、搜索、编辑工具不因此增加任何编码参数。

## 验证矩阵

覆盖中文、emoji、组合字符、反斜杠、JSON/正则源码、空文件、文件头 BOM、UTF-16 大小端、有无 BOM、GB18030、LF/CRLF，以及在每种多字节字符中间截断的预算和分块边界。

同一内容通过 read/search/code/current-view/recall 得到一致的逻辑文本；edit/file/change 批量写入后可重新读取，undo 恢复原字节和权限。格式探测失败或编码不完整在写入前拒绝。写入失败后按事务计划恢复；恢复因外部冲突或 IO 失败中断时明确报错，启用持久化状态的宿主保留恢复计划以便后续恢复。

## 实现与验证入口

- `utils/text.ts`：编码探测、严格解码、Unicode 输入与写入验证。流式探测只保存有限头部和解码器状态，在 EOF 确定编码。
- `files/text-stream.ts`、`files/file-reader.ts`：一次读取绑定解码器，按目标窗口增量收集文本，不重复拼接与解码整份前缀。
- `files/file-store.ts`、`files/project-queries.ts`：搜索格式分类缓存只保存有界元数据；UTF-8 使用快速后端，其余受支持格式通过统一解码与搜索适配器处理。
- `transactions/byte-codec.ts`、`transactions/byte-plan.ts`：在限定差异计算成本内保留原字节表示；极端差异时允许重编码中部，保证 Unicode 正文一致。撤销独立使用完整原字节，不依赖反向编码恢复。
- `test/text-stream.test.ts`：字符分块、读取预算、真假大文件路径、Unicode 列边界、七种物理编码及真实快速搜索。
- `test/model-text-protocol.test.ts`：相同源码在七种格式下经过最终可见行、语义解析、局部编辑和原字节撤销。

提示词和文档同步另由 `project-guidance-drift.test.ts` 及两个宿主的实际请求组装检查约束。发布前运行完整检查，再用安装候选包的宿主验证真实模型任务。
