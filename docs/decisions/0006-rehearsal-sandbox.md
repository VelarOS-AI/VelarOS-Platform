# 0006: 演练沙箱——脚本先在受约束的镜像里跑，看过差量再落到真实目录

- Status: proposed
- Date: 2026-09-15
- Owners: `@velaros-ai/system` 工具面；第二阶段扩到 `@velaros-ai/project`

## Context

大项目重构、迁移、批量处理时，agent 常常要写一段脚本一次改几十上百个文件、删目录、跑 git。今天它只有两条路：直接在用户的工作区跑，或者不跑。直接跑的代价在 2026-09-15 已经付过一次：一个删目录的脚本把仓库路径当成了临时目录参数，整个工作区被 `rmtree` 掉，靠远端与会话记录才找回。危险命令确认拦得住 `rm -rf`，拦不住脚本里算错的路径。

`@velaros-ai/system` 已经有两样东西可以拼出答案：`system:run` 的进程约束（macOS `sandbox-exec`、Linux `bubblewrap`、Windows 注入后端，`workspace-write` 模式下子进程只能写工作区根与临时目录），以及按字符的读改工具。缺的是"一份可以随便糟蹋的工作区镜像"和"跑完之后发生了什么"。

## Decision

新增能力**演练沙箱**：把一个目录镜像到临时区，agent 在镜像里写脚本、跑脚本、读结果；每条跑在镜像里的命令都被进程约束钉死在镜像根之内；跑完能拿到"镜像相对源目录变了什么"的差量；确认无误后，把变化落回源目录，或者拿同一段脚本去真实目录再跑一次。

### 工具面：一个工具，四个动作

`system:sandbox { action: 'create' | 'diff' | 'apply' | 'discard', … }`

| 动作 | 入参 | 做什么 |
| --- | --- | --- |
| `create` | `source?`（缺省是 system:run 的默认目录）、`network?`（缺省 false）、`ignored?`（`link` / `copy` / `skip`，缺省 `link`） | 把源目录镜像到 `<tmp>/velaros-sandbox/<id>/tree`，返回 `sandboxId`、`root`（镜像根的绝对路径）、文件数与字节数、哪些被忽略的目录是链接过去的 |
| `diff` | `sandboxId`、`maxFiles?` | 镜像相对创建时的变化：新增、修改、删除的路径各一列（删除列永远完整给出），文本文件附有界的统一差量，`.git` 里的引用有没有变单独标出 |
| `apply` | `sandboxId`、`paths?`（只落一部分） | 把镜像里的文件变化写回源目录。先向用户确认（高风险、手动、列出删除与覆盖的条数和前 20 条路径），再核对源目录里这些文件自镜像以来没被别人改过，改过的整批不落；然后按顺序新建、覆盖、删除。`.git` 永远不落，回执里提示 git 操作要在真实仓库重放 |
| `discard` | `sandboxId` | 删掉镜像。删除前核对路径确实在 `<tmp>/velaros-sandbox/` 之下，不在就拒绝——这条是事故的直接教训，写进不变量 |

镜像里的其他事都用现有工具做：`system:edit` 往镜像根写脚本，`system:run` 把 `cwd` 指到镜像根跑脚本，`system:read` 看结果。工具面不为沙箱复制一套读写跑。

### `system:run` 在镜像里的行为

本地内核登记每个沙箱的根目录。`runCommand` 解析出的 cwd 落在某个沙箱根之内时，命令交给这个沙箱专属的命令执行器：约束模式固定 `workspace-write`、`workspaceRoot` 是镜像根、网络按创建时的选择（缺省切断）。脚本算错路径写到镜像外——包括写回真实工作区——会被操作系统拒绝，而不是悄悄成功；读真实工作区仍然允许，脚本可以对照源数据。

没有约束后端的宿主（没装 bubblewrap 的 Linux、没注入后端的 Windows）上 `create` 直接失败，错误码沿用 `SYSTEM_PROCESS_CONFINEMENT_UNAVAILABLE`。没有约束的"沙箱"只是一个目录副本，不叫沙箱。

危险命令确认在镜像里照常弹（`rm -rf`、`git reset --hard` 这类）：约束保证它们出不了镜像，但用户仍然看得到脚本在做什么。是否在镜像里免掉"递归删除"这一类确认，留给第二阶段按实际打扰程度决定。

### 镜像怎么做

- 逐项复制源目录，`fs.cp` 带 `COPYFILE_FICLONE`：APFS 与 btrfs/xfs 上是写时复制，秒级、几乎不占空间；其他文件系统退回普通复制。
- `.git` 一并复制，然后把镜像仓库每个远端的推送地址改成无效值，并置 `GIT_TERMINAL_PROMPT=0`：git 迁移能真实演练，推不出去。
- gitignore 忽略的目录（`node_modules`、`dist`、缓存）缺省不复制，改成指向真实目录的符号链接：脚本能用依赖，写它们会被约束拒绝（链接解析到镜像外）。要在镜像里重新构建就用 `ignored: 'copy'`；完全不要用 `skip`。gitignore 规则复用 `utils/search.ts` 现有的解析。
- 创建时记下清单：每个文件的相对路径、大小、修改时间；`diff` 时先按大小与时间筛出候选，再按内容哈希确认。清单落在沙箱目录旁的 `manifest.json`，内核重启后仍能 `diff` / `apply` / `discard`。
- 上限：每个内核最多 5 个沙箱；源目录不超过 20 万个文件、2 GB（不算链接过去的忽略目录）；文本差量每个文件不超过 200 KB、总量不超过 2 MB，超出只列路径。沙箱不能建在源目录之内，源目录也不能是另一个沙箱。
- 内核 `dispose()` 时不删沙箱：用户可能还要看差量。沙箱目录名带创建时间，宿主可以按自己的策略清理过期的。

### 落回源目录

`apply` 只搬文件级变化，不搬 git 状态。对每个变化的文件：先核对源目录里它现在的大小与修改时间还等于清单里记的（小文件再核哈希），任何一个对不上就整批不落、按 not-applied 报出冲突清单（和 `system:edit` 的"写之前再核一次"同一口径）；然后新建的原子写入、修改的原子覆盖、删除的删掉，保留原来的权限位。回执列出每个落下去的路径。要"重放"而不是"搬结果"（比如 git 历史操作），agent 在真实目录再跑一次同一段脚本，危险命令确认照旧。

### 宿主与产品面

- 注入面 `SystemToolSystemApi` 加四个方法：`createSandbox`、`diffSandbox`、`applySandbox`、`discardSandbox`，都由 `system:sandbox` 调用，门禁按工具文件核对。
- 产品面 `LocalSystemKernelApi` 另加 `listSandboxes`，给宿主界面列沙箱、展示差量；差量数据的形状按现有 `file-change` 卡片能画的来定，宿主不必新做卡片。
- 数据放 `contract/sandbox.ts`（可移植）：沙箱记录、差量、落回结果与冲突。
- 实现是 `impl/SystemSandboxes.ts` 一个类（登记表、专属执行器的创建与释放），镜像、清单、差量、落回的纯函数在 `utils/sandbox.ts`；文本差量用 `diff` 包（project 已在用同一版本）。

### 第二阶段：project 空间

project 与 system 互不知道对方，所以 project 空间不直接用系统工具。做法与命令策略镜像一致：`@velaros-ai/project` 的宿主端口加一个沙箱端口（同样四个方法、同样的数据形状），`project:sandbox` 工具调它；Desktop 用本地内核的沙箱能力实现这个端口。这样 project 空间的迁移脚本也能先在镜像里跑，而 project 包不依赖 system 包。

## Alternatives

- **只做 dry-run 提示，让脚本自己带 `--dry-run`**：多数脚本没有这个开关，agent 写的一次性脚本更没有；而且 dry-run 的输出是脚本自己说的，不是发生了什么。
- **git worktree 当沙箱**：只对 git 仓库有效，没有未跟踪与忽略的文件，最要命的是 worktree 和真实仓库共享引用，`git branch -D`、`git push` 直接作用在真仓库上。
- **容器 / OverlayFS**：隔离最好，但需要 root 或 Docker，Windows 与多数用户机器没有；进程约束加写时复制在三个平台上都能不装东西就工作。
- **把沙箱做成一套独立的读写跑工具**：工具面翻倍，模型要学两套；镜像根就是普通路径，现有工具直接能用，只需要内核按路径切换约束。

## Security and privacy

- 沙箱里的命令只能写镜像根与临时目录，网络缺省切断；这是操作系统级约束，不是策略检查。
- 镜像仓库的推送地址被改掉，`apply` 永远不碰 `.git`，演练不会把历史推出去或改坏真仓库。
- `discard` 只删 `<tmp>/velaros-sandbox/` 之下的目录，路径不在那里就拒绝。
- 敏感路径与凭证文件的判定按镜像路径算：镜像在临时区，所以镜像里的 `~/.ssh` 副本不会再问一遍；但 `apply` 落回源目录时按源路径重新过一遍敏感路径与凭证审批。
- 镜像会复制源目录里的一切，包括凭证文件；沙箱目录只对当前用户可读（0700），并在回执里提醒用完就 `discard`。

## Compatibility and migration

新增，不改现有接口的语义。宿主端口多四个方法，Desktop 与 Workbench 升级时按 `createLocalSystemKernel` 直接拿到实现。工具从六个变七个，卡片、不变量表随之更新。

## Validation

新增不变量：沙箱里的命令一定受约束、没有后端就拒绝创建（测试）；`apply` 只写清单记过的文件、源目录变过就整批不落（测试）；`discard` 只删沙箱基目录之下的东西（测试）；镜像仓库推不出去（测试）。单测覆盖写时复制回退、忽略目录链接、差量三列、冲突拒绝；验收用例按编号登记。

## Consequences

复杂迁移的标准做法变成：建沙箱 → 把脚本写进镜像 → 在镜像里跑 → 看差量 → 改脚本再跑 → `apply` 或到真实目录重放 → `discard`。工具说明里写明这条链路，模型在"要一次改很多文件、删目录、跑 git 迁移"时先走这一步。
