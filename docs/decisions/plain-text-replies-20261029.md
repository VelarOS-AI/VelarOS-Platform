# 普通文本回复与控制调用解耦

真实日常任务已经生成三个文件，但最后几轮仅返回正文和文件链接。旧的 NativeTurnDecoder 因缺少 observe/exec/done 拒绝整个回复，触发重复修复；宿主撤掉正文预览，用户看到链接突然消失。

## 行为调整

两种传输都接受没有控制调用的非空普通文本。没有后台工作时，它进入原有完成校验；有执行或子任务时，保留为进度并沿用等待机制。普通文本不会生成工具调用、工具回执或目标完成依据。活动目标仍要求明确依据，领域验收、必需材料、状态更新和取消约束保持有效。空响应、孤立原文、非法参数、截断调用仍走原有协议拒绝。

此入口用于面向用户的答复。内部模型工具必须交付其专用合同要求的结果，不能以普通文字替代上下文整理补丁；Runtime 从既有 tool 身份确定边界，不新增用户设置。真实旧帧的可执行控制头也不能通过普通文本入口被当作完成答复。

Desktop 将控制校验和正文展示分开：已生成的正文与链接保留，不因控制校验失败而消失；任务和工具状态仍由实际回执投影。

## 合同与验证

没有新增公开接口或工具参数。改变的是 INV-88 的普通答复接纳语义，并同步稳定说明、帧尾说明与 README。测试覆盖两种传输的文本、链接、空响应、孤立原文、后台等待、普通任务及暂停目标结束、活动目标完成条件；Desktop 覆盖节流末段、重放和重启保留。

Windows 本机专项 17 项及 Desktop 正文 11 项通过。扩大执行回归时，多项旧用例需要本机不支持的 read-only 进程隔离，返回 SHELL_CONFINEMENT_UNAVAILABLE；没有放宽隔离或将其算作通过。完整 Linux 发布检查由正式工作流执行。
