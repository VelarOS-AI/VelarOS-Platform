# Agent 任务语义

状态：已实现并通过候选消费者验证。版本发布与 Desktop 锁文件升级按跨仓发布流程执行。

本约定贯穿 Desktop 输入、共享 Agent 执行、工具授权、上下文、持久化与 UI 投影。沿用现有会话、目标和执行标识；每项用户操作由同一个 owner 确认其实际结果。

## 从操作到结果

| 层次 | 唯一负责的事实 | 消费者如何判断 |
| --- | --- | --- |
| Desktop 输入 | 草稿、会话与本次执行归属 | 文件准备、登录、预检期间变更归属就保留原草稿；显式目标失效直接失败 |
| 提交控制 | 输入被后端接收 | 布尔结果来自实际准入回执；接收前不清草稿 |
| Agent 执行 | 当前指导、稍后执行、待恢复输入 | `accepted` 与 `input-applied` 分开；事件乱序按输入 ID 合并 |
| 上下文编译 | 本次真正采用的来源、驻留预算与可召回证据 | 来源偏好约束全部入口，媒体费用未知时如实展示 |
| 工具策略 | 可见工具、调用身份、当前授权决定 | 启用与授权分离；主子任务共享授权 owner |
| 工具副作用 | 系统、项目和 MCP 操作的实际结果 | 工具调用必须配对结果；失败恢复先核对实际状态 |
| 收尾与存储 | 执行终态、目标状态、验证事实、存储回执 | 正常返回不推断目标完成或验证通过；停止等待实际收束 |
| UI 投影 | 上述事实的状态和用户可用操作 | 指导、排队、停止、撤销、恢复各有明确入口 |

## 身份与回执

| 标识 | 作用域 | 判断规则 |
| --- | --- | --- |
| `sessionId` | 成员任务及其持久状态 | 输入、上下文、偏好、授权与队列绑定该任务 |
| `executionId` | 一次 Agent 执行 | 主执行与子执行各自有身份，通过父子关系确定任务归属 |
| `runId` / 原生 `turnSeq`、`turnId` | 一轮实际投递和执行 | 迟到输出、结束事件和准备异常只结算原轮；重试创建新的投递身份 |
| `messageId` / Hook `commandId` | 可见输入及重试去重 | 同一请求重试可复用，不能单独作为异步执行的世代标识 |
| `confirmationId` | 一次挂起确认 | 点击携带所见卡片的 ID；界面、Hook、原生引擎和评测驱动均校验同一身份 |
| 授权操作标识 | 任务内的操作对象与范围 | 持续授权由任务授权对象拥有；确认回执只决定相应操作 |

输入接收、输入采用、执行结束、目标完成与验证通过分别记录回执。接收确认不推断其他结果，渲染层消费这些事实。

## 用户输入

- 普通发送在空闲时开始执行，Velar 运行中指导当前任务。另一个明确操作将输入留到当前任务结束后执行；不支持实时指导的原生引擎明确显示排队操作。
- 指导保持当前目标；用户明确更换目标时更新有效目标。查询进度和补充条件属于当前任务输入。
- 接收输入与执行采用输入分别记录。接收失败保留草稿；等待期间编辑的新草稿不被旧请求清空。
- 排队输入保留自己的正文、附件、上下文选择及执行选项。停止或失败后自动队列暂停，由用户继续。已接受输入的恢复状态随会话持久化；尚未提交的草稿队列在当前进程内跨视图保留。真正删除任务释放队列与附件，迟到回执不能复活已删除任务。
- 组件操作与主输入框使用同一提交和队列路径，携带当前模式与技能。等待确认或停止时保留为暂停输入；新操作成功不会自动重试其他暂停输入。Hook 同 commandId 重试以新的 runId 隔离旧准备流程。
- 计划模式由显式选择决定；正文提到“计划任务”或“规划算法”仍按用户原始请求执行。
- 目标持续推进依照用户明确选择和有效目标；普通措辞不改变执行模式。

## 执行与交付

- 运行状态描述执行是否推进；目标状态描述要求是否完成；验证状态描述证据是否通过。三者独立保存和展示。
- 整体回复结束不能把尚未完成的步骤自动改成完成。完成记录对应实际交付、步骤结果和剩余事项。
- 没有执行验证时如实记录，沿用允许正常收尾的规则。已有失败证据继续参与收尾判断。
- 停止请求后显示正在停止；主 Agent、子 Agent 及本次运行的自动推进收束后才显示已停止。
- 后台子作业保留祖先归属，父作业结束或被清理后，取消与等待仍覆盖存活子代。原生连接失效后释放失效连接；恢复仍附着原轮，连接恢复失败保持可恢复日志。
- 停止保留已产生的成果和未执行输入。继续任务根据当前实际状态推进；文件回溯使用独立操作。

## 宿主关闭

执行服务在关闭时同步封闭新准入，以共享完成回执取消并等待已登记的运行。等待范围包括启动钩子、执行本体和结束钩子；启动钩子返回后再次检查关闭态与授权，随后才进入执行。执行存储在所有运行实际收尾后提交并关闭。

系统进程根节点退出后，继承输出仍可能尚未关闭。停止回执等待管道收束或有界清理结果；清理无法确认时保持未知状态，保留 cleanupIncomplete 证据。

## 授权

- 拒绝仅跳过本次操作，并把理由交给 Agent 决定替代路径；停止任务使用明确停止入口。
- 已拒绝的同一操作在当前任务内保持拒绝，直到用户修订授权或操作范围发生实质变化。
- 低风险和用户明确授权的操作继续执行。需要确认的调用说明操作、对象、发起任务与授权范围。
- 每次确认都要求所见卡片的 `confirmationId`；缺失、过期和乱序回复不能批准新的操作。挂起查询返回该身份，旧界面需刷新并由用户重新点击。
- 已授予的任务权限可以查看和收回。执行前检查最新授权；主子 Agent 遵循同一确认策略。
- 删除任务同时销毁共享授权对象，旧主执行、子执行、续跑执行和迟到审批结果均不能重用或重建旧授权。
- 工具启用只改变指定 Agent 的可用工具；授权决定独立于工具启用。
- 显式自动批准设置维持其已定义的作用域。

## 上下文与记忆

- 本轮参考记录实际采用的来源，包括发送时与运行中加入的来源。
- 单次忽略只作用于本次输入；本任务暂停来源会约束后续自动附加，并能恢复。
- 会话分别决定是否使用已有记忆、是否保存本会话。默认继承现有全局设置。
- 当前目标和有效约束使用既有 active context 状态。用户修订更新这份状态；压缩和交接消费同一份有效状态。
- 交接携带目标、有效约束、未完成步骤、证据引用与来源偏好；跨会话引用必须可解析。
- 交接只继承目标任务未主动改动的偏好字段；复制期间用户关闭来源、修改保存/使用记忆或恢复默认，均优先保留用户的新选择。
- 真删除先封闭上下文写口；排队写入与同步保存遵循同一世代，迟到目标或约束更新不能重建已删除文件。
- 常规压缩保持连续执行；显式交接沿用用户批准流程。

## 验收场景

| 用户操作 | 必须观察到的结果 |
| --- | --- |
| 运行中发送“先只分析” | 输入进入当前任务指导通道，收到接收/采用结果 |
| 选择稍后执行并发送 | 原任务继续，新输入保留在队列 |
| 发送因预检或准入失败 | 正文和附件可继续编辑或重试 |
| 点击停止 | 先进入正在停止，收到后端收束结果后终止，队列保持暂停 |
| 停止后继续 | 保留已发生的修改和未完成目标，从实际状态恢复 |
| 拒绝工具并附替代要求 | 该工具未执行，理由进入后续决策，其他工作可继续 |
| 撤销已授予权限 | 后续主子 Agent 调用按最新权限判断 |
| 回复结束时仍有未完成步骤 | 步骤保持真实状态，交付明确剩余事项 |
| 修复计划任务报错 | 计划模式保持用户所选状态 |
| 暂停自动上下文来源 | 后续本任务的发送与运行期均遵守该偏好 |
| 关闭保存本会话 | 采集停止，已有记忆是否可用由另一个会话选择决定 |
| 交接长任务 | 新会话读到当前目标/约束和可解析的关键证据 |

## 所有权

Platform Agent 拥有输入、授权、执行和目标的共享契约；Memory 拥有召回与采集；Desktop 拥有用户操作、会话偏好和持久化适配；UI 依据事实渲染状态。模式、审批和完成规则不在多个入口重新推断。

## 消费者升级

- Agent 新增 `input-applied`、`stopping`、审批操作详情和输入状态；穷举事件、状态与详情的消费者必须同步分支。现有公开导出保留，新增字段按可选契约提供。
- Desktop 内部发送 API 返回真实 `Promise<boolean>`；调用方按准入结果消费草稿。取消 API 返回后端收束回执，UI 不用固定延迟推断停止。
- 确认 ID 字段在声明层为可选，运行时的新卡回复要求精确身份。升级时需同步 UI、IPC、Hook CLI（`--confirmation-id`）及 Agent Lab 驱动，禁止自动把旧回复补成当前卡身份。
- 原生中断确认超过 15 秒或传输失效时，报告无法确认停止并保留恢复日志；请求确认与执行终态分别处理。
- 记忆写事务一旦进入 backend，其既有事务语义继续成立；用户关闭保存约束后续新写入。图片和文档的模型费用仍需供应商计量元数据，目前标记为未知。
