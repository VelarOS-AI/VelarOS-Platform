# ScriptAct 文本协议：设计复核与执行约束

状态：正式实现已接入现有 Platform 主链。实现细节与验证见 `../engineering/scriptact-text-protocol-delta.md`。

主模型维护观察程序，并提交一次性执行程序。Runtime 负责程序版本、调度、能力边界、操作回执及下一轮可见材料。AI SDK 继续承担模型供应商适配、流接收、用量和多模态消息传输。

本文补齐文本协议、多执行块和后台运行接入时的边界。既有 ScriptAct、Kernel 权限与 journal、ContextStorage、ProviderRequestCompiler 是实现基础。

## 1. 普通 Markdown 与独立闭合的控制段

模型可以在普通 Markdown 中穿插原文材料、观察程序和执行程序。每段有明确的起止边界，段前、段间和段后都是可直接流式展示的 Markdown。

宿主为每个模型帧提供一个保留标记，例如 `@@s7f3a9c2d`。该字符串是协议文本，不是供应商特殊 token；实际标记由宿主生成并写入本帧说明，协议修复沿用本帧标记。版本、注册表和标记都随请求固定。

控制头是独立一行的 `标记 + 空格 + 函数调用形式的声明`。有载荷的声明以独立一行、仅包含同一标记的尾行闭合。段之间不嵌套，也不以新段的开始隐式结束上一段。控制头保持单行并受长度限制。

无参声明允许省略括号：`done` 与 `done()`、`execute` 与 `execute()`、`observe` 与 `observe()` 分别等价，统一归一成相同名称和空参数列表，再按注册表校验。只有协议标记之后启用这条规则；正文里的同名词语属于普通文字。声明需要必填参数时仍须提供，例如 `blobs("payload")`。

| 内置声明 | 用途 | 边界与数量 |
| --- | --- | --- |
| `blobs("名称")` | 承载具名原文，自动注入 `velaros:program` 的 blobs 对象 | 有载荷并显式闭合；同一响应内名称唯一 |
| `observe` / `observe(options?)` | 更新每个新业务回合运行的观察程序 | 有载荷并显式闭合；一份响应至多一个 |
| `execute` / `execute(options?)` | 提交一次性程序 | 有载荷并显式闭合；可多个，执行身份与回执各自独立 |
| `done` / `done()` | 申请完成当前任务并停止自动循环 | 单行、无载荷；一份响应至多一次 |

声明名称、参数、载荷格式、数量限制和使用说明来自同一份宿主注册表。外层函数形式只用于解析控制声明，参数限定为可校验的字面量；不执行头部表达式。普通 Markdown 的语言标签不参与调度；控制头遇到未知名称或参数返回协议错误。能力被撤销时，执行前仍需重新检查权限。

`execute()` 默认顺序等待；`execute({ async: true, retain: 2 })` 表示后台提交并设置结果曝光次数。`retain` 接受 1–32 或 `'task'`；主任务默认 2，搜索默认 task。宿主协议配置通过 allowed 限定入口、defaultRetain 设置默认租期。小参数使用 options.input，宿主参数使用 options.inputRef，二者互斥。程序载荷默认直接是 JavaScript，原样交给现有检查与执行器。

下面是协议示例，帧标记由宿主动态提供。Markdown 代码围栏在正文中仅用于展示。

````text
我先准备原文。下面是普通代码示例：

```javascript
const limit = 20;
```

@@s7f3a9c2d blobs("payload")
const message = `Hello, ${name}`;
console.log(message);
@@s7f3a9c2d

这段原文将作为数据提供给脚本。

@@s7f3a9c2d execute()
import { blobs } from 'velaros:program';
import { output } from 'velaros';
output(blobs.payload);
@@s7f3a9c2d

这里继续输出普通 **Markdown**。
````

`blobs("payload")` 中的原文可以是任意用途的文本。Runtime 自动绑定到本响应程序的 `blobs.payload`，无需模型声明引用映射；只作为数据传入，不拼接到 JavaScript 源码。协议标记行是原文的保留边界。

仅含标记的尾行只结束当前段。API 正常结束事件确定整条模型响应的结束。`done()` 表达业务完成请求，三者分别处理。请求身份、帧身份、执行身份和权限上下文由宿主维护。

## 2. 流式分流、整份检查与派发

传输层持续提供原始文本片段。装配层的协议接收器分流为正文增量和程序预览；前端分别用 Markdown 与代码组件展示。该分流不解析 Markdown AST，不递归解析正文里的代码围栏，也不对 JavaScript 作 JSON 字符串反转义。

在正文区，仅在行首暂存可能匹配保留标记的短前缀。前缀不匹配便立即原样发送；完整匹配后，继续缓冲并解析这一行控制头。有载荷的声明进入段内状态，匹配尾行后恢复正文状态。`done()` 是单行声明。任意网络分片、CRLF、Unicode 和半个标记都不能导致标记泄露到正文或漏识别。头行缓冲有明确上限。

控制区的原始程序也可以逐段预览。完整接收所有记录和正常结束事件后，才验证全部记录与程序，持久化接受记录及派发占位，然后按序调度。预览本身不授权任何脚本执行。

- 每个有载荷的段必须显式闭合，并收到供应商正常结束事件。正常 finish 不能补齐缺失的段尾；截断、传输中断、超长响应均不授权执行。
- 不把结束标记配置成会剥除标记的供应商 stop sequence。
- 任意类型、字段、参数引用、程序检查失败，整份响应不派发，观察指针不更新。检查失败的程序可沿用现有草稿保存机制。
- 已显示的正文保留为模型文字，运行状态单独显示为接收中、校验失败或实际执行状态。正文声称成功不代表操作已经发生。
- 静态检查不运行用户代码。模块导入检查不得通过执行模块顶层代码获取信息。
- 全部预检通过不代表未来的资源和权限保持不变。每个操作派发前重新校验自己的前提。
- 观察版本发布及执行占位复用现有 CAS。外部效果以逐操作回执为准，无法合成跨文件、网络和终端的全局回滚。

分流器在正文与段内两个主状态间切换，另记录完成请求。头部接受单个声明名称或函数调用形式；前者按空参数列表处理，后者读取名称和字面量参数。拒绝额外语句、动态表达式及重复选项。尾行按整行的完整保留标记识别，前缀大小写和前导空白不自动纠正。正文状态出现孤立尾行、段内出现另一条控制头均报错，防止缺尾导致后续段被吞并。头部、载荷和整体响应分别有预算。

载荷从头行换行之后开始；尾行前紧邻的一次换行属于分隔边界，其他字符和换行原样保留。需要让原文自身以换行结束时，在尾行前增加一个空行。空段的载荷为空字符串。解析器不 trim、改缩进或解释载荷里的反斜杠、反引号及模板插值。流式预览保留必要的边界候选缓冲，以免先输出分隔字符再回删。

每帧标记降低与普通文档意外重合的概率，但不是安全凭证。完整的控制头行和尾行始终是协议保留内容，即使它位于 Markdown 围栏或 JavaScript 模板字符串内。展示协议用固定示例标记；JavaScript 确需构造当前标记时可拆开字符串拼接。需要任意文本逐字保真且绝对无边界冲突时，必须另用带外通道或明确的转义、长度机制；单一文本流无法同时省略这些条件。

只分流当前主模型的响应。用户正文、工具返回、历史引用和附件内容不会重新送入控制解析器；实际执行继续经过 Kernel 权限与效果检查。

协议修复得到定位到块、行和属性的诊断。修复次数和实际模型用量有共享上限；同一帧的纯协议修复使用原帧，避免重跑观察造成基线漂移。需要重建材料时显式发布新帧。

## 3. 顺序、依赖和局部变量

两个执行块依次运行，只保证前一个结束后才开始后一个。模型生成这两个块时尚未看到中间结果。

- 需要程序消费前一步返回值时，优先放在同一个脚本里用 `await` 串联。
- 需要模型判断返回值时，结束本次执行，下一轮把结果发给模型。
- 不同执行块有独立的局部变量和执行环境。共享材料使用显式存储引用或能力模块。
- 后台块完成受理后，后续块可以继续；后续同步块不隐含等待此前全部后台任务。
- 两个后台块按原文顺序受理，实际运行受并发额度约束，完成顺序不保证。

每个脚本的返回结果只包含已完成输出和明确的未完成状态。脚本内部的未等待 Promise 不自动升级成独立持久任务；延续既有 ScriptAct 的未结算操作检查。

同步块失败时停止本响应尚未派发的后续执行块。后台失败发生时，后续操作可能已经开始；停止尚未派发的块，向本批在途任务请求取消，按真实回执报告已经完成、部分完成和未知效果。取消请求本身不证明外界操作没有发生。

## 4. 后台任务由任务运行管理器持有

模型调用、一次脚本运行、用户任务和会话具有不同的生命周期。

- 一次模型响应结束不会终止已受理的后台任务。
- 后台任务有独立 `executionId`、父任务及目标版本、输入快照、权限范围、取消信号、执行时限和回执。
- 用户取消任务或关闭会话时停止新派发、请求取消在途运行，并保存未能核实的效果。
- 用户补充或改变目标后，旧任务只能更新自己的回执，不能覆盖新目标的完成状态。
- 管理器负责执行所有权续期。续期失败的实例停止新派发；已经发出的远端操作仍需核对。
- 并发任务共享任务总预算，包括模型、执行次数、并发数、时间和输出存储额度。

同一任务的主模型回合保持有序。后台结果可以并发到达，但只在下一次构帧时加入；不会修改已经发出的模型请求。

没有可推进的前台工作时，主循环等待任务事件、用户输入或截止时间。事件合并后唤醒模型；不通过反复询问“完成了吗”轮询。存在在途执行时，纯进度正文允许等待任务事件。没有在途任务的工作响应必须提供控制决策；缺少决策进入有界协议修复。需要用户输入时显式调用 interaction，未知效果继续待核对。

`done()` 声明之后允许继续输出给用户的 Markdown，不允许再声明控制操作。整份响应正常结束并通过校验后，Runtime 检查当前目标版本、必需执行、未知效果及领域验收结果；通过后保存完成状态并停止自动调用模型。等待后台任务时保持事件等待，条件不满足时提供明确反馈。没有领域验收器时可记录模型声明完成，验证状态仍为 unverified。

## 5. 结果租约只消耗实际展示过的材料

每个发出的模型帧持久化一份实际投递清单：结果引用、内容表示、附件引用、观察版本、输入版本及截断情况。有效模型响应确认该帧后，幂等地消费清单内结果的一次曝光额度。

例子：

1. 帧 F10 发出时，后台任务 J 仍在运行。
2. 模型思考期间，J 完成，产生 `retain=1` 的结果 R。
3. F10 的响应被接受，R 不在其清单内，不扣减。
4. F11 实际带上 R。F11 的有效响应被接受后，R 退出自动展示。

每个结果以选定的正文或切片及其必需附件作为一次投递单元。仅发送引用、因预算跳过正文或缺少必需附件时，不扣减该结果的曝光额度。发送切片必须标明范围和截断；省略可选附件也必须标明。投影器不能通过只保留引用来假称正文已投递。

结果曝光额度、任务执行所有权有效期、底层存储保留期各自管理。正文退出自动展示后仍可按引用召回；程序运行状态、未处理失败和未知效果由任务状态管理，不能随正文租约消失。

新结果不能无界积压。预算不足时提供可见的缺口和可召回引用，限制新任务受理，必要时进入明确的上下文受阻状态。

## 6. 参数数据与代码分别保存

小参数直接使用函数参数中的 input，例如 `execute({ input: { limit: 20 } })`。宿主注入或已经保存的大材料使用 inputRef，例如 `execute({ inputRef: "host:report_args" })`。头部只保存引用时，实际数据由 Runtime 按访问范围读取。

具名原文由 `blobs("名称")` 声明，收齐并校验本响应后统一绑定，因此声明位置不影响引用解析。原文名称在本响应内唯一，绑定使用精确键值；与其他显式注入的同名材料冲突时拒绝，不静默覆盖。观察版本和执行记录保存实际绑定的材料快照，不依赖本次响应的临时名称在以后仍然有效。

- 参数引用使用明确的命名空间，避免宿主绑定与持久记录混淆；本帧展示的宿主引用绑定固定数据版本。
- 稳定观察安装或后台任务受理之前，参数解析成不可变快照并与程序版本一同持久保存。下一轮不依赖上一条响应内的别名仍然存在。
- 同一次执行读取固定快照；宿主后续修改参数产生新版本，不改变在途运行。
- 共享输入快照不可变；脚本可以创建自己的可变工作副本。
- 对象数据通过 `input`，附件通过 `blobs` 或既有附件引用，函数和服务通过能力模块注入。数据不插值进入源码。
- 宿主引用必须经过会话范围与访问检查。凭证通过能力的凭证机制使用，避免进入会被渲染和审计的普通参数正文。

程序、参数、模块包和附件形成显式引用关系。观察仍在使用、执行仍在运行或版本仍需恢复时保留对应对象；结果租期到期不触发这些对象的级联删除。

## 7. 稳定观察要能够修复和退出

`observe` 是下一业务回合生效的程序更新，不在块出现的位置立即执行。

- 省略表示保留；必须提供明确的清除操作，不把空响应或省略误判成卸载。
- 全量源码、`sourceRef`、精确 `edits` 以及程序的 `modules`、`input`、`blobs` 沿用同一份程序合同。协议注册表声明载荷形式，不把能力收缩为只能重写单文件。
- 编辑绑定模型实际看到的底稿版本；基线改变时返回冲突和当前引用。
- 新业务帧运行一次观察。相同帧的传输恢复和纯协议修复不重复运行观察。
- 观察失败时发送本轮失败信息、源版本和必要诊断，让模型能够修复或清除。历史成功结果如被展示，必须标为历史，不冒充当前观察。
- 时间、输出和成本有界。频繁变化不自动产生无限重试。

观察通过同一 Kernel 检查能力效果，禁止管理后台任务、续租结果和修改稳定状态。受限命令执行继续报告真实的隔离覆盖；通用命令的绝对无副作用无法保证，不能靠模型注释、名称或静态推断作出承诺。一次性执行保留实际操作能力。

## 8. 请求内容固定，外界状态仍会变化

帧固定的是已发给模型的证据、时间和版本，不是把外部世界冻结。

- 模型思考期间发生的资源变化在下一帧报告；相关写操作先核对自己的版本前提。
- 同一受控资源的冲突写入按领域锁、版本条件或串行调度处理。
- 对影响范围不明的通用命令，按其工作区或宿主边界保守调度；隔离执行空间可以提高并发度。
- 观察跨多个数据源不天然具有原子快照。发布前验证可验证的版本，无法验证的一致性如实标记。
- 无关后台任务完成不应使所有请求无条件失效；校验目标版本、观察底稿和实际依赖的资源。

源码变化和运行结果变化分别生成 diff。差异可以说明进展；若要求依靠 diff 还原当前内容，本次请求必须包含对应基线。否则展示原文、切片或明确缺口。

## 9. 重试与真实效果

接受身份由持久请求、响应和块序号确定。相同身份再次送达，返回已有受理记录；同一响应里两段相同代码属于两个独立执行意图，不能按源码 hash 去重。

派发前持久占位。恢复时区分确定尚未派发、已完成、已派发但结果未知。未知效果使用 Kernel journal 与领域核对器查询，不自动重跑整个脚本。外部幂等键仅在能力明确支持时使用。

协议错误回执可以声明 `executed:false`；执行阶段错误必须给出真实已派发情况与效果。消息文字不是成功凭证，UI 的执行状态以 Runtime 回执为准。流式文本若提前展示，标为尚未验证的输出。

## 10. 上下文预算、多模态和模型输入

继续由 ProviderRequestCompiler 编译并核算最终发送的同一份请求，包括系统说明、协议定义、当前代码、观察输出、任务状态、结果正文、图片和预留输出空间。

- 必须显示目标、当前程序身份、执行状态和必需故障；普通材料按预算切片并保留引用。
- 输出过大时保存原件，发送明确的截断与召回信息。若必需状态都无法容纳，停止正常执行并提供有界维护反馈，不能静默丢失目标继续工作。
- 对重复程序、重复错误、重复结果保留有界进展信息；无进展时提示模型修复，超过任务预算后交还控制。
- 模型看到直接可读的材料，内部存储仍用结构化记录；避免把 JSON 字符串再放入多层 JSON 正文。
- 用户上传图片和能力返回图片都使用真实多模态附件。发送清单关联图片与其来源；图片未送达时明确反馈。
- 宿主 `submit` 需接受文字与附件组合，并允许仅附件输入；兼容现有文字调用。
- 供应商或模型不支持某种附件时显式报告，不能用图片路径文字假称模型已经看见图片。

高级搜索通过 execute 中的 `velaros:search.search` 按需调用，使用共享 ScriptAct 协议与增量历史。协议、执行和上下文策略分别通过 ActProtocolPort、ActExecutionPort、ActContextPort 接入；模式相关的容量、租约与恢复规则见 [context-management.md](./context-management.md)。
