# 长程上下文

Context 保存原始输入、程序、执行回执和派生展示；Runtime 在每次请求前按模型容量组装当前视图。主任务、搜索与业务子任务共用这一链路，当前合同见 [Runtime README](../../packages/velaros/act/runtime/README.md) 和 [Context README](../../packages/context/README.md)。

## 请求与历史

稳定说明包含执行环境与所选协议。任务、工作区、观察、近期历史和运行状态分别组织；原始输入保留独立来源，派生摘要带版本与证据引用。模型实际看见的文本和图片由 Model 请求编译器编码，内部统计保留在宿主状态中。

活动历史段按接纳顺序追加，已发出的请求保持原样。封段后形成可召回的历史卷与目录，当前请求保留必要近期记录和引用；完整原文仍在存储中。会话缓存键、供应商缓存断点与实际命中用量由 Model 适配器处理，缓存命中不代表资料仍有效。

## 容量与整理

Runtime 根据模型容量、输出预留、实际用量及剩余可用轮数控制历史封段。封段本身不要求模型总结。显式整理、结构性超载、供应商超窗拒绝以及需要叙事的历史卷，按各自边界触发整理；每次请求都计入共同预算。

自动封卷优先把原始需求、当前事项和整卷材料交给有界结构化调用，生成本卷事实、新增未解事项和失败尝试。材料超过请求容量时使用交互式分页整理。交互式整理固定卷边界，目录只展示该边界内的材料，原始用户要求独立提供。

派生内容发布前核对来源、完整性、版本和容量。关闭已有事项需要对应卷内完整可见的真实执行见证及唯一原文引文；用户约束和未提及事项继续保留。叙事与事项原子发布，取消、失败或迟到结果不能覆盖当前状态。

## 观察与执行结果

观察脚本保存稳定版本，每个业务轮采集当前事实。只有宿主能覆盖完整数据依赖、授权和 ABA 变化的可靠代次，才可复用结果；无法确认时重新采集。Node 原生 I/O 是否被完整覆盖由宿主端口声明。

执行结果按租约曝光，生命周期可按次数、历史段或任务设置。后台完成保存真实结果，不改写已经发出的帧；下一帧按身份投递，接纳后再确认相同租约的曝光。引用、精确编辑与原文绑定见 [结果租约](script-context-leases.md) 和 [程序编辑](script-incremental-edit.md)。

## 计量与验收

保留每次请求的来源、输入输出用量、缓存读写、失败和未知值。模型整理、复核与子任务各自留账，汇总时按真实请求身份去重。用户要求、已交付产物、未完成事项和外部效果事实分别保存；上下文压缩不能改变授权或将未知效果写成成功。

相关行为由 Runtime 的上下文、封卷叙事、观察租约、取消和恢复测试，以及 Context 的存储和核查测试覆盖。长期运行收益通过冻结任务、完整费用和独立验收评估，见 [评测规范](../engineering/scriptact-acceptance-criteria.md)。
