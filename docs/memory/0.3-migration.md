# Memory 0.3 migration

`0.3.0` removes the product-domain DTOs previously borrowed from Kernel Core.
There are no compatibility aliases.

## Knowledge runtime

Replace `configStore` with an injected embedding runtime port:

```ts
createKnowledgeRuntime({
  embeddingConfig: {
    resolveEmbeddingRuntime: () => ({
      provider: modelHost.embeddingProviderId(),
      model: modelHost.embeddingModel(),
      apiKey: modelHost.embeddingCredential(),
      baseURL: modelHost.embeddingBaseURL(),
      configured: modelHost.isEmbeddingConfigured(),
      providerLabel: modelHost.embeddingProviderLabel(),
    }),
    isManualEmbeddingAllowed,
    isAnswerEmbeddingAllowed,
  },
  indexingPolicy: {
    shouldIncludeEntry: ({ name, isDirectory, relativePath }) =>
      workspaceVisibility.canIndex({ name, isDirectory, relativePath }),
  },
  // existing database, storage, HTTP, request-factory and code-intelligence ports
})
```

The removed `KnowledgeEmbeddingConfigStore` no longer accepts model manifests,
provider runtime config arrays, chat provider selection, or Kernel environment
variable conventions.

Use Knowledge-owned public types instead of Core types:

- `KnowledgeIndexStatuses`, `KnowledgeMatchTypes`, `KnowledgeIndexConfig`
- `KnowledgeRecord`, `KnowledgeSearchResult`, `KnowledgeDiagnostics`
- `KnowledgeEmbeddingProviderId`, `KnowledgeEmbeddingRuntime`
- `KnowledgeCodeSymbol` and the `KnowledgeCode*` port DTOs

## Memory scope

Import `MemoryScopeId`, `GLOBAL_MEMORY_SCOPE`,
`buildProjectMemoryScope`, `buildSiteMemoryScope`, and
`scopeTypeForScopeId` from `@velaros-ai/memory`.

The Kernel adapter no longer resolves System/Project/Browser context. Inject:

```ts
mountMemoryAdapter({
  domain,
  idleSignal,
  config,
  hostContext: {
    turnContextScopes: productScopeIds,
    resolveScope: ({ sessionId, workspaceRoot, contextId }) => ({
      scopeType: 'workspace',
      scopeId: `project:${workspaceRoot}`,
    }),
    environmentContextBlockOpenTag: '<environment-context>',
  },
})
```

`MemoryEvidenceBridge` accepts `MemoryHostUserMessageEvent` and
`MemoryHostSessionSnapshot`. Hosts must normalize their Chat/session storage
objects into these small contracts before capture.
