## 需求背景

当前 Memory 页把记忆展示成关系图和时间图，但这两种图都只是在已有记忆记录上做可视化，无法表达 VelarOS 长期成长为个人 AI 系统的产品目标。

用户希望 VelarOS 的记忆不是静态记录，也不是若干孤立节点，而是一棵会随着长期使用逐渐成长的树：

- 树有根，所有结论都能回到真实来源。
- 树有主干，记录 AI 在长期使用中形成和改变的自我认知。
- 树有枝条，项目、任务和沟通经历持续塑造这条成长轨迹。
- 树会演化，能够看到一项任务从过去到现在的完整过程。
- 树会整理，VelarOS 在用户空闲时主动归并、压缩、修剪和维护记忆。
- 树最终成为每个用户自己的 AI 系统，而不只是模型调用时附带的一份上下文。

## 产品北极星

VelarOS 要从“每次调用一个模型”成长为“持续理解同一个用户、同一批项目和长期任务的 AI 系统”。

记忆树是这个成长过程的核心产品载体。后续项目记忆、任务记忆、用户画像、兴趣、偏好、方法、主动建议、任务恢复和个性化能力，都需要在同一根基上生长，不能继续建设彼此独立的记忆模块。

## 已明确的硬需求

以下内容来自用户的明确要求，后续方案不得悄悄改变。

### R-001：Memory 页只保留一棵树

- 删除“关系 / 时间”双视图。
- 不再保留独立关系图或时间页。
- 时间和关系都由树本身及树的交互状态表达。
- 页面不是旧图的换皮，底层数据结构也必须围绕树的成长重构。

### R-002：树必须有根、主干、枝条和生长过程

- 根代表记忆为何存在，必须能够回溯来源。
- 主干代表 AI 的成长轨迹与记忆主干，不代表用户人生，也不代表当前某一个任务。
- 主干由一段段身份时期组成，记录 AI 曾经如何理解“我主要在为用户做什么”。
- 枝条代表项目、任务、沟通、成果和失败等具体经历。
- 用户画像、兴趣、偏好和方法更像营养信号，持续影响枝条权重、主线提炼和身份变化，而不是默认占据可见主枝。
- 新的任务、沟通和操作会逐渐形成芽点、叶片或新的分支。
- 树的变化要体现真实数据变化，而不是每次打开页面重新随机排布。

### R-003：所有长期记忆进入同一棵树

树至少需要容纳：

- 项目记忆。
- 任务记忆。
- 用户画像。
- 用户偏好。
- 用户兴趣和持续关注主题。
- 用户对 Velar 工作方式的纠正和反馈。
- 可复用的方法、习惯和流程。
- 每次任务与沟通中形成的关键经历、决策和结果。
- 未来其它在 VelarOS 中被授权收集的长期信息。

这些内容不能继续由多套独立摘要或缓存分别维护。它们都会进入同一记忆系统，但不要求在视觉上拥有同等层级：项目和任务主要成为经历枝条，画像、兴趣和偏好主要成为塑造整棵树的营养。

### R-004：任何时刻只形成一条全局主线

- 无论用户同时进行多少个项目和任务，树在当前时刻只突出一条全局主线。
- 全局主线不一定等于活动次数最多的单个任务，而是对当前全部重要经历的更高层概括。
- 即使任务表面上毫不相关，系统也应尝试提炼用户此刻主要把 AI 塑造成什么角色。
- 重复最多、持续最久、产生重要结果且被用户反复依赖的能力，会逐渐成为 AI 身份的核心。
- 同一任务暂停后再次进行，应沿原分支继续生长，并继续为全局主线提供证据。
- 不能仅靠标题或向量相似决定主线；需要综合目标、时间、项目、执行、产物、反馈、频率、持续性和用户确认。
- 证据不足时可以使用更宽泛、更低置信的主线描述，但不能同时展示多条竞争主线。

### R-005：AI 身份能够发生阶段性跃迁

- AI 对自己的认知不是静态配置，也不是用户手写的一段 persona。
- 早期数据很少时，AI 可能把自己理解为“主要帮用户完成某一类任务”。
- 随着任务和经历积累，它需要重新概括自己的角色，形成更高层、更综合的身份理解。
- 当证据积累达到阈值时，身份可以出现明显的阶段变化，体现“量变产生质变”。
- 身份变化不能覆盖历史；旧身份成为主干下方的历史段，新身份从其上继续生长。
- 当前身份必须能解释它由哪些长期重复经历、关键任务和用户反馈形成。
- 这里描述的是 AI 的可追溯自我模型和产品成长感，不宣称模型拥有真实意识。

### R-006：点击节点可以查看完整历史演化

- 点击任务、分支或关键记忆后，显示它从起因到当前状态的完整路径。
- 分支在树上的原始连接关系必须保留，不能脱离主干变成独立页面。
- 点击后枝条在原位舒展、放大并显示更多层级，其他区域降低视觉权重。
- 需要看到关键阶段，例如起因、调研、决策、执行、验证、反馈、修正和当前状态。
- 相关旁支可以接入主线，说明某个决策或变化从哪里产生。
- 暂不采用横向历史时间线；时间和发展历史必须融入枝条自身的生长路径。

### R-007：支持选择时间范围

- 用户能够查看某一段时间内树如何生长。
- 时间范围用于强调新增、变化、合并和修剪，不切换到另一种产品模型。
- 用户能够回看历史版本，但历史状态只读。
- 历史回看必须展示当时真实提交的树形快照，包括当时的 Identity Epoch、主线判断、分支结构和可见记忆，不能以今天的树形隐藏未来节点来伪装历史。
- 从历史快照回到当前时，可以沿版本差异重新播放树的生长，使用户看到 AI 的认识如何一步步演进。
- 已裁决的历史保留粒度：最近一年保留全部细粒度树版本；更早的历史降采样保留月度快照、重大成长阶段（Identity Epoch 变化）与重要主枝变化。被降采样合并的中间版本不再承诺可访问，年轮在远古区段相应显示更粗的刻度，远古区段的生长重放以保留粒度为准。
- 降采样不削弱 R-006：单个任务或分支的完整演化视图由语义层（Episode / Claim / Relation）承载，不依赖树版本链，不受历史版本降采样影响。

### R-008：VelarOS 需要“记忆生长”能力

- VelarOS 在用户长时间空闲、设备资源允许时自动整理记忆。
- 设备真正进入系统睡眠后不要求继续运行；“用户睡眠时”指用户不再操作而设备仍可执行后台任务。
- 后台整理不是普通用户定时任务，也不是一条固定 prompt。
- 整理过程需要识别全局主线、更新 AI 自我模型、建立关系、合并重复、压缩历史、处理冲突、修剪低价值信息并更新树。
- 整理过程必须可暂停、可取消、可失败回滚。
- 每次整理生成一个明确的新树版本，而不是直接在当前树上留下半完成修改。
- 记忆生长分为即时整理、空闲整理和深度生长三级；三者共享同一套 Evidence、谱系、版本与提交契约。
- 即时整理在会话或任务稳定结束后处理脱敏、最小 Evidence 和候选索引，不改变 AI 身份。
- 空闲整理在用户离开且设备资源允许时关联任务、合并重复、更新分支、权重和冲突。
- 深度生长在更长空闲窗口运行全局主线综合、历史压缩、重要主枝重组和 Identity Epoch 跃迁。
- 默认使用智能调度，不要求普通用户理解或配置三级流水线；高级设置只暴露必要资源偏好和手动控制。
- 三级整理默认携带 token 预算档位（如每日上限），对所有用户生效以约束 BYOK 成本；普通用户无感，高级设置可调；后台整理消耗额度这一事实由产品级隐私/使用协议覆盖。

### R-009：树需要逐渐成长，而不是一次性生成

- 新用户最初看到幼苗或很小的树。
- 新信息先成为待整理芽点。
- 稳定证据积累后才成为枝条或主干的一部分。
- 后台整理完成后展示真实的生长差异。
- 已看过的生长动画不重复播放。
- 树不能因为模型每次输出不同而频繁换形状。

### R-010：任何结论都必须可解释

- 用户画像、项目结论、任务状态和偏好都能查看来源。
- 系统必须区分用户确认、直接观察、归纳和模型推断。
- 模型推断不能伪装成用户明确事实。
- 发生冲突时不能静默覆盖；需要保留版本、冲突或待确认状态。

### R-011：用户能够治理自己的树

- 查看来源。
- 纠正结论。
- 对信息执行“忘记”，降低其权重和可见性。
- 在设置的隐私治理区对具体记忆执行受限的“彻底清除”（确定性加密擦除，语义见 R-021）。
- 固定分支或命名。
- 合并或拆分错误分支。
- 排除某个项目、会话、站点或来源。
- 标记“这次不要记住”。

### R-012：记忆聊天属于树

- 记忆页保留聊天入口。
- 可以询问项目历史、任务主线、用户画像和结论来源。
- 回答需要引用树路径和证据。
- 修改请求先成为结构化提案，不能让聊天模型直接修改树。

### R-013：页面保留已确认的交互约束

- “记忆”标题位于主内容顶部。
- 搜索按钮位于标题右侧，点击动画展开。
- 右侧详情面板不常驻，点击节点后从右侧出现。
- 右上角操作固定，不随右侧面板移动。
- 记忆聊天框使用与侧栏记忆入口不同的图标。
- 树节点不使用明显边框。
- 颜色遵循 VelarOS 主题，不照搬之前的彩色图谱。

### R-014：允许破坏性重构

- 当前没有生产用户和需要保留的用户记忆。
- 数据库、表结构、类型、IPC 和页面可以重新设计。
- 不需要旧记忆数据迁移。
- 不需要旧 `MemoryRecord`、旧 API、旧图页面的兼容层。
- 不做新旧双写或长期适配。
- 本轮先写文档并继续讨论，不开始实现。

### R-015：未来可选云端保护

- 记忆树第一阶段完全本地运行，本地数据库是权威副本。
- 为防止设备损坏、丢失或重装导致记忆树永久消失，未来可以接入 VelarOS 云端数据库。
- 云端能力是用户主动选择的付费增值服务，不是使用记忆树的前置条件。
- 已拥有树可视化 entitlement 的用户即使不开通云端保险库，也能完整使用本地记忆树。
- 云端的首要价值是加密备份与恢复，后续可以扩展多设备同步。
- 云端不能接管本地记忆推理，也不能让离线状态下的树不可用。
- 本阶段只记录产品愿景和架构边界，不实现云数据库、同步、计费或 UI。

### R-016：当前采集边界是应用内部与 Computer Use 观察

- 第一阶段只使用 VelarOS 应用内部产生的数据，以及 Agent 通过 Computer Use 在执行任务时明确观察到的信息。
- 应用内部包括对话、任务、Goal、Execution、工具调用、Workbench、内置 Browser、记忆纠错和用户操作。
- Computer Use 只记录任务执行中实际看见并被记忆策略选中的最小证据，不等于持续录屏或后台监控桌面。
- 未来可以通过外部应用连接器或新的观察能力扩展来源，但每种来源都必须单独定义权限、最小采集和排除策略。
- 第一阶段不接入未被 VelarOS 或 Computer Use 明确观察到的外部应用数据。

### R-017：所有用户使用同一套默认开启的自动记忆

- 普通用户、年度用户和永久用户都使用同一套自动记忆与 MemoryDream。
- 自动记忆对所有用户默认开启。隐私知情由产品级隐私协议在用户使用产品之前一次性覆盖——记忆能力（含敏感生活类别与后台整理消耗模型额度）属于该协议范围；应用内不再单独设首次启动记忆告知门。
- 自动记忆的运行态只有两个：`enabled`（默认）和 `disabled`（用户在设置里关闭）。不设 `pending_notice` 中间态，也不记录应用内告知确认时间——采集从首次使用即开始。
- 用户仍可随时关闭自动记忆、降低现有记忆权重或排除具体来源。
- 关闭后停止采集新的长期 Evidence；是否保留已有树由用户选择。
- 不建设“免费版记忆”和“付费版记忆”两套系统。
- 普通用户的隐藏树同样参与 AI 召回和身份演进，只是不展示产品页面。
- 年度与永久 entitlement 只控制记忆树是否可以被看见，不控制底层是否生长。

### R-018：树成熟后才揭晓

- 即使自动记忆已经默认启动，也不会立即展示一棵空树或幼苗。
- 记忆树在后台静默生长，达到规模、时间跨度、概念稳定度和身份置信度阈值后才解锁。
- 解锁是一次产品惊喜：用户第一次看到的应该已经是一棵有内容、有主干、有经历的树。
- 成熟度不能只按记录条数判断，需要综合有效 Evidence、活跃天数、Episode 连续性、稳定 Concept、全局主线置信度和 Identity Epoch 质量。
- 未成熟期间不显示百分比进度、空树页面或每日成长通知，避免把后台智能变成需要管理的任务。
- 只有年度或永久用户的树达到成熟阈值后，树才进入侧栏和 Memory 产品入口。
- 普通用户即使树已经成熟也继续隐藏；升级后若已成熟，可以立即揭晓。
- 成熟后侧边栏悄然出现“记忆”入口和克制的新生芽点提示，不使用强制弹窗打断当前任务。
- 用户第一次主动进入时才播放完整生长揭晓，并进入首次引导流程。

### R-019：AI 自我认知完全自动且日常无感

- Identity Epoch、全局主线和 AI 自我模型由 MemoryDream 自动形成与更新。
- 身份变化不弹确认框、不要求用户批准，也不发送日常变化通知。
- 用户日常使用不需要知道系统正在归纳、压缩或重写自我模型。
- 自动并不等于不可治理：树解锁后仍可查看来源和历史时期，用户纠正会成为高权重 Evidence，影响下一次自动生长。
- 只有首次树成熟解锁可以作为一次明确惊喜；后续身份演变保持安静，通过用户主动打开树时自然体现。

### R-020：只保留提炼后的最小 Evidence

- Computer Use 不长期保存原始截图、录屏或整段观察文本。
- 原始观察只允许存在于完成当次提炼所需的短暂缓冲区，随后释放。
- 长期 Evidence 只保存最小语义片段、发生时间、来源类型、必要的对象引用和随机化内容承诺（不是明文派生哈希，低熵内容不可被字典枚举）。
- 不是每次操作都形成 Evidence；只有达到显著性门槛的节点片段才进入长期记忆。
- 对话、任务和工具原始记录如果本来由各自产品域保存，Memory 只保留引用，不复制一份完整原文。

### R-021：遗忘默认是权重衰减；物理清除仅为受限治理例外

- 记忆树不是完整历史档案，不要求记住用户发生过的每一件事。
- 每条 Episode、Claim、Relation 和经历枝都有动态记忆强度。
- 时间流逝、长期未使用、与当前身份无关或证据变弱时，记忆权重逐渐下降。
- 权重下降后，记忆先退出日常召回，再从可见树中淡出，最后进入深层沉睡状态。
- 沉睡记忆仍保留压缩后的最小痕迹和关联，正常任务不会主动召回。
- 重复发生、再次被使用、产生重要结果、与当前主线重新相关或被用户明确提起时，记忆会被强化和唤醒。
- 删除一段会话、任务或普通来源不会级联删除所有派生记忆，而是减少证据支撑并重新计算权重。
- 日常记忆产品不提供也不推销单条“永久删除记忆”；用户主动忘记默认只降低权重，深层痕迹继续存在。
- 但系统必须保留一条确定性“彻底清除”通道，入口位于设置“记忆”Tab 的隐私治理区。清除是一个崩溃可续跑的两段过程（Erasure Saga）：确认后立即在权威库单事务写入墓碑、固化的类型化闭包与查询拒绝集，召回、搜索、聊天、历史回看和诊断从这一刻起对该内容全部不可见（历史结构位置以 redacted 占位呈现，占位不算残留）；后台随后幂等清理向量索引、全文索引、缓存与历史检查点、运行账本与加密内容，并逐面验证。中途崩溃自动续跑；持续失败进入可观测的“清除受阻”状态并提供诊断入口，不会出现“显示已清除但仍有残留”的状态。
- 已裁决的用户承诺：点击确认后立即从所有 VelarOS 查询面消失；后台继续清理应用自己管理的副本；验证完成前界面如实显示“清除中”，验证完成后才显示“已彻底清除”。“清除中”的时长随索引规模变化（大库下可能持续数分钟），期间内容已经全面不可见，界面不按秒级完成态设计。
- 清除承诺的边界：覆盖 VelarOS 自己管理的所有副本（数据库、WAL、向量库旧版本、缓存、日志、应用管理的备份）；已按用户配置披露给远程 provider 的最小化数据无法由本地撤回，系统以披露台账如实记录；操作系统级备份与用户自行导出不在即时保证内。
- 闭包按类型区分传播，不做无脑图遍历：擦除一条证据时，仍有独立支撑的结论只移除该支撑并重评，不无条件连坐；擦除一条结论时，默认不反向擦除还支撑着其他结论的证据。确认框展示闭包的类别与数量，闭包固化后执行。
- 全部内容正文（不限隐私级）从写入起就与结构历史分离并逐条加密——隐私分级只影响展示、召回范围与远程披露，不影响可擦除性，被误分类为普通内容的私密信息同样可被加密擦除。清除通过销毁密文与密钥完成，结构历史保持只增不改，历史重建中对应内容呈现为不可恢复的 redacted 占位，而不是伪装成从未存在。
- 被清洗的派生文本在下一次记忆生长时基于剩余证据重新生成；无可用模型时保持 redacted，不阻塞清除本身。
- 已裁决的交互粒度：条目级（一条 Claim 或一条 Evidence）+ 自动闭包 + 执行前一次明确二次确认。
- 系统不把保留的任何承诺值或密文声称为“已匿名化”；对外表述为加密擦除（crypto-erasure），公开发行前的合规审阅（含 GDPR 第 17 条边界）是硬门槛。
- “彻底清除”是例外治理路径，服务于秘密误入长期层的事后补救、用户的强隐私诉求和法规要求；它不是日常遗忘模型，不出现在树页面的常规交互里。
- 卸载应用、删除本地数据库或执行账户级数据擦除属于系统存储治理，不属于记忆的遗忘模型。

### R-022：支持“用力回忆”

- 普通召回只使用高权重、近期、当前主线相关的记忆。
- 当用户明确要求回忆很久以前、追溯历史或普通召回没有答案时，系统进入深层召回。
- 深层召回可以降低权重阈值、扩大时间范围、增加 Relation 跳数，并尝试沿仍存在的来源引用重建上下文。
- 深层召回允许更慢、更高成本，但必须向回答标注置信度和来源完整性。
- 普通召回的同步路径不调用大语言模型、不同步等待网络请求，延迟以毫秒计：查询侧向量化只使用本地或已缓存能力，远程 embedding 不可用或超预算时确定性降级到词法与树路径检索。
- 向量召回按 embedding profile 严格隔离；profile 至少由 provider、model 与 dimensions 共同确定。一次查询只能检索与当前 profile 完全一致的向量，禁止把不同模型空间的候选或分数混在一起。
- 用户切换 embedding provider / model 只改变后续写入与查询选中的 profile：旧向量保留，不删除、不重建、不回填历史记忆，也不触发任何后台维护任务；切回旧 profile 后，其已有向量自然重新可见。
- 新增或内容发生变化的记忆只为当时激活的 profile 生成当前内容版本向量。其它 profile 的旧内容版本可以物理保留，但因内容版本不匹配不参与召回。只有用户明确执行手动补建才允许为当前内容增加另一个 profile 的向量。
- 模型切换之外的删除边界不变：记忆本体被彻底清除时，Erasure Saga 必须跨全部 profile 删除其派生向量；这不能被“保留旧向量”规则阻止。
- 模型参与的记忆选择与丰富必须异步且零阻塞：回合开始异步注入，结果赶不上本轮就进下一轮，不等待。
- 只有深层召回允许更重的模型参与和更高延迟，且必须可取消、带进度、标注“模糊回忆”。
- 已裁决的入口形态：不设专用 UI 按钮；由用户自然语言明确要求（“仔细想想以前”）触发，或普通召回无果时自动升级并在回答中声明。
- 被成功找回且重新产生价值的记忆可以重新强化，在树上重新长出可见节点。

### R-023：敏感生活信息允许进入记忆系统

- 健康、财务、情绪、关系等敏感信息不做类别级禁止。
- 当它们确实影响用户行为、任务、偏好或 AI 身份时，可以成为 Claim、营养信号和 Identity Epoch 的支撑。
- 系统必须区分用户明确陈述、直接观察和模型推断，不能把一次情绪或偶发表现写成稳定人格结论。
- 敏感信息使用更高 `privacyClass`、更少原文、更严格的来源和更谨慎的召回范围。
- 敏感不等于秘密：密码、Token、Cookie、私钥、恢复码等 `secret_forbidden` 数据仍禁止进入长期 Evidence、摘要和向量索引。
- 用户可以为记忆整理、MemoryDream、相关性、页面聊天和 embedding 自行配置模型/provider。
- 用户选择远程 provider 后，允许敏感索引和最小 Evidence 交给该模型处理；不再逐次弹确认。
- 无论使用本地还是远程模型，都不发送原始截图、完整隐私正文或 `secret_forbidden` 数据。

### R-024：隐私信息优先使用索引式记忆

- 隐私信息不必保存完整内容，可以只保存“是什么、在哪里、何时观察到、从哪里可以再次找到”的最小索引。
- 典型例子是物品位置：保存对象别名、位置别名、最后观察时间、置信度和来源引用，不保存现场截图、周围环境或物品内容。
- 健康、财务、情绪和关系可以只保存主题索引、重要程度和来源指针，需要细节时再经过授权读取仍存在的原始来源。
- 索引必须有时效性。物品可能移动、状态可能变化；回答时需要表达最后观察时间和置信度，不能把旧位置说成当前确定事实。
- 原始来源已经不存在时，系统只能返回最小索引和不完整性说明，不能补写不存在的细节。
- 索引式记忆仍参与权重衰减、深层召回和 Identity 营养，但不会把原始隐私正文写进摘要或 embedding。

首批存储模式：

- `semantic_minimal`：保存完成长期理解所需的最小语义。
- `index_only`：只保存结构化索引与来源指针。
- `secret_forbidden`：完全禁止进入长期系统。

### R-025：用户看到的是自然形态 Canvas 树

- 用户界面必须呈现接近自然生长形态的有机树，而不是节点连线图、流程图或神经网络示意图。
- 树使用 Canvas 绘制，使树干、枝条、叶片、光影和生长动画具有自然连续性。
- 视觉品质是核心产品能力，不能只满足“能显示数据”。
- 艺术方向是“抽象自然的数字生命”：保留树的自然结构和生命感，但不追求写实森林效果。
- 颜色延续 VelarOS 的黑、白、灰主题，只使用少量主题色表达活跃、成长、唤醒和当前焦点。
- 同一份数据必须产生稳定树形；重进页面不能因为随机数而整体换形。
- Canvas 可以在实现层使用 WebGL、OffscreenCanvas 或其它加速，但产品视觉仍是一棵自然树。

### R-026：大阶段变化才播放生长动画

- 第一次树成熟解锁时，播放完整的首次生长揭晓动画。
- 每次形成新的 Identity Epoch、全局主线发生阶段变化或长出重要主枝时，播放一次明显生长动画。
- 普通叶片、权重变化和小修剪只做轻量变化，不频繁打断用户。
- 每个树版本的主动画只播放一次，记录用户已观看版本。
- 动画必须尊重 reduced motion 设置，并提供快速跳过。

### R-027：全产品引导与树内引导分层实现

- VelarOS 需要单独建设一套全产品 Onboarding 气泡组件，用于引导用户第一次使用系统及其页面级功能。
- 全产品 Onboarding 是独立基础组件和后续任务，不属于记忆树 Canvas renderer。
- Onboarding 可以介绍侧边栏入口、页面标题、搜索、设置和聊天等外部界面，但不通过 DOM 气泡直接锚定树内枝条或节点。
- 记忆树内部对主干、经历枝、点击展开、来源路径和历史回看的引导由 Canvas 自己绘制和播放。
- Canvas 树内引导使用自身的镜头、光脉、标签、枝条舒展和示范动画，与树的自然视觉保持一致。
- 外部 Onboarding 可以触发一次“记忆树内部引导”命令并等待完成，但不控制树内每个视觉步骤。
- 当前阶段只记录外部 Onboarding 为独立后续任务，不实现该通用组件。

### R-028：时间、关系与视觉必须共用树的几何结构

- 时间不能重新退化为独立时间轴页面。
- 候选方向是“靠近主干连接点表示更早，沿枝条向枝梢表示更晚”。
- 枝条粗细可以表达长期稳定度，节点大小表达重要性，枝间距离表达概念亲和度。
- 默认状态不显示满屏关系线；聚焦分支时，相关节点之间可以出现克制的光脉或细线。
- 主干上的 Identity Epoch 与分支连接点必须可见，使用户理解某条经历如何影响 AI 当时的身份。
- 历史浏览采用真实树版本快照，而不是在今天的树形上简单隐藏未来内容。
- 时间控件采用平时隐藏的年轮刷选器；亲和关系默认通过枝条邻近和共同分叉表达，聚焦时只点亮少量相关光脉。

### R-029：自然元素具有稳定的记忆语义

- 主干表示 AI 身份成长轨迹。
- 主枝表示长期项目或持续经历。
- 细枝表示任务及其演化。
- 分叉表示方向变化或关键决策。
- 枝节表示重要历史节点。
- 芽表示尚未稳定的候选记忆。
- 叶表示已经形成的认知、成果或当前状态。
- 果实只用于极少数具有长期价值的成果，不能成为普通重要性图标。
- 淡去的枝叶表示沉睡记忆，不表示删除；深层召回后可以重新恢复存在感。
- 这些语义在缩放、历史回看和生长动画中必须保持一致，不能为了装饰随意改变。

### R-030：AI 身份通过主干自然显现

- 默认整树状态不在树顶悬挂醒目的身份说明牌，避免把动态自我认知做成静态口号。
- 用户点击或聚焦主干后，才浮现一句当前 AI 自我认知与当前全局主线。
- 历史 Identity Epoch 通过主干上的年轮、枝节或阶段纹理表达。
- 用户继续选择某个历史阶段时，显示当时的身份描述、有效时间和支撑经历。
- 身份表达必须保持可追溯，不能只显示没有证据入口的模型文案。

### R-031：用户纠正记忆，但不手工塑造树

- 用户不能通过自由拖拽枝条、直接改写主干或手写 AI 身份来改变树的真实结构。
- 用户可以纠正事实、重命名项目、合并或拆分错误分支、固定重要记忆、降低记忆权重和排除来源。
- 用户操作必须先形成结构化纠正或治理命令，再由统一记忆模型重算受影响的谱系和树切片。
- 用户纠正是最高权重 Evidence，MemoryDream 不得用后续模型推断静默覆盖。
- 布局偏好与语义结构必须分离；允许调整镜头或固定展示位置，不等于允许篡改记忆关系。

### R-032：敏感记忆默认收敛展示

- 敏感信息可以参与 AI 认知，但默认树视图只显示模糊名称，例如“健康变化”“个人关系”或“重要物品位置”。
- 用户主动选择后，才显示允许保存的具体内容、最后观察时间、置信度、认识状态和来源。
- 页面不能因为模糊展示而把模型推断伪装成事实。
- 后续可以提供全局隐私显示模式；它只影响页面呈现，不改变底层记忆、召回权重和来源谱系。
- `secret_forbidden` 内容不存在“点击后显示”，因为它从一开始就不能进入长期记忆系统。

### R-033：MemoryDream 自动生长，但必须版本化和可回滚

- 合并重复、调整权重、形成分支、更新全局主线和创建 Identity Epoch 默认自动提交，不逐次打断用户。
- 每次提交生成原子树版本和可审计差异，失败不改变当前树，已提交版本可以回滚或重建。
- 证据冲突不能静默覆盖，也不默认弹窗打断用户；冲突双方继续存在，并在树上形成克制的异常芽点或不确定标记。
- 用户主动查看冲突时，系统解释双方来源、时间和置信度，并接受纠正。
- 用户纠正拥有最高优先级；自动整理只能在新证据明确推翻或用户再次纠正后更新相关结论。

### R-034：大规模记忆通过语义缩放呈现

- 远景只显示整棵树轮廓、主干和身份阶段，不显示密集标签。
- 中景显示主要项目、持续经历和当前活跃任务。
- 近景显示关键枝节、芽、叶、时间和状态。
- 聚焦节点后才显示摘要、置信度、冲突、来源和治理操作。
- 默认层级根据视口、重要性和活跃度自适应，不固定把全部项目或标签塞在首屏。

### R-035：记忆聊天与当前树状态联动

- 未选择节点时，记忆聊天以整棵已提交的树为查询范围。
- 选择分支或节点后，聊天自动以当前树路径为主要上下文，同时允许显式切回整棵树。
- 回答时 Canvas 将镜头定位到相关枝条，并依次点亮回答引用的树路径。
- 证据详情仍通过按需出现的右侧抽屉查看，回答不能把大量来源文本覆盖在树上。
- 修改类聊天请求遵守结构化纠正链，不能让聊天模型直接改动 Canvas 节点。

### R-036：设置页提供独立的“记忆”顶层 Tab

- Settings 中单独增加一个顶层“记忆”Tab，不把记忆树设置降级为其它设置页面下的普通分组。
- 所有记忆树相关开关、模型选择、来源排除、后台生长、隐私展示、治理和诊断入口都集中在该 Tab。
- 其它设置 Tab 可以链接到“记忆”，但不能维护第二份记忆配置或出现语义重复的开关。
- 普通用户即使看不到记忆树页面，也可以进入该 Tab 管理自动记忆、来源、模型、隐私和后台整理。
- 未揭晓用户在该 Tab 的隐私治理区可以按来源、时间与关键词检索最小记忆条目（标题级列表），用于降权、排除与彻底清除；该列表不呈现树形、身份阶段或全局主线，不破坏成熟揭晓。
- Tab 不向尚未揭晓的用户显示树成熟百分比或倒计时，避免破坏成熟后的惊喜。
- 未来云端保险库、备份与恢复进入同一 Tab，但第一阶段不实现。

### R-037：模型只能提出记忆变化，不能直接写入

- 本地确定性程序负责密钥过滤、隐私分类、权限、稳定 ID、结构校验和最终提交；这些职责不能交给远程模型。
- 快速记忆模型负责摘要、分类和 Concept / Episode / Claim 候选提取。
- Embedding 只负责召回可能相关的候选，不能证明因果、决定合并或直接创建树关系。
- MemoryDream 模型负责长期关系、全局主线、冲突、压缩和身份演进，只输出变更提案。
- 记忆聊天模型负责查询、解释和生成纠正提案，不能直接操作树或数据库。
- 用户可以为模型任务选择本地或远程 provider，但确定性隐私入口和最终提交校验始终本地执行。

### R-038：重大成长必须经过独立复核

- 普通叶片、任务阶段和权重变化经过一次模型提案与确定性校验即可提交。
- 新 Identity Epoch、全局主线变化、重要主枝移动或合并、大范围画像营养变化和批量沉睡必须额外经过一次隔离复核。
- 复核可以使用同一个已配置模型的独立调用，不强制用户配置第二个 provider。
- 复核失败时保留内部候选和审计原因，不改变当前树、不播放成长动画，也不打扰用户。
- 只有提案、复核和确定性校验全部通过后，重大变化才能原子提交为新树版本。

### R-039：用户界面命名保持自然一致

- 侧边栏入口使用“记忆”。
- 页面核心概念使用“记忆树”。
- Settings 顶层 Tab 使用“记忆”。
- 后台整理能力面向用户称为“记忆生长”，内部技术名使用 `MemoryDream`。
- 手动触发按钮使用“立即整理”。
- 历史时间控件使用“年轮”。
- 低权重扩大召回能力使用“深层回忆”。
- `IdentityEpoch` 在产品界面称为“成长阶段”，不直接暴露内部对象名。
- “做梦”可以作为产品理念和动画隐喻，但不作为普通设置项或运行状态的正式名称。

### R-040：采集与提炼解耦，未配置模型时优雅降级

- VelarOS 是 BYOK 产品；用户可能尚未配置任何可用模型或 embedding provider。
- 最小 Evidence 片段由确定性管线产出（脱敏、结构化字段抽取、截断、来源引用、随机化承诺），不依赖大语言模型，在自动记忆处于 `enabled` 状态时任何时候都持续工作（`disabled` 期间不采集，见 R-017）；原始观察缓冲区仍按 R-020 释放，不为等待模型而保留。
- 需要模型的部分是 Concept / Episode / Claim 候选提取与语义综合（R-037 中快速记忆模型与 MemoryDream 的职责）；无可用 provider 时这部分暂停，证据 frontier 持续积压，用户配置模型后对已落盘 Evidence 自动补整理。
- 期间不伪造成熟度，也不向用户显示错误或催促；这是一种正常运行状态，不是故障。
- Embedding provider / model 更换后不做后台重建或跨版本合并；系统保留各 profile 的已有向量，只查询当前 profile。当前 profile 覆盖不足时正常降级到词法与树路径召回，不能把缺失覆盖伪装成故障或自动补建任务。

### R-041：外部内容按不可信来源分级

- 来自网页、外部文件和第三方内容的信息在证据层携带明确的来源信任等级，低于用户陈述和系统直接观察。
- 信任分级按内容作者而非采集通道判定：Computer Use 或内置浏览器观察到的用户行为与环境状态属于系统直接观察；同一通道观察到的第三方文本内容属于外部内容。
- 仅由外部内容支撑的 Claim 认识状态封顶为模型推断且低置信，不得直接改变用户画像、偏好营养或 AI 身份。
- 外部内容中的指令性文本（prompt injection）不得被 MemoryDream 当作用户意图执行；整理模型把证据当数据处理。
- 重大变化的隔离复核必须显式检查“提案是否被证据文本中的指令操纵”。
- 外部信息只有与用户确认或系统直接观察的证据结合后才能晋升认识状态。

## 已确认的统一领域模型

记忆树、MemoryDream、Agent 召回、记忆聊天和 Canvas 必须共同使用以下领域模型：

- `Evidence`：发生过什么，以及来源在哪里。
- `Concept`：长期存在的对象，例如用户、项目、任务、兴趣和方法。
- `Episode`：有时间边界的一段经历，例如一次会话、执行或任务阶段。
- `Claim`：关于某个 Concept 的可验证结论。
- `Relation`：Concept、Episode、Claim 之间的结构、时间、任务和认识关系。
- `NutrientSignal`：从有来源的 Claim 派生、影响整棵树但不默认成为可见节点的营养信号。
- `Identity Epoch`：AI 在一段时期内对自身角色和全局主线的可追溯概括。
- `TreeSnapshot`：某个已提交版本中用户实际看到的完整树投影（逻辑对象；存储上退化为版本锚点，正文由 TreeDiff 链重建，见投影原则）。
- `TreeDiff`：两个 TreeSnapshot 之间可验证、可播放的成长差异。

项目、任务、目标、兴趣、人物、物品和产物统一建模为不同类型的 `Concept`，不再各自建设独立长期记忆表。`Tree Projection` 是把统一意义模型编译为 `TreeSnapshot` 的确定性投影过程，不是第二套事实来源。

`NutrientSignal` 不能脱离 Claim 独立成为事实。它必须保存来源 Claim、作用范围、影响维度、强度、置信度、有效时间和隐私等级；其中强度是“基础系数 × 来源 Claim 当前权重”的派生值，有效时间继承自来源 Claim，二者都不是独立权威状态。它不持有独立的衰减状态——衰减只发生在 Claim / Episode / Relation 上，任何时刻都能由 Claim 全量重算。支撑 Claim 被纠正、降权或失效后，营养必须在同一版本事务中重算，不能成为脱离证据的隐藏画像缓存。

认识状态使用统一的有序枚举：`user_confirmed`（用户确认与纠正）> `observed`（系统直接观察）> `derived`（多证据归纳）> `inferred`（单次模型推断）；`disputed` 是并列的冲突标记。R-010 的来源区分、R-023 的敏感信息认识状态与 R-041 的“封顶 / 晋升”都以此序为准。用户画像、兴趣、偏好和方法通过该信号影响重要性、主线综合、工作方式和 Identity Epoch，但默认不占据可见主枝。

## 已确认的投影原则

底层 Relation 可以组成图，但产品层始终投影为一棵半稳定树。用户纠正和固定的展示偏好优先于后台模型重新组织；TreeSnapshot 是版本化派生状态，Evidence 与用户确认仍是事实权威。

版本历史的存储权威是自包含、可逆放的 TreeDiff 链：当前树是物化视图，TreeSnapshot 只登记版本元数据与校验锚点，历史回看按 diff 链确定性重建，不额外维护第二份全量历史。被“彻底清除”的内容在历史重建中呈现为 redacted 占位，而不是被伪装成从未存在。

结构与内容分层存储：TreeDiff 只保存 append-only 的结构事件、内容引用与随机化承诺（commitment），全部内容正文（不限隐私级）外置为逐条加密的内容 blob。版本锚点只聚合结构事件与承诺，因此历史结构校验永远成立；彻底清除通过销毁密文与密钥并提交只含 redact 操作的新版本完成，从不改写已提交的结构历史。擦除后系统只验证结构与事件顺序，不再声称能验证已删除的原文——明文派生的哈希不能作为“已删除”或“已匿名”的证明。

历史降采样（R-007 已裁决）的执行例外：被保留的远古版本转为自包含、可校验的物化基点，不再是纯派生状态；事件审计链在基点重新锚定并保留旧链末端哈希作审计延续，被合并区段内的 redact 语义在基点中保留。

## 第一轮已经确认的世界观

- 每个用户只有一棵总树。
- 这棵树是 AI 对自己的认知与自传式记忆，不是用户的人生资料树。
- 根系是所有可追溯证据。
- 主干是 AI 的成长轨迹，由连续的身份时期组成。
- 当前任务只是成长经历的一环，不能直接等同于主干。
- 任意时刻只有一条全局主线，多任务需要被提炼为更高层概括。
- 用户画像、兴趣、偏好和方法是营养信号，不默认成为可见主枝。
- 树最终长成什么样不预设，由用户长期如何使用 VelarOS 决定。

## 明确的非目标

- 不把树做成纯装饰性动画。
- 不让前端根据相似度临时决定真实关系。
- 不把全部聊天、日志和文件原文永久保存为记忆。
- 不把“忘记”实现为定期物理删除数据库记录。
- 不保存链式思考。
- 不默认监控 VelarOS 之外的所有桌面活动。
- 不把一次模型推断直接写进稳定用户画像。
- 不因为信息属于健康、财务、情绪或关系领域就完全拒绝记忆。
- 不保留关系图、时间图和树三套产品模型。
- 不在第一阶段实现云端备份、多设备同步或相关付费能力。
- 不在需求未冻结前开始大规模实现。

## 关键用户场景

### 场景 1：项目持续生长

用户连续数月开发 VelarOS。每次相关会话、代码任务、设计决策和反馈都进入同一个项目概念。树上可以看到项目主枝、记忆系统任务枝以及每次重构的演化过程。

### 场景 2：任务暂停后恢复

用户一个月前暂停某项功能。再次提到它时，VelarOS 识别为同一任务，召回此前目标、已经完成的部分、失败路径、关键决策和待处理问题，并沿原分支继续生长。

### 场景 3：用户画像被纠正

系统通过多次行为归纳出一个偏好。用户明确说“不对，我只在这个项目这样做”。系统把原 Claim 标记为被纠正，缩小适用范围，并重建受影响的树和召回路径。

### 场景 4：后台整理

用户离开电脑但设备仍在充电。VelarOS 发现有新的待整理证据，启动一次记忆生长。它合并重复信息、补齐一个任务的阶段关系、识别一个新项目分支，并原子提交新树版本。用户回来时看到简短的生长变化。

### 场景 5：询问完整历史

用户点击一条任务枝。树进入聚焦状态，该枝条保持与主干相连并在原位舒展，镜头靠近后沿生长方向展示起因、调研、决策、实现、反馈和当前方案。用户可以点开任何阶段查看来源，也能看到这段经历连接在哪一个 Identity Epoch 上。

### 场景 6：AI 身份发生跃迁

最初几个月，用户主要让 VelarOS 完成编码任务，当前身份可能是“项目开发助手”。后来用户持续让它参与产品定义、系统设计、研究、规划和长期决策。新的经历达到稳定阈值后，MemoryDream 把全局主线提升为更高层概括，例如“与用户共同构建 AI 产品与系统”。旧身份仍保留在主干历史中，新身份从其上继续生长。

### 场景 7：忘记与重新想起

一年前的一次短任务长期没有被提起，相关枝条逐渐降权并从默认树中淡出。用户后来问“我们是不是曾经处理过类似问题”，系统进入深层召回，沿低权重 Relation 找到压缩片段和仍存在的来源引用，给出带低置信度的回忆。该经验重新被当前任务验证后，记忆被强化并再次进入可见树。

### 场景 8：找回物品位置

Computer Use 在一次任务中看到用户把某个重要物品放入书房抽屉。长期记忆只保存“对象别名 -> 书房第二个抽屉”、最后观察时间和来源指针，不保存截图。几个月后用户询问位置，系统返回“我最后一次看到它是在书房第二个抽屉，时间为……，之后可能已移动”，并可在授权后尝试重新确认。

### 场景 9：彻底清除一条误入的记忆

用户发现某段高度私密的对话内容被提炼成了 Claim。他在设置的隐私治理区找到该记忆，执行“彻底清除”。确认框展示固化的闭包（将擦除的证据、结论、派生文本与索引的类别与数量），用户确认后，权威库单事务写入墓碑与查询拒绝集——召回、搜索、记忆聊天、历史年轮回看和诊断从这一刻起全部不可见，界面显示“清除中”。后台随后幂等清理向量、全文索引、缓存、账本与加密内容并逐面验证，验证完成后界面变为“已彻底清除”；中途哪怕应用崩溃，重启后清理自动续跑。历史重建中对应位置显示 redacted 占位。整个过程不需要卸载应用或清空整棵树。

## 初步验收标准

工程方案评审与最终验收至少需要回答：

1. 为什么这是同一个任务，而不是两个相似任务？
2. 为什么这条信息属于这个项目？
3. 为什么这条偏好进入了用户画像？
4. 哪些来源支持当前结论？
5. 删除某个来源后，树会发生什么变化？
6. 后台整理失败时，当前树是否保持不变？
7. 点击一个任务后，能否看到完整、按时间排序的演化？
8. 多个项目和任务同时存在时，系统是否仍能形成一条可信的全局主线？
9. 数据规模增长后，树是否保持稳定而不是每晚重排？
10. Agent 召回的内容是否与页面展示的同一棵树一致？
11. 低权重记忆能否在明确深层召回时重新被找到？
12. 删除普通来源后，派生记忆是否正确降权而不是立即消失？
13. 索引式记忆能否回答“什么东西放在哪里”，同时不保存原始隐私内容？
14. 执行“彻底清除”确认后，是否立即在所有查询面对该内容不可见（redacted 结构占位不算残留）；后台清理是否幂等、可崩溃续跑、持续失败时是否进入可观测的受阻状态；验证完成前是否如实显示“清除中”？
15. 普通召回是否满足零大模型调用、零网络阻塞的毫秒级延迟预算？
16. 未配置任何模型时，采集是否继续、整理是否安静积压、配置后能否补整理？
17. 一段包含指令性文本的网页内容成为证据后，能否证明它无法操纵画像、营养或 AI 身份？

- 新增 R-040：采集与提炼解耦，未配置模型时优雅降级。
- 新增 R-041：外部内容按不可信来源分级，防 prompt injection 污染画像与身份。
- 领域模型澄清：NutrientSignal 不持有独立衰减状态，衰减只发生在 Claim / Episode / Relation 上。
- 投影原则澄清：TreeDiff 链是版本历史的存储权威，TreeSnapshot 只登记版本元数据。

### 第三轮独立评审与第四轮修订

状态：第三轮独立评审（见 [第三轮评审报告](./memory-tree-third-round-review.md)）结论 NEEDS REVISION，两项 P0 与五项 P1 已在第四轮修订并入本文与架构文档：

- 彻底清除从“跨库单事务”改为可恢复的 Erasure Saga：确认即全查询面不可见，后台幂等清理并验证，验证完成才显示“已彻底清除”。
- 历史校验从“明文派生哈希指纹”改为内容外置 + 逐条加密 + 随机化承诺：结构历史 append-only 永不改写，清除靠销毁密文与密钥，擦除后只验证结构。
- 闭包按类型区分传播（证据与结论的擦除规则不同），确认框展示固化闭包。
- 首次告知补齐可执行状态机（pending_notice 期间不采集、不做梦）。（**2026-07-14 已撤销**：告知门整体移除，运行态只保留 enabled/disabled。）
- 两项新产品裁决并入：远古历史降采样粒度、清除承诺的“立即不可见 + 后台验证”形态。
- 清除承诺边界（应用管理副本 / OS 备份与用户导出除外 / 远程披露台账）并入 R-021 与架构威胁模型；Dream 幂等与反饥饿契约（`input_fingerprint`、read / write set、受限 rebase、AbortSignal、缩批退避）落架构文档并发章节。
- 第四轮对抗校验补丁：承诺随机数封装进加密信封（不留明文列）、Evidence 层内容哈希同步改为随机化承诺、全部内容正文统一加密外置（隐私分级不影响可擦除性）、redact 定为结构事件且擦除提交新树版本（闭合 Dream 写回竞态）、双哈希口径定案（状态哈希 / 审计链）、降采样物化基点、擦除执行 owner 与免电源门控通道、`stalled` 可观测态、keystore 永不入备份。
- 评审确认：九对象模型与此前五项产品裁决无需推翻。

### 第五轮独立评审与第六轮修订

状态：第五轮独立评审（见 [第五轮评审报告](./memory-tree-fifth-round-review.md)）确认第三轮两项 P0 已修复、九对象模型与全部产品裁决无需重开，但发现三项新 P0（权威 schema 明文残留、明文派生索引与备份承诺矛盾、擦除后远程披露竞态），全部位于第四轮新设计的接缝。第六轮按其七项最小补丁包完成架构修订：

- schema 逐表去明文（语义列 → blob 引用 + 随机化承诺 + 等值盲索引）+ 列级数据分类矩阵。
- 五个物理根（authority / blobs / keyring / index / backup），备份边界由物理布局保证。
- 派生索引装入静态加密的 index generation：行删除立即生效，轮换销毁旧代密钥兜底介质残留。
- privacy generation + 披露闸门（`MemoryDisclosureGateway`）：擦除确认后不再有命中闭包的新远程披露。
- normalized erasure targets 索引表：在线过滤走索引与单调世代，闭包 JSON 只作审计。
- DEK / keyring generation / wrapping root 三层密钥信封：已擦密钥在任何回滚路径不复活。
- 物化基点权威表与双哈希规范（状态哈希 + 事件审计链，快照绑定 event head；对外措辞为完整性自检）。
